# PR 专属预览数据

共享预览初始化时先写入通用演示数据，再根据部署流程提供的 PR 编号加载同一构建版本中的专项数据。生产和普通本地初始化沿用通用种子。

需要专项样本的 PR，在本目录增加 `pr_<编号>.py`，实现 `async def seed(db)` 和 `async def verify(db)`。用带 PR 编号的合成业务标识保存样本，确保重复调用不会创建重复记录。使用传入的数据库会话，由初始化流程统一提交事务。页面读取快照等派生数据时，在 `seed` 中一并生成。`verify` 用页面所用的读路径和验收角色的数据范围验证样本及预期结果，缺失或不符时抛出异常。两步都成功才提交。任一步失败会回滚，并阻止预览发布就绪。

把 PR 模板影响范围内的 `<!-- openqms-preview-fixture: none -->` 改为 `<!-- openqms-preview-fixture: required -->`。验收计划检查会核对当前提交的文件，预览发布还会核对待部署版本中的同一文件。

在 PR 的验收计划列出 Manager、Engineer 等对应角色可见的样本标识、操作和预期结果。新增数据只在该 PR 的独占测试库发放，结束验收后随该库清理。没有专项数据的 PR 继续使用通用演示数据。

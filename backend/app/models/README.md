# models/

## Responsibility

SQLAlchemy 2.0 ORM layer. One module per business concept, declaring the
tables that `services/` reads and mutates. No business logic lives here —
models carry columns, foreign keys, and relationships only. They also
register themselves with `TenantBase` (tenant business tables) or
`PlatformBase` (cross-tenant control plane) so Alembic can discover them
and generate migrations against the right metadata.

## File Organisation

~55 `*.py` files, one per aggregate. They group by domain:

- **Core auth & tenancy** — `user`, `role` (RoleDefinition, RolePermission,
  UserProductLine), `factory` (Factory, UserFactory), `product_line`,
  `product_type`, `tenant`, `tenant_migration`, `platform_admin`,
  `system_setting`, `reference_template`.
- **FMEA** — `fmea` (FMEADocument with JSONB `graph_data`),
  `fmea_version` (immutable snapshot + sha256), `special_characteristic`,
  `special_characteristic_link`.
- **CAPA 8D** — `capa` (CAPAEightD with `d1_team` JSONB plus
  `d2_description`…`d8_closure` text columns).
- **Audit programs** — `audit_program`, `audit_plan`, `audit_finding`.
- **SPC / MSA** — `spc` (InspectionCharacteristic, SampleBatch,
  SampleValue, SPCAlarm, ControlLimitSnapshot), `gauge`, `grr`, `bias`,
  `linearity`, `stability`, `attribute`.
- **IQC** — `iqc_material`, `iqc_inspection`, `iqc_inspection_item`,
  `iqc_inspection_template`, `iqc_aql_*` (config / profile / snapshot /
  recommendation).
- **Suppliers & customers** — `supplier` (Supplier, SupplierCertification,
  SupplierEvaluation, SupplierPPAPSubmission, SupplierPPAPElement,
  SupplierSCAR), `supplier_risk`, `supplier_shared_profile`,
  `customer_quality` (Customer, CustomerComplaint, RMARecord),
  `supply_chain_risk_map`.
- **APQP / PPAP / Control Plans** — `apqp`, `control_plan`,
  `control_plan_version`, `cp_validation`.
- **Management review & quality goals** — `management_review`,
  `management_review_report`, `quality_goal`, `group_kpi_snapshot`.
- **Connectors** — `erp`, `mes`, `plm` (connection + sync job + push
  outbox + cached entities per system).
- **Cross-cutting** — `audit` (AuditLog), `login_audit_log`, `system_log`,
  `change_impact`, `collaboration_session`, `user_dashboard_layout`,
  `recommendation_cache`.
- **Async pipelines** — `graph_sync_outbox` (FMEA → knowledge graph),
  `document_embedding` (DocumentEmbedding + EmbeddingSyncOutbox for the
  pgvector pipeline).
- **AI agent harness** — `agent` (AgentSession, AgentAction, AgentMessage,
  AgentToolCall, AgentMemory, AgentCommitWhitelist).

`__init__.py` re-exports every class so that `from app.models import X`
works and Alembic autogeneration sees the full metadata set.

## Public Interface

Consumers are `services/` (reads, mutates, persists), Alembic migration
scripts (`alembic/versions/`), and a handful of read-only helpers in
`api/` (response serialisation via `model_config = {"from_attributes":
True}` on the matching Pydantic schema).

- **Imports** — `from app.models import FMEADocument, CAPAEightD,
  AuditLog`. Avoid deep imports (`from app.models.fmea import …`) outside
  this package; the package `__init__` is the contract.
- **Construction** — instantiate with keyword arguments; UUIDs are
  generated by the `default=uuid.uuid4` on the column. Never pass an id
  from the client.
- **Sessions** — every model is bound to `TenantBase`/`PlatformBase`
  metadata. Use `app.database.get_db` (tenant-aware, sets `search_path`)
  to obtain an `AsyncSession`; never instantiate engines here.
- **Pagination contract** — services return `(items, total)` from list
  queries built on these models; the api layer wraps it as
  `PaginatedResponse`.

## Conventions & Constraints

- **UUID v4 primary keys, generated in Python.** Every PK column uses
  `UUID(as_uuid=True)` with `default=uuid.uuid4`. Do not rely on DB-side
  uuid defaults; migrations do not install `uuid-ossp`.
- **`factory_id` is NOT NULL on every business table** and is a FK to
  `factories.id` with `ondelete="RESTRICT"`. Group-level users may have a
  NULL `factory_id` on `users` — that is the only exception.
  Row-level enforcement is the service layer's job
  (`core/factory_scope.check_factory_access`).
- **Two declarative bases.** `TenantBase` is the default (`Base` aliases
  to it) and covers all tenant-scoped business tables. `PlatformBase`
  covers cross-tenant control-plane tables (`tenants`,
  `platform_admin_users`, `reference_templates`, `tenant_migrations`).
  Pick the right base when adding a table or Alembic will not see it.
- **JSONB instead of side tables** where the shape is read-only-by-app:
  `FMEADocument.graph_data = {"nodes": [...], "edges": [...]}`,
  `CAPAEightD.d1_team` (list of team-member dicts), `AuditLog.old_values`
  / `new_values` / `changed_fields`. The graph is the single source of
  truth for FMEA — there are no separate node/edge tables.
- **CAPA 8D step columns are individual `Text` columns** (`d2_description`
  through `d8_closure`). Only `d1_team` is JSONB because it carries
  structured members. The state machine string (D1_TEAM, …) lives in
  `status` and is validated in `state_machines/eightd_state.py`.
- **Document numbering is application-managed.** `document_no` is a
  unique `String(50)` filled in by services (`PFMEA-2026-001`,
  `DFMEA-2026-001`, `8D-2026-001`). No DB sequence.
- **Timestamps via `server_default=func.now()`** with
  `onupdate=func.now()` on `updated_at`. Do not set them from Python.
- **Optimistic locking** — `FMEADocument.lock_version` is an integer the
  service must increment on each save; the API rejects stale writes.
- **`AuditLog` is never mutated**, only inserted. It carries
  `tenant_schema` and `correlation_id` so that platform-level reads can
  reconstruct the original tenant context.
- **Outboxes are SQL-managed queues.** `graph_sync_outbox` and
  `embedding_sync_outbox` both carry `status`, `attempt_count`,
  `next_attempt_at`, `locked_at`, `last_error`. Producers insert in the
  same transaction as the business write; workers in `services/` drain
  them.
- **pgvector columns are not mapped.** `DocumentEmbedding.embedding`
  exists in the DB but is omitted from the ORM — queries that use
  `<->` / `<=>` go through raw SQL in `services/`.
- **Reserved name workaround** — `DocumentEmbedding.embedding_metadata`
  maps DB column `metadata` (`metadata` is reserved on SQLAlchemy Base).

## Dependencies

- **Depends on:** `app.database` (`Base`, `TenantBase`, `PlatformBase`),
  `sqlalchemy` (2.0 typed `Mapped` / `mapped_column`),
  `sqlalchemy.dialects.postgresql` (UUID, JSONB), `uuid` stdlib.
  Nothing FastAPI, nothing Pydantic.
- **Depended on by:** `services/` (every service imports the matching
  model), `schemas/` (only via `from_attributes=True` serialisation, not
  by import), `alembic/versions/*` (migration autogen sees this
  metadata), and a small number of `api/` modules that need
  type-narrowing on a model instance.

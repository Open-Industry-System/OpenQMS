# R5 首片设计：由 Agent 为当前 8D 报告提交 D5 措施建议

日期：2026-11-14。业务选择已确认，用户已同意进入实施计划。设计参考基线为 R4b 本地功能签收提交 `dcda1d55`。实施计划须从实际集成基线核对服务、迁移前驱和测试入口。

## 1. 一次完整的业务操作

质量工程师打开一份已有有效 D4 根因来源证明的报告，在侧栏选择获准的模型部署，要求“根据当前根因建议纠正措施”。受控环境里的 Agent 读取获准的上下文，自行规划步骤。需要提出措施时，它可以直接调用已预授权的保存命令。保存成功后，报告内出现一条待审建议，任务结束后同事仍可接手。

报告进入 D5 后，具备采纳权限的员工核对建议和当前依据，可以细化措辞后采纳。CAPA 同时保存 Agent 原文、员工确认的最终文本及其关系。正式措施按条目控制可见性。整份报告的批准沿用现有审批节点。

## 2. 模块职责与事实来源

| 模块 | 负责的事实与决定 |
|---|---|
| CAPA | 声明建议命令、所需权限和阶段条件，拥有报告内的建议、正式措施、采纳和撤回记录。页面与 Agent 工具调用同一业务服务，各入口按自己的身份及命令权限执行。 |
| OpenQMS 平台 | 登记受控 Agent 安装、管理员批准的本地或云端模型部署，绑定任务、运行、执行身份和接收方。持久记录命令身份、执行状态、业务对象引用及检查点位置。 |
| Agent 插件 | 实现模型调用、上下文整合和多轮规划，选择何时保存、明确更正或增加备选。插件通过平台工具读取业务事实，业务对象及权限范围由服务端解析。 |
| 侧栏 | 展示任务实际绑定的模型、当前输入的接收方和命令执行结果。报告页面按当前读者权限从 CAPA 读取建议和措施。 |

建议正文、正式文本各由 CAPA 管理。平台账本、审计、运行结果和检查点保存必要的引用与控制信息。恢复、重试和侧栏重开时，从业务服务重新读取允许展示的内容。

现有[草稿生成服务](../../../backend/app/services/capa_draft_service.py)使用进程内缓存。[已有建议采纳服务](../../../backend/app/services/capa_verification_service.py)会把文本追加到单一字段。R5 需要可持久处理的待审对象，并为受限正式措施提供独立条目。[R4b 正文交付](2026-11-08-agent-d4-root-cause-local-delivery-design.md)与[受限重开](2026-11-13-agent-d4-restricted-restart-design.md)提供读取及运行控制基线。

## 3. 模型选择、消息与交付

管理员预先批准具体模型部署。用户可在侧栏输入框旁选择已获准的本地或云端部署，创建任务时绑定该部署。允许某个云端部署用于此任务，即允许它接收任务有权使用的完整上下文，包括获准的 D4 正文、用户聊天原文和工具结果，无需逐类预授权或逐条确认。访问业务资料仍取决于当前执行人、安装、任务和模块规则的交集。模型收到的资料不能赋予 Agent 额外的写入范围。

切换选择器仅影响新任务。当前任务运行中，默认发送按钮显示“补充给〈当前模型〉”，消息持久排队并在下一个检查点处理。另设“用〈所选模型〉开始新任务”入口。旧任务的对话和正文不会因切换自动进入新任务。部署不可用或许可失效时停止向其交付，恢复执行前复核绑定及当前权限。

R5 单独定义有模型调用能力的受控插件准入。平台应能核对**实际接收方**与任务绑定部署一致，阻止插件自行指定地址或静默切换服务。采用平台管理的调用出口还是受限部署网络，由实施计划结合现有插件部署方式确定。现有 R4b 固定接收器的消息字面量、执行物和无模型合同继续适用于其原有 profile。

## 4. 保存、更正、备选与命令账本

- **保存。** 已到 D4 且当前根因有有效来源证明时，Agent 可在预授权内保存待审 D5 建议。服务端从运行解析报告，核租户代际、身份、运行状态、工厂、产品线、能力、目标及来源范围，保留结案、归档和既有材料写保护。每条建议绑定报告、任务、命令、执行者、根因修订、来源证明与来源范围。存在更多受限依据时继承全部限制；无法界定完整范围时拒绝保存。
- **更正。** 用户明确纠正先前输入时，Agent 指定本任务、本报告内仍待审的建议。服务端在一个事务内创建新版并将旧版标为“已被替代”，保存双向可追溯关系及相关用户消息引用。目标已被采纳、撤回或替代时，整次更正失败。
- **增加备选。** 用户要求另一方案时新增并列待审项，旧建议仍可处理。
- **命令重试。** 同一租户、任务和命令标识唯一绑定操作及规范化参数。业务变更、命令结果和审计原子提交。超时或并发重放不能重复创建或撤回；同标识换参数返回冲突。返回旧结果前按当前权限核对内容。命令账本可定位发生在哪个任务和检查点之后，无需复制正文。

## 5. 报告协作、采纳与审批

建议状态包括待审、已采纳、已撤回、已被替代。依据是否仍有效单独判定。D4 实际修订或来源证明发生变化时，旧建议显示“依据已变更”，采纳时必须拒绝，并要求基于当前依据重新提交。A→B→A 的文本变化也产生新修订。可读权限撤销时隐藏内容，不能用旧任务凭据或旧页面取回。

日常读者逐条满足报告及来源读取权后，才能看见对应建议、正式措施和历史文本。员工持当前报告编辑权及该条来源读取权可以填写原因撤回待审项。报告进入 D5、当前状态允许编辑时，具备采纳权限的员工可修改措辞后采纳。CAPA 在提交前锁定报告和目标建议，重读状态、根因修订、来源证明及权限，将正式条目、原始建议的已采纳状态、最终文本、操作者和审计一起提交。与撤回或替代并发时只有先成功的决定生效。已采纳的更正沿用正式 D5 的修改与终态保护规则。

正式 D5 读取需组合原有内容和读者获准查看的措施条目。原有普通措施保留原可见范围，受限最终文本继承依据的来源限制。页面、API、导出、审核材料、知识派生、搜索索引及系统同步都须遵守这一合同。无法保留限制的消费路径须在接入前关闭相应输出；如果不能保证正式措施的读取边界，拒绝采纳并保留待审建议。实施时须盘点[现有 D5 消费路径](../../../backend/app/services/capa_service.py)，尤其是将字段用于嵌入或生成下游建议的代码。首片不包含降敏流程或自动跨模块联动。

整份报告的审批同时要求专门审批权限、对象范围，以及全部待审材料和引用来源的当前读取权。审批页面只是展示入口，提交批准时必须对完整材料复核，不能依据当前页面已过滤出的子集批准。新增或修改正式条目还须纳入既有审核版本与终态保护。

## 6. 暂停、检查点与部分撤回

暂停只改变运行状态。用户选择检查点后，平台借助服务端命令顺序定位该任务自该检查点以来保存的建议，CAPA 按当前权限返回可见项。用户逐条勾选仍待审项，填写撤回原因；每项按最新权限和状态独立提交并返回结果。一项被同事采纳时，其他合格项仍可撤回。有读取权可显示“已采纳”，失去读取权时只返回“当前不可操作”。原建议、撤回人、时间及原因留痕。重开运行不会自动撤回或者复活建议。已替代版本保留历史身份。

## 7. 端到端验收

| 场景 | 验收结果 |
|---|---|
| 正常协作 | 员工在 D4 发起任务，Agent 自主保存；同事在任务结束后仍能查看。进入 D5 后同事修改措辞并采纳，原文、最终文本、依据和操作者均可追溯。 |
| 两种模型部署 | 分别选已获准的本地和云端部署，实际接收方与任务绑定一致。云端能收到该任务有权使用的聊天、业务上下文和工具结果。撤销部署或来源授权后下一次交付被拒。 |
| 侧栏切换 | 运行甲时选乙，默认补充只在甲的下一个检查点交付；显式以乙发起时创建新任务。 |
| 命令授权及重试 | 试图改写其他报告、越来源范围或在暂停后写入均被拒。成功保存后模拟响应丢失，重试只返回原建议；同标识不同文本被拒。 |
| 更正与备选 | 更正指定待审项原子替代，另一备选并列；目标已被处理时不产生孤立新版。 |
| 旧依据 | D4 换源或 A→B→A 后，旧建议仍可按权限追溯，但不能采纳。核对最新依据并重新提交后才可处理。 |
| 逐条可见 | 同报告含普通措施及受限措施；两名读者的页面、API、导出各自只含有权读取的条目。改写措辞、索引及派生内容均不能扩大可见范围。 |
| 审批与竞争 | 有审批角色但缺任一来源权限时拒绝批准；材料或权限在打开审核页之后变化时重新核对。采纳与撤回并发时只允许一个合法状态变化。 |
| 部分撤回 | 选中三条后，一条被采纳，其余两条撤回成功；撤权项返回通用结果。重复请求不重复留痕，检查点之前及其他任务的建议不受影响。 |

书面复核通过后，实施计划应先验证逐条读取与既有 D5 消费链，再接入真实模型部署和命令入口。具体表名、API 名称和迁移前驱由实施计划从集成分支确定。

## 2026-11-15 已批准补充：R5 Responses API

用户指定`gpt-6.1-terra`并明确批准新增R5独立Responses适配。部署版本显式固定API协议，旧版本
保持Chat与原配置HMAC，新Responses版本绑定协议；任何切换需新批准版本和新任务。
平台仍自行构造完整授权上下文、绑定实际接收方并控制工具执行，模型不能指定URL、报告、来源或凭据。

使用stateless Responses，完整typed推理/消息phase/工具调用顺序及call_id仅保留在受控平台内存，
不引入提供方会话续接或原文控制日志。既有来源授权、成功交付证明、命令幂等、检查点、员工采纳与逐条
可见性合同不变；不完整/畸形模型轮次不能产生可用保存依据。真实云端试用仍只用合成8D，链路成功与
质量工程师判断分别取证，不由Agent替代人工签收。详细协议与回归见`docs/development/r5-model-egress.md`。

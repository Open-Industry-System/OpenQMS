## 1. 背景与现状

D3（临时/遏制措施）当前仅 `capa_eightd.d3_interim` 文本字段 + `capa_draft_service` 的 AI 文本草稿。故事要求的"数据导入 → 受影响范围分析报告 → AI 遏制建议"链路完全缺失，D3→D4 无闸口。

**可复用基础设施**：
- `ERPInventoryBalance`（material_code/location_code/lot_no/quantity/inventory_status/snapshot_at）— 库存
- `ERPShipment`（shipment_number/customer_code/material_code/lot_no/quantity/shipment_date）+ `ShipmentRecord`（customer_id/batch_no/quantity/destination）— 发货/物流
- `IqcInspection`（supplier_id/lot_no/defect_description/inspection_result/inspection_date/defect_qty）— 查 iqc_inspections 非 iqc_materials
- `SPCAlarm` + `InspectionCharacteristic`（`SPCAnomalySource` 30 天判异口径）— SPC
- `Customer`（customer_code/name/segment）— 客户关键性
- `recommendation_orchestrator` 的 `StageRun` + `RecommendationResult(blocked=True)` 模式
- `capa_draft_service` 的 DB-backed timeout + `_generate_and_validate` 重试 + `MAX_PROMPT_CHARS=8000` 截断 + safety_trailer
- `provider_adapter.complete_json`
- 迁移测试基础设施 `backend/tests/migrations/`（`mig_db_url` + `_cfg`）
- `CapaRootCauseVerification.evidence_attachments`（JSONB `[]`，无受控附件表先例）

**字段缺口**：物流到货状态（arrival_status）在 ERPShipment/ShipmentRecord 均无字段。v3 口径：**导入时统一记 `unknown`，不做 destination/日期推导**（finding 3，不制造假事实）；E2E 用 mock ERP payload 显式携带 arrival_status（扩 seed）；风险计算遇 unknown 按保守（high）处理。

## 2. 架构总览

D3 遏制链路是独立于 12 阶段 DAG 的 3 阶段流，按不可变 generation 组织：

```
import_run (代根, is_current)
 ├─ import: [inventory, shipment, iqc, spc] 4 子源，库内查询 → JSONB 快照（run 内 UQ type）
 ├─ analyze: 报告 5 项 — 事实确定性计算(批追溯/数量/客户/时间窗) + LLM 风险分级+解释
 ├─ llm_advice: LLM 消费报告事实(非全量快照) → 建议文本+advice_type（provenance 后端按 advice_type 映射）
 └─ execution: 工程师执行记录（manual 或 adopted advice，绑 report generation）
       ↑ adoption: 单一当前决策 UQ(advice_id) + 文本修订审计
                           → D3→D4 闸口（当前 generation，读最新有效 execution）
```

- **两阶段事务**（finding 1）：事务 A 提交 run/快照 → 事务 B 生成报告；import 端点始终 200 + `report_status`；独立 /d3/report 用 422 blocked。
- **不可变 generation + DB 约束 is_current**（finding 2）：partial unique index 保证每 capa 至多一条 current run/report；旧代保留。
- **事实确定性 + LLM 风险**：批追溯/影响数量/客户影响/时间窗口 = 确定性代码；risk_level + risk_explanation = LLM。
- **prompt 精简**（finding 5）：prompt 只含确定性报告事实 + 统计摘要 + 有上限高风险证据，不含全量快照。
- **provenance 按 advice_type 映射**（finding 6）：每类 record_key + 证据映射规则，非批次建议从 IQC/SPC 生成 provenance。
- **execution 绑 generation**（finding 4）：加 report_id + PATCH + 闸口读最新有效版本。
- **发布策略**（finding 7）：A+B 原子发布，闸口完整版。

每阶段产 `StageRun{name, status, hit_count, summary, error?}`，`status∈{pending,running,done,skipped,error}`。无 LLM 凭证时 analyze/llm_advice BLOCKED。

新增服务 `backend/app/services/capa_d3_containment_service.py`。复用 `StageRun`/`RecommendationResult` 数据结构，不复用 12 阶段 DAG。

## 3. 数据模型（6 张新表，一个 Alembic 迁移）

所有表 `factory_id` NOT NULL。**冗余可派生列去除**（finding 2）：snapshot/report/advice/execution 不存 capa_id（可从 run→capa 派生），只存 run_id；adoption 不存 capa_id（从 advice→report→run 派生），只存 advice_id。factory_id 保留（RBAC 过滤，不从派生链取以防 N+1）。审计实体（adoption/execution）用 `ON DELETE SET NULL` 指向 advice/report，不 CASCADE。

### 3.1 `capa_d3_import_run` — 导入代根

| 列 | 类型 | 约束 |
|---|---|---|
| `run_id` | UUID PK | default uuid4 |
| `capa_id` | UUID FK→capa_eightd.report_id | ON DELETE CASCADE, NOT NULL |
| `factory_id` | UUID FK→factories.id | ON DELETE RESTRICT, NOT NULL |
| `is_current` | Boolean | NOT NULL, default true |
| `status` | String(12) | CHECK IN ('importing','completed','failed'), NOT NULL, default 'importing' |
| `imported_types` | JSONB | `["inventory","shipment","iqc","spc"]` |
| `started_at` | DateTime(tz) | server_default now() |
| `completed_at` | DateTime(tz) | nullable |
| `imported_by` | UUID FK→users.user_id | NOT NULL |
| `created_at` | DateTime(tz) | server_default now() |

**partial unique index**（finding 2）：`UNIQUE(capa_id) WHERE is_current = true`。新建 run 时旧 run is_current 置 false（同一事务，锁 capa 行 FOR UPDATE）。所有生成/重试入口锁 capa 行。

### 3.2 `capa_d3_containment_snapshot` — 导入快照

| 列 | 类型 | 约束 |
|---|---|---|
| `snapshot_id` | UUID PK | default uuid4 |
| `run_id` | UUID FK→capa_d3_import_run.run_id | ON DELETE CASCADE, NOT NULL |
| `factory_id` | UUID FK→factories.id | ON DELETE RESTRICT, NOT NULL |
| `snapshot_type` | String(20) | CHECK IN ('inventory','shipment','iqc','spc'), NOT NULL |
| `payload` | JSONB | NOT NULL — 原始记录副本 |
| `source_query` | JSONB | 生成快照的查询参数 |
| `record_count` | Integer | NOT NULL, default 0 |
| `imported_by` | UUID FK→users.user_id | NOT NULL |
| `imported_at` | DateTime(tz) | server_default now() |
| `created_at` | DateTime(tz) | server_default now() |

**UQ(run_id, snapshot_type)** — run 内每类唯一。索引：`(run_id)`、`factory_id`。

`payload` 按 type 结构（v3：arrival_status 统一 unknown，E2E mock 显式状态）：
- `inventory`：`[{material_code, location_code, lot_no, quantity, unit, inventory_status, snapshot_at}]`
- `shipment`：`[{shipment_number, customer_code, customer_name, material_code, lot_no, quantity, shipment_date, arrival_status}]`（arrival_status 默认 `unknown`；E2E seed mock 显式带 `in_transit`/`signed`，**生产导入无权威字段时恒 unknown**）

- `spc`：`[{alarm_id, ic_id, characteristic, triggered_at, rule_violated}]`

## 4. 服务层（`capa_d3_containment_service.py`）

### 4.1 导入 + run（两阶段事务，finding 1）

```python
async def import_containment_data(db, capa_id, user, request) -> dict
```
**事务 A**（锁 capa → run/快照 → 提交）：
- 锁 capa 行 FOR UPDATE（防双击产生两代 run）。
- 新建 `capa_d3_import_run`（is_current=true，旧 run is_current=false，partial UQ 保证唯一）。
- 按 `request.snapshot_types`（默认全 4 类）调子源查询 → 每类落 snapshot（run 内 UQ）。
- run `status='completed'`。
- 写 `D3_DATA_IMPORTED` 审计。
- **提交事务 A**。

**事务 B**（自动报告生成，独立事务）：
- 调 `generate_impact_report(db, run_id, user)`。
- 成功 → `report_status='done'`；失败 → `report_status='failed'`；无凭证 → `report_status='blocked'`。
- 事务 B 失败/异常**不回滚事务 A**（run/快照已提交）。

**返回**（始终 200）：
```json
{"run_id": ..., "snapshots": [{snapshot_type, record_count}], "report_status": "done"|"failed"|"blocked", "report": {...}|null, "report_error": "..."|null}
```

子源查询（私有，product_line_code + factory_id 隔离）：
- `_query_inventory` → ERPInventoryBalance
- `_query_shipment` → ERPShipment LEFT JOIN ShipmentRecord LEFT JOIN customers（**arrival_status 恒 unknown**，E2E seed mock 可显式注入，finding 3）
- `_query_iqc` → IqcInspection JOIN suppliers（finding 3，按 supplier_id/part_no + 近 N 天）
- `_query_spc` → SPCAlarm JOIN InspectionCharacteristic（复用 SPCAnomalySource 30 天口径）

### 4.2 报告生成（事实确定性 + LLM 风险 + 精简 prompt）

```python
async def generate_impact_report(db, run_id, user) -> dict
```
- 锁 capa 行 FOR UPDATE（finding 2，防并发报告重试双 current）。
- 读当前 run 的 4 类快照。
- **确定性计算 4 项事实**（finding 4/5）：
  - `_compute_batches(snapshots)` — 按物料/批次 join 聚合
  - `_compute_impact_qty(batches)` — 按状态聚合 + **校验 = 明细求和**
  - `_compute_customer_impact(shipment_snapshot)` — join customers，真名；unknown 按 high 保守（finding 3）
  - `_compute_time_window(spc_snapshot)` — alarm 最早~最晚
- **精简 prompt**（finding 5）：prompt 只含：确定性报告事实 + 每类来源统计摘要（record_count + 高风险项 top N）+ 截断标记 + 原始总数。**不含全量快照**。遵守 MAX_PROMPT_CHARS=8000 截断（截断标 `truncated=true` + `original_total`）。
- 客户名脱敏：prompt 里 `customer_01` 代号。
- 调 `provider_adapter.complete_json` + safety_trailer（injection 防护）。
- LLM 返回 `{risk_level, risk_explanation}` → schema 校验 → 失败重试 1 次 → 仍失败 `status='failed'`。
- 落库前还原客户名（代号→真名）。
- 落 `capa_d3_impact_report`（新 generation，旧 report is_current=false，partial UQ 保证唯一）。
- `prompt_stats={fact_chars, truncated, original_total}` 容量观测。
- 写 `D3_REPORT_GENERATED` 审计（成功/失败都写）。
- 无 LLM 凭证 → BLOCKED（不抛 422 在此函数内，而是返回 blocked 状态给 import 端点；独立 /d3/report 端点才 422）。

### 4.3 建议生成（provenance 按 advice_type 映射）

```python
async def generate_advice(db, capa_id, report_id, user, request) -> dict
```
- 锁 capa 行 FOR UPDATE（finding 2）。
- 读当前 report。
- LLM prompt 含确定性报告事实（已脱敏）+ safety_trailer。
- LLM 返回建议列表（advice_type + advice_text + target_batch_refs + provenance_sources_hint）。
- **后端标注 provenance**（finding 6，按 advice_type 映射）：
  - `recall`/`notify_customer` → 反查 shipment snapshot 的批次 record_key
  - `isolate` → 反查 inventory snapshot 的库位 record_key
  - `strict_inspection` → 反查 iqc snapshot 的 inspection record_key
  - `alternative` → 从 report-level evidence（多源汇总）生成非空 provenance
  - **规则**：每条建议 provenance 必须非空；映射后为空 → 拒绝该建议（不落库）+ 记 stage_runs error
- 后端校验：`target_batch_refs`（非 null 时）须存在于 report.batches；`advice_text` 客户名还原真名。
- 落 `capa_d3_ai_advice` 多行（绑当前 report_id）。
- 失败不落行，写审计 `D3_AI_ADVICE_GENERATED`（status=failed）。
- 无凭证 → BLOCKED → 422。

### 4.4 采纳/拒绝（单一当前决策 + 文本修订）

```python
async def adopt_advice(db, capa_id, advice_id, decision, adopted_text, user) -> dict
```
- 校验 advice 属当前代 report。
- 查 adoption where advice_id：
  - 不存在 → INSERT。
  - 存在且 decision + adopted_text 均相同 → 幂等返回。
  - 存在且 decision 或 adopted_text 变化 → UPDATE + 写 `D3_ADVICE_DECISION_CHANGED` 审计（old/new decision + old/new adopted_text，次要1）。
- CHECK 保证 adopted 时 adopted_text 非空、rejected 时为空。
- 写 `D3_ADVICE_ADOPTED`/`D3_ADVICE_REJECTED` 审计（新增/首次决策时）。

### 4.5 执行记录（绑 generation + PATCH）

```python
async def record_execution(db, capa_id, report_id, user, request) -> dict
```
- `source='manual'` → advice_id=null；`source='adopted'` → advice_id 必填且有 adopted 决策 + 属当前 report。
- 落 `capa_d3_execution`（绑当前 report_id）。
- 写 `D3_EXECUTION_RECORDED` 审计。

```python
async def update_execution(db, capa_id, execution_id, user, request) -> dict
```
- PATCH `result_status`/`measure_text`/`evidence_refs`（finding 4 生命周期）。
- 写 `D3_EXECUTION_UPDATED` 审计（old/new result_status）。

## 5. D3→D4 闸口（故事 v2 授权，读最新有效 execution）

`capa_service.advance_capa` 新增：

```python
elif current == EightDState.D3_INTERIM and target == EightDState.D4_ROOT_CAUSE:

```

`_d3_to_d4_gate`（fail-closed）：

```python
# 1. 当前 run 4 类快照齐全
current_run = SELECT run_id WHERE capa_id, is_current=true  # partial UQ 保证唯一
if not current_run: raise ValueError("D3→D4 需先导入遏制数据")
types = SELECT snapshot_type FROM snapshots WHERE run_id=current_run
if set(types) != {'inventory','shipment','iqc','spc'}:
    raise ValueError("D3→D4 需当前导入 4 类数据齐全")

# 2. 当前代报告 status='done'
report = SELECT FROM impact_report WHERE run_id=current_run, is_current=true  # partial UQ
if not report or report.status != 'done':
    raise ValueError("D3→D4 需受影响范围报告已生成")

# 3. 有效执行记录（绑当前 report，读最新版本）
exec_count = count(execution WHERE report_id=report.report_id,
                   result_status IN ('completed','in_progress'))  # failed 不算有效
if exec_count == 0:
    raise ValueError("D3→D4 需记录遏制执行结果")
```

**关键**（finding 4）：execution 绑 `report_id`（当前 generation）；报告重生成后新 report 无 execution → 闸口不满足。`result_status='failed'` 不计入有效（PATCH 降级后不再满足闸口）。无 LLM 凭证 → 报告 blocked → 闸口报告 done 不满足 → D3 推不进 D4（故事 v2 授权）。

## 6. LLM 结构化输出契约

### 6.1 报告 LLM 输入（精简，finding 5）

prompt 含（均脱敏客户名代号）：
- 确定性算好的报告事实：batches（top N 高风险）+ impact_qty + customer_impact（代号）+ time_window
- 每类来源统计摘要：`{source_type, record_count, top_risk_items}`
- capa.severity + customer.segment
- 截断标记 + 原始总数
- safety_trailer

**不含全量快照**。遵守 MAX_PROMPT_CHARS=8000。LLM 只输出：
```json
{"risk_level": "high"|"medium"|"low", "risk_explanation": "str（含代号）"}
```
校验失败 → 重试 1 次 → 仍失败 `status='failed'`。unknown arrival_status 按 high 保守（finding 3）。

### 6.2 建议 LLM 输出

```json
[{"advice_type": "recall"|"isolate"|"notify_customer"|"strict_inspection"|"alternative",
  "advice_text": "str（含代号）",
  "target_batch_refs": ["batch key"]|null,
  "provenance_sources_hint": ["inventory"|"shipment"|"iqc"|"spc"]}]
```

`provenance_sources_hint` 是 LLM 提示，**后端按 §4.3 advice_type 映射标注实际 provenance**（finding 6）。

### 6.3 客户名脱敏与还原

- prompt 阶段：客户名→`customer_01` 代号映射。
- 落库阶段：`risk_explanation`/`advice_text` 代号→真名还原。
- `customer_impact` 结构化字段：后端确定性，真名，不进 prompt。

**主流程断言**（只验结构/状态/来源，不验文字）：
1. engineer D2→D3
2. import → 200 + run + 4 类快照 + `report_status='done'`（凭证可用时；blocked 时见下）
3. 报告 5 项齐全 + `risk_level∈{high,medium,low}` + `status='done'` + 客户名真名

5. 采纳 1 条 → adoptions 回读 adopted
6. 记录 execution → executions 回读
7. D3→D4 推进成功
8. 审计回读：D3_DATA_IMPORTED + D3_REPORT_GENERATED + D3_AI_ADVICE_GENERATED + D3_ADVICE_ADOPTED + D3_EXECUTION_RECORDED + TRANSITION
9. viewer 只读

**反向/边界断言**（含 finding 次要3 补充）：
- 未导入→拒
- 只导 3 类→拒（缺类）
- 有快照无报告 done→拒
- 有报告无 execution→拒
- 纯人工 execution + 报告 done→推进成功
- 重复 import→新 run，旧 run is_current=false；报告读新 run 不重复计数
- 报告重生成→新 generation，旧 report is_current=false；旧 report 的 execution 不满足当前闸口（finding 4）
- 并发报告重试→partial UQ 防双 current（finding 2）
- import 后自动报告 blocked→快照仍提交（事务 A 独立，finding 1）
- execution 状态降级（completed→failed）→闸口不再满足（finding 4）
- adopt→reject 切换 + adopted_text 修订→UPDATE + D3_ADVICE_DECISION_CHANGED 审计（次要1）
- 无 batch provenance（strict_inspection/alternative）→provenance 从 IQC/report-level 生成非空（finding 6）
- 跨 CAPA advice_id 拒绝→404/403
- 无凭证→/d3/report + /d3/advice 返回 422 blocked；import 仍 200 + report_status=blocked

## 1. 背景与现状

D3（临时/遏制措施）当前仅 `capa_eightd.d3_interim` 文本字段 + `capa_draft_service` 的 AI 文本草稿。故事要求的"数据导入 → 受影响范围分析报告 → AI 遏制建议"链路完全缺失，D3→D4 无闸口。

**可复用基础设施**：
- `ERPInventoryBalance`（material_code/location_code/lot_no/quantity/inventory_status/snapshot_at）— 库存
- `ERPShipment`（shipment_number/customer_code/material_code/lot_no/quantity/shipment_date）+ `ShipmentRecord`（customer_id/batch_no/quantity/destination）— 发货/物流
- `IqcInspection`（supplier_id/lot_no/defect_description/inspection_result/inspection_date/defect_qty）— 查 iqc_inspections 非 iqc_materials
- `SPCAlarm` + `InspectionCharacteristic`（`SPCAnomalySource` 30 天判异口径）— SPC
- `Customer`（customer_code/name/segment）— 客户关键性
- `recommendation_orchestrator` 的 `StageRun` + `RecommendationResult(blocked=True)` 模式
- `capa_draft_service` 的 DB-backed timeout + `_generate_and_validate` 重试 + `MAX_PROMPT_CHARS=8000` 截断 + safety_trailer
- `provider_adapter.complete_json`
- 迁移测试基础设施 `backend/tests/migrations/`（`mig_db_url` + `_cfg`）
- `CapaRootCauseVerification.evidence_attachments`（JSONB `[]`，无受控附件表先例）

**字段缺口**：物流到货状态（arrival_status）在 ERPShipment/ShipmentRecord 均无字段。v8 口径：**import 时从 `ERPShipment.erp_raw_data["arrival_status"]` 读取并固化到 snapshot payload**，仅接受 `in_transit`/`signed`/`unknown` 枚举值；缺失或非法时回退 `unknown`（finding 4，不制造假事实，也不靠日期/地址推导）；E2E seed mock 在 erp_raw_data 显式注入；**风险下限**：unknown 且有受影响客户时 `deterministic_risk_floor='high'`，后端 `risk_level = max(llm_risk, floor)`（非靠 prompt 指示）。

## 2. 架构总览

D3 遏制链路是独立于 12 阶段 DAG 的 3 阶段流，按不可变 generation 组织（**v8：generation 覆盖 run→report→advice_generation→advice，running 态 + attempt_token CAS**）：

```
import_run (代根, is_current)
 ├─ import: [inventory, shipment, iqc, spc] 4 子源，库内查询 → JSONB 快照（run 内 UQ type，**固化 unit/customer_segment/customer_name/arrival_status**）
 ├─ analyze: 报告 5 项 — 事实确定性计算(只读 payload) + LLM 风险分级（受后端 floor 约束）+ 解释；短事务三阶段 running→done/failed
 ├─ advice_generation (代, is_current, attempt_token) → llm_advice: LLM 消费报告事实 → 建议绑 generation_id；短事务三阶段 + CAS
 └─ execution: 工程师执行记录（manual report_id 归属 或 adopted advice 绑 generation）
       ↑ adoption: 单一当前决策 UQ(advice_id) + 文本修订审计（只 advice_id，report 从 advice→generation 派生）
                           → D3→D4 闸口（当前 generation，读最新有效 execution）
```

- **不可变 generation 覆盖 run→report→advice_generation→advice**（finding 1）：每层 is_current + partial UQ；adoption/execution 绑当前 generation。
- **短事务三阶段 + attempt_token CAS**（v8 F2）：报告/建议生成 = 锁+建 running artifact+提交 → 无锁 LLM → 重锁+条件 UPDATE（attempt_token CAS）完成/superseded/failed；LLM 不持 capa 锁。
- **后端 risk floor**（finding 4）：`risk_level = max(llm_risk, deterministic_floor)`，unknown+受影响客户→floor=high。
- **record_key 定义 + provenance 按 advice_type 映射**（finding 3/6）：每类稳定 record_key；alternative 允许 report-level `{report_id, aggregate_key}` schema。
- **复合 FK 保证 factory 一致 + 同链**（finding 3/6）：父表 (id, factory_id) UQ + 子表 (parent_id, factory_id) 复合 FK；advice 同代 (advice_id, generation_id, factory_id) 复合 FK。
- **快照固化分析数据**（v8 F3）：import 时 unit/customer_segment/customer_name/arrival_status 固化到 payload；报告阶段只读 payload 不查源表。
- **审计实体保留 policy**（finding 2）：adoption 只 advice_id（RESTRICT 不可空，advice 不可物理删）；execution `report_id` NOT NULL（业务归属，v6 P0）+ `generation_id` nullable（仅 adopted）+ `advice_id` nullable；CAPA 删除时 adoption/execution 审计行因 RESTRICT 阻断物理删除，须软删 CAPA（归档）。

每阶段产 `StageRun{name, status, hit_count, summary, error?}`。无 LLM 凭证时 analyze/llm_advice BLOCKED。

新增服务 `backend/app/services/capa_d3_containment_service.py`。复用 `StageRun`/`RecommendationResult` 数据结构，不复用 12 阶段 DAG。

## 3. 数据模型（7 张新表，一个 Alembic 迁移）

所有表 `factory_id` NOT NULL。**删冗余可派生列避免双真源**（finding 3）：advice 只留 `generation_id`（report 从 generation 派生，不存 report_id）；adoption 只留 `advice_id`（generation+report 从 advice→generation 派生）。**execution 例外**（v6 P0）：execution 留 `report_id` NOT NULL（业务归属，manual/adopted 都有）+ `generation_id` nullable（仅 adopted 追溯来源，非双真源——report_id 是归属，generation_id 是来源）。run 是代根，存 `capa_id`。

**复合 FK 保证 factory 一致 + 同链**（finding 3/6）：
- run 根：`FOREIGN KEY(capa_id, factory_id) REFERENCES capa_eightd(report_id, factory_id)`（capa_eightd 需加 `UNIQUE(report_id, factory_id)`）。
- snapshot：`FOREIGN KEY(run_id, factory_id) REFERENCES import_run(run_id, factory_id)`。
- report：`FOREIGN KEY(run_id, factory_id) REFERENCES import_run(run_id, factory_id)`。
- advice_generation：`FOREIGN KEY(report_id, factory_id) REFERENCES impact_report(report_id, factory_id)`。
- advice：`FOREIGN KEY(generation_id, factory_id) REFERENCES advice_generation(generation_id, factory_id)`（仅此一列，report_id 不存 → 不可能不一致）。
- adoption：`FOREIGN KEY(advice_id, factory_id) REFERENCES advice(advice_id, factory_id)`。
- execution：`FOREIGN KEY(generation_id, factory_id) REFERENCES advice_generation(generation_id, factory_id)`。
父表均建 `UNIQUE(id, factory_id)`。

**统一 ON DELETE RESTRICT + CAPA 软删除**（finding 2）：capa_eightd/run/report/advice_generation/advice 全链不可物理删除（RESTRICT）；adoption 的 advice_id、execution 的 report_id/generation_id/advice_id 均 RESTRICT（不 SET NULL 不 CASCADE）；CAPA 采用归档/软删除（status=ARCHIVED），不物理删。**政策**：存在 D3 审计实体（adoption/execution）时禁止物理删除 CAPA/run/report/generation（DB RESTRICT 阻断 + 应用层校验给出可读错误）。adoption 的 advice_id 不可空（必有对应 advice）；execution 的 report_id 不可空（业务归属），generation_id/advice_id nullable（manual 时 null，v6 P0）。

### 3.1 `capa_d3_import_run` — 导入代根

| 列 | 类型 | 约束 |
|---|---|---|
| `run_id` | UUID PK | default uuid4 |
| `capa_id` | UUID FK→capa_eightd.report_id | ON DELETE RESTRICT, NOT NULL（v5，finding 2，CAPA 软删不物理删） |
| `factory_id` | UUID FK→factories.id | ON DELETE RESTRICT, NOT NULL |
| `is_current` | Boolean | NOT NULL, default **false**（v10 F1 P0：与 importing 默认值一致，防 partial UQ 撞键） |
| `status` | String(12) | CHECK IN ('importing','completed','failed'), NOT NULL, default 'importing' |
| `imported_types` | JSONB | `["inventory","shipment","iqc","spc"]` |
| `analysis_context` | JSONB | NOT NULL — `{capa_severity: critical|fatal|serious|general, risk_mapping_version: "v1"}`（v10 F2：固化分析上下文唯一真源，报告只读此处） |
| `started_at` | DateTime(tz) | server_default now() |
| `completed_at` | DateTime(tz) | nullable |
| `imported_by` | UUID FK→users.user_id | NOT NULL |
| `created_at` | DateTime(tz) | server_default now() |

**partial unique index**（finding 2）：`UNIQUE(capa_id) WHERE is_current = true`。**v10 F1 P0 CHECK**：`CHECK NOT (is_current = true AND (status != 'completed' OR completed_at IS NULL))`（is_current=true 必须 status=completed 且有 completed_at）。**v10 F1 P0 5 步晋升顺序**（事务 A，防 partial UQ 逐语句撞键）：① 锁 capa → 建新 run `status='importing', is_current=false, analysis_context={capa_severity: capa.severity 快照, risk_mapping_version: 当前版本}`；② 快照导入完成→`status='completed', completed_at=now()`；③ `UPDATE 旧 current run SET is_current=false`；④ `UPDATE 新 run SET is_current=true`；⑤ 任一步失败整笔回滚（旧 run 保持 current）。**复合 FK 基础**：`UNIQUE(run_id, factory_id)`（子表 snapshot/report 复合 FK 用）。所有生成/重试入口仅在短事务阶段①③短暂锁 capa 行。

### 3.2 `capa_d3_containment_snapshot` — 导入快照

| 列 | 类型 | 约束 |
|---|---|---|
| `snapshot_id` | UUID PK | default uuid4 |
| `run_id` | UUID FK→capa_d3_import_run.run_id | ON DELETE RESTRICT, NOT NULL（v5，finding 2） |
| `factory_id` | UUID FK→factories.id | ON DELETE RESTRICT, NOT NULL |
| `snapshot_type` | String(20) | CHECK IN ('inventory','shipment','iqc','spc'), NOT NULL |
| `payload` | JSONB | NOT NULL — 原始记录副本 |
| `source_query` | JSONB | 生成快照的查询参数 |
| `record_count` | Integer | NOT NULL, default 0 |
| `imported_by` | UUID FK→users.user_id | NOT NULL |
| `imported_at` | DateTime(tz) | server_default now() |
| `created_at` | DateTime(tz) | server_default now() |

**UQ(run_id, snapshot_type)** — run 内每类唯一。**复合 FK**：`FOREIGN KEY(run_id, factory_id) REFERENCES import_run(run_id, factory_id)`。索引：`(run_id)`、`factory_id`。

`payload` 按 type 结构（**v4：每条记录统一带 `record_key` + `source_id`**，finding 3；arrival_status 从 erp_raw_data 读，finding 4）：

每条记录统一头部：`{record_key: str（类型内稳定唯一）, source_id: str（原表 PK 或复合业务键）, ...字段}`

- `inventory`：`[{record_key, source_id: balance_id, material_code, location_code, lot_no, quantity, unit, inventory_status, snapshot_at}]`
- `shipment`：`[{record_key, source_id: erp_shipment_id（含 line_number，不可只用 shipment_number）, shipment_number, customer_code, customer_name, customer_segment, material_code, lot_no, quantity, unit, shipment_date, arrival_status}]`（**v8 F3：unit/customer_segment/customer_name/arrival_status 在 import 时固化到 payload**——unit 来源 `erp_raw_data["unit"]`→物料主数据基础单位→缺失 `unknown`；customer_segment/customer_name 来自 customers 表；arrival_status 从 erp_raw_data 读，枚举 `in_transit`/`signed`/`unknown`，缺失/非法→`unknown`，**报告阶段只读 payload 不再查源表**）

**快照可追溯性承诺**（v9 F2 + v10 F2）：同一快照产生**相同的确定性事实和 risk floor 输入**（batches/impact_qty/customer_impact/time_window/risk_floor 全确定性，只读 payload + `run.analysis_context`）；LLM 的 risk_level 解释文本因模型升级/非确定性不保证完全相同（除非复用已生成 artifact）。`capa_severity` + `risk_mapping_version` 固化在 **`capa_d3_import_run.analysis_context`**（v10 F2 唯一真源，不在 snapshot source_query）。
- `iqc`：`[{record_key, source_id: inspection_id, inspection_no, supplier_id, supplier_name, part_no, lot_no, defect_qty, defect_description, inspection_result, inspection_date}]`（来源 iqc_inspections JOIN suppliers）
- `spc`：`[{record_key, source_id: alarm_id, ic_id, characteristic, triggered_at, rule_violated}]`

**batches[] 结构**（v7 finding 2，字段级数量契约，多单位数组）：
```json
{
  "batch_key": "hash(normalized_material + normalized_lot)",
  "material_code": "str",
  "lot_no": "str|null",
  "qty_by_status": {
    "inventory": [{"qty": number, "unit": "str"}],
    "in_transit": [{"qty": number, "unit": "str"}],
    "shipped": [{"qty": number, "unit": "str"}]
  },
  "source_refs": [{"snapshot_type": "inventory|shipment|iqc|spc", "snapshot_id": "uuid", "record_key": "str"}]
}
```
- **batch_key** = `hash(normalized_material_code + normalized_lot_no)`（normalized = 去空白/统一大小写），跨来源同物料同批号合并为同一受影响批次；lot_no 缺失退化 `batch_key = {snapshot_type}:{source_id}`（不跨来源合并）。
- **数量贡献规则**：只有 inventory（ERPInventoryBalance.quantity）+ shipment（ERPShipment.quantity）贡献 `qty_by_status`；**IQC/SPC 记录只作为 source_refs 证据，不贡献数量**（防 lot_qty+库存+发货=200 的错误求和）。
- **去重**：按源记录主键（source_id）去重，同一 source 记录不重复计入。
- **单位（v7 F2）**：`qty_by_status` 每状态是 `[{qty, unit}]` 数组（同状态多单位分组返回，不合并不同单位）；inventory unit 来自 ERPInventoryBalance.unit；**shipment unit 来源 `ERPShipment.erp_raw_data["unit"]`，缺失时查物料主数据（ERPMaterial/IqcMaterial）基础单位，仍缺失记 `unit='unknown'`，不与已知单位合并**；impact_qty 同数组结构汇总各状态。
- **impact_qty** = 从 `qty_by_status` 汇总，结构同 `{inventory:[{qty,unit}], in_transit:[...], shipped:[...]}`（v7 F2，不再是无单位标量）。
- `source_refs` 保留原始记录 provenance（一个 batch 可来自多个 snapshot 记录，含 IQC/SPC 证据引用）。
target_batch_refs 引用 batch_key，后端校验存在于 report.batches。

### 3.3 `capa_d3_impact_report` — 受影响范围报告

| 列 | 类型 | 约束 |
|---|---|---|
| `report_id` | UUID PK | default uuid4 |
| `run_id` | UUID FK→capa_d3_import_run.run_id | ON DELETE RESTRICT, NOT NULL（v5，finding 2） |
| `factory_id` | UUID FK→factories.id | ON DELETE RESTRICT, NOT NULL |
| `is_current` | Boolean | NOT NULL, default **false**（v8 F1 P0：与 running 默认值一致） |
| `batches` | JSONB | 确定性批追溯 |
| `impact_qty` | JSONB | 确定性数组 `{inventory:[{qty,unit}], in_transit:[...], shipped:[...]}` |
| `customer_impact` | JSONB | 确定性 `[{customer_name, customer_segment, arrival_status, quantities:[{qty,unit}]}]`（真名，v8 F3 quantities 数组） |
| `time_window` | JSONB | 确定性 `{start, end}` |
| `risk_level` | String(8) | CHECK IN ('high','medium','low'), nullable |
| `risk_explanation` | Text | nullable — LLM 风险解释（客户名已还原真名） |
| `status` | String(10) | CHECK IN ('running','done','failed'), NOT NULL, default 'running'（v7 F4：短事务三阶段用 running） |
| `attempt_token` | UUID | NOT NULL, default uuid4（v8 F2：不可变，阶段③ CAS 防 stale worker 复活） |
| `stage_runs` | JSONB | analyze 阶段执行记录 |
| `prompt_stats` | JSONB | `{fact_chars, truncated: bool, original_total}` 容量观测 |
| `error` | Text | nullable |
| `started_at` | DateTime(tz) | server_default now()（v7 F4，stale 超时恢复用） |
| `completed_at` | DateTime(tz) | nullable（v7 F4） |
| `llm_available` | Boolean | NOT NULL, default false |
| `model` | String(40) | nullable |
| `generated_by` | UUID FK→users.user_id | NOT NULL |
| `generated_at` | DateTime(tz) | server_default now() |
| `created_at` | DateTime(tz) | server_default now() |

**partial unique index**：`UNIQUE(run_id) WHERE is_current = true`（**含义澄清 finding 5**：每 run 至多一条 current report；跨 run 的旧 report 仍可能 is_current=true，故所有查询必须先锁 current run，再在该 run 下取 is_current report，不可直接按 report.is_current 全局查）。`status='done'` 才被闸口认可。**v9 F1 P0 综合 CHECK**（done 分支加 completed_at）：
```sql
CHECK (
  (status='running' AND is_current=false AND completed_at IS NULL)
  OR (status='failed'  AND is_current=false AND completed_at IS NOT NULL)
  OR (status='done'    AND completed_at IS NOT NULL)
)
```
（running/failed 恒 is_current=false；done 可 current 且必有 completed_at；failed 必有 completed_at）。**v13 F1 done 完整性 CHECK**（加 5 项报告结果非空）：
```sql
CHECK (status != 'done' OR (
  batches IS NOT NULL AND impact_qty IS NOT NULL AND customer_impact IS NOT NULL
  AND time_window IS NOT NULL AND risk_level IS NOT NULL AND risk_floor IS NOT NULL
  AND completed_at IS NOT NULL
))
```
（done 必含 5 项确定性结果 + risk_floor + completed_at；防 done 但结果全 NULL 通过闸口）。**v9 F1 P0 原子晋升 4 步顺序**（同一事务，防 partial UQ 逐语句撞键）：① CAS 新 report `running→done`（`WHERE report_id=:id AND status='running' AND attempt_token=:token`，**is_current 保持 false**）→ 行数 0 丢弃；② 行数 1 后 `UPDATE 旧 current SET is_current=false`；③ `UPDATE 新 SET is_current=true, completed_at=now()`；④ 任一步失败整笔回滚。**stale/superseded 转 failed 必写 `completed_at=now()`**（否则违反 CHECK）。**running partial UQ**：`UNIQUE(run_id) WHERE status = 'running'`。**attempt_token CAS**（v8 F2）：见 4 步顺序①。**stale 超时恢复**：started_at 超阈值的 running，重试时先 CAS `running→failed`（同 attempt_token + completed_at=now()）再建新 running；重复请求返 **202 Accepted + 现有 running artifact ID + status + Retry-After**（v11 P2，不暴露 UQ 异常）。batches（含 `qty_by_status`/`source_refs`，v7 F2 数组）/impact_qty（数组）/customer_impact（v8 F3 quantities 数组）/time_window 确定性计算，**报告阶段只读 snapshot payload 不查源表**（v8 F3）。**risk_level 受后端 floor 约束**（finding 4）：`risk_level = max(llm_risk, deterministic_floor)`，其中 `deterministic_risk_floor` = 若 customer_impact 存在 arrival_status='unknown' 的受影响客户则 `'high'`，否则由 **`run.analysis_context.capa_severity`**（v10 F2 唯一真源，import 时固化，不查实时 capa）按 `analysis_context.risk_mapping_version` 查 **`RISK_MAPPINGS` 版本注册表**（v11 F1 P1）映射；floor 存 `risk_floor` 列便于审计。后端校验：`impact_qty` 与 `qty_by_status` 汇总一致。新增列：`risk_floor` String(8) nullable。**复合 FK**：`FOREIGN KEY(run_id, factory_id) REFERENCES import_run(run_id, factory_id)`。`UNIQUE(report_id, factory_id)` 供 advice_generation/execution 复合 FK。

**RISK_MAPPINGS 版本注册表**（v11 F1 P1，服务层常量，旧版本不可删）：
```python
RISK_MAPPINGS = {
    "v1": {"critical": "high", "fatal": "high", "serious": "medium", "general": "low"},
```

## 4. 服务层（`capa_d3_containment_service.py`）

### 4.1 导入 + run（两阶段事务，v10 F1 P0 5 步晋升）

```python
async def import_containment_data(db, capa_id, user, request) -> dict
```
**事务 A**（5 步，防 partial UQ 撞键）：
1. 锁 capa 行 FOR UPDATE（防双击产生两代 run）→ 建新 run `status='importing', is_current=false, analysis_context={capa_severity: capa.severity 快照, risk_mapping_version: 当前版本}`。
2. 按 `request.snapshot_types`（默认全 4 类）调子源查询 → 每类落 snapshot（run 内 UQ）；全部成功后 run `status='completed', completed_at=now()`。
3. `UPDATE 旧 current run SET is_current=false`。
4. `UPDATE 新 run SET is_current=true`。
5. 写 `D3_DATA_IMPORTED` 审计 → **提交事务 A**；任一步失败整笔回滚（旧 run 保持 current）。

**事务 B**（自动报告生成，独立事务）：
- 调 `generate_impact_report(db, run_id, user)`。
- **重检 run.is_current**（finding 5）：获锁后若 run 已被另一 import 置非 current → 返回 `report_status='superseded'`，不调 LLM，前端刷新当前 run。
- 成功 → `report_status='done'`；失败 → `report_status='failed'`；无凭证 → `report_status='blocked'`；被取代 → `report_status='superseded'`。
- 事务 B 失败/异常**不回滚事务 A**（run/快照已提交）。

**返回**（始终 200）：
```json
{"run_id": ..., "snapshots": [{snapshot_type, record_count}], "report_status": "done"|"failed"|"blocked"|"superseded", "report": {...}|null, "report_error": "..."|null}
```

子源查询（私有，product_line_code + factory_id 隔离）：
- `_query_inventory` → ERPInventoryBalance（payload 每条带 `record_key` + `source_id: balance_id`）
- `_query_shipment` → ERPShipment LEFT JOIN ShipmentRecord LEFT JOIN customers（**arrival_status 从 `ERPShipment.erp_raw_data["arrival_status"]` 读**，枚举 `in_transit`/`signed`/`unknown`，缺失/非法→`unknown`，不靠日期/地址推导，finding 4；payload 每条带 `record_key` + `source_id: erp_shipment_id`）
- `_query_iqc` → IqcInspection JOIN suppliers（按 supplier_id/part_no + 近 N 天；payload 每条带 `record_key` + `source_id: inspection_id`）
- `_query_spc` → SPCAlarm JOIN InspectionCharacteristic（复用 SPCAnomalySource 30 天口径；payload 每条带 `record_key` + `source_id: alarm_id`）

### 4.2 报告生成（短事务三阶段 + 事实确定性 + LLM 风险 + 精简 prompt + risk floor）

```python
async def generate_impact_report(db, run_id, user) -> dict
```
- **短事务三阶段**（v7 F4，LLM 调用不持 capa 锁）：
  1. **短事务①**：锁 capa → 重检 run.is_current → 建 `capa_d3_impact_report` 行 `status='running'`, `is_current=false`, `attempt_token=uuid4()`, `started_at=now()` → 提交释放锁。
  2. **无锁 LLM**：读快照（**只读 snapshot payload，不查源表**，v8 F3）+ 确定性计算 4 项事实 + 精简 prompt（脱敏）+ 调 `provider_adapter.complete_json` + safety_trailer；不持任何行锁。
  3. **短事务③**（v9 F1 P0 4 步原子晋升，同一事务防 partial UQ 撞键）：重锁 capa → 重检 run.is_current：
     - **run 仍 current + LLM 成功**：① CAS `UPDATE report SET status='done', completed_at=now(), batches/impact_qty/risk_level+risk_floor/risk_explanation（还原真名）WHERE report_id=:id AND status='running' AND attempt_token=:token`（**is_current 保持 false**）→ 行数 0 → worker stale/superseded，丢弃结果；② 行数 1 后 `UPDATE 旧 current SET is_current=false`；③ `UPDATE 新 SET is_current=true`；④ 任一步失败整笔回滚。
     - **run 已被取代（superseded）**：CAS `UPDATE report SET status='failed', completed_at=now(), stage_runs=:runs, error='superseded' WHERE report_id=:id AND status='running' AND attempt_token=:token`（is_current 保持 false，旧 report 保持 current；v13 F2）。
     - **LLM 失败**：CAS `UPDATE report SET status='failed', completed_at=now(), stage_runs=:runs, error='llm_failed' WHERE ... AND attempt_token=:token`（is_current=false，旧 report 保持 current；v13 F2）。
     - **schema 校验失败**：CAS `UPDATE report SET status='failed', completed_at=now(), stage_runs=:runs, error='schema_failed'`（旧 report 保持 current；v13 F2）。
     - **未知 risk_mapping_version**（v11 F1 + v13 F2）：CAS `UPDATE report SET status='failed', completed_at=now(), stage_runs=:runs, error='unknown_risk_mapping_version'`（旧 report 保持 current）。
- **确定性计算 4 项事实**（在阶段②无锁进行，**只读 snapshot payload**）：
  - `_compute_batches(snapshots)` — 按 `batch_key=hash(normalized_material+normalized_lot)` 聚合（lot 缺失退化 `{snapshot_type}:{source_id}`）；每 batch 带 `qty_by_status`（数组，v7 F2）+ `source_refs`；**只 inventory/shipment 贡献数量，IQC/SPC 仅 source_refs 证据**；按 source_id 去重；shipment unit 从 payload 读（import 时固化，v8 F3）
  - `_compute_impact_qty(batches)` — 从 `qty_by_status` 数组汇总 `{inventory:[{qty,unit}], ...}`；**不混加不同单位**（v7 F2）
  - `_compute_customer_impact(shipment_snapshot)` — 从 payload 读 customer_name/customer_segment（import 固化，v8 F3），真名，`quantities:[{qty,unit}]` 数组
  - `_compute_time_window(spc_snapshot)` — alarm 最早~最晚
  - `_compute_risk_floor(customer_impact, analysis_context)` — 若存在 arrival_status='unknown' 的受影响客户 → `'high'`；否则用 **`run.analysis_context.capa_severity`**（v10 F2 唯一真源）按 `analysis_context.risk_mapping_version` 查 **`RISK_MAPPINGS` 版本注册表**（v11 F1）；**未知版本 → 返回 failed 信号（阶段③标 status='failed' 不切 current，旧 report 保持）**，不静默用最新版本
- **精简 prompt**（finding 5，v9 F2 + v10 F2）：prompt 只含：确定性报告事实 + 每类来源统计摘要（record_count + 高风险项 top N）+ **从快照 customer_impact[].customer_segment 读客户关键性（不查实时 customers 表）** + **`run.analysis_context.capa_severity` + `risk_mapping_version`**（v10 F2 唯一真源）+ 截断标记 + 原始总数。**不含全量快照**。遵守 MAX_PROMPT_CHARS=8000 截断（截断标 `truncated=true` + `original_total`）。
- LLM 返回 `{risk_level, risk_explanation}` → schema 校验 → 失败重试 1 次 → 仍失败阶段③标 `failed`。
- **后端 risk floor**（finding 4）：`final_risk = max(llm_risk, risk_floor)`（high>medium>low），存 `risk_level` + `risk_floor` 列。
- `prompt_stats={fact_chars, truncated, original_total}` 容量观测。
- 写 `D3_REPORT_GENERATED` 审计（成功/失败/superseded 都写）。
- 无 LLM 凭证 → BLOCKED（阶段①前检查，不建 running report；返回 blocked 给 import 端点；独立 /d3/report 端点才 422）。
- **stale 超时恢复**（v9 F1）：重试时若发现 run 下有 started_at 超阈值的 running report，先 CAS `running→failed`（同 attempt_token + `completed_at=now()`）再建新 running；重复请求返 **202 Accepted + 现有 running artifact ID + status + Retry-After**（v11 P2）。

### 4.3 建议生成（advice_generation running→current + 先检查凭证 + provenance 按 advice_type 映射）

```python
async def generate_advice(db, capa_id, report_id, user, request) -> dict
```
- **先检查 LLM 凭证**（次4）：无凭证 → 直接返回 BLOCKED 422，**不建 generation**（保留旧 current 可用）。
- **短事务三阶段**（v7 F4，LLM 调用不持 capa 锁）：
  1. **短事务①**：锁 capa → 读当前 report → 建 `capa_d3_advice_generation` `status='running'`, `is_current=false`, `attempt_token=uuid4()`, `started_at=now()`（不切旧 current）→ 提交释放锁。running partial UQ 保证每 report 至多一个 running；重复请求返 **202 Accepted + 现有 running generation ID + status + Retry-After**（v11 P2）。
  2. **无锁 LLM**：prompt 含确定性报告事实（已脱敏，**只读 snapshot payload + run.analysis_context**）+ safety_trailer → 调 `provider_adapter.complete_json`；不持任何行锁。LLM 返回后**先在内存完成 schema 校验 + 批次引用校验 + provenance 映射**，得 `accepted_advice` 列表（映射失败的逐条拒绝记 stage_runs error）。
  3. **短事务③**（v11 F2 accepted_advice 驱动，同一事务）：重锁 capa → 重检 report 仍当前 generation 上下文：
     - **仍当前 + accepted_advice 非空**：① CAS `UPDATE generation SET status='done', completed_at=now(), advice_count=len(accepted_advice), rejected_advice_count=len(rejected), stage_runs=:runs WHERE generation_id=:id AND status='running' AND attempt_token=:token`（is_current 保持 false，`stage_runs` 记 schema/批次/provenance 过滤摘要，v12 F1）→ 行数 0 丢弃；② 行数 1 后**逐条 INSERT accepted_advice**（绑 generation_id，含 provenance）；③ `UPDATE 旧 generation SET is_current=false`；④ `UPDATE 新 generation SET is_current=true`；⑤ 任一步失败整笔回滚。
     - **仍当前 + accepted_advice 为空**（v11 F2，全 provenance 映射失败）：CAS `UPDATE generation SET status='failed', completed_at=now(), rejected_advice_count=len(rejected), stage_runs=:runs, error='all_provenance_mapping_failed'`（is_current 保持 false，**不切 current**，旧 generation 保持；`stage_runs` 记各建议失败原因，v12 F1）+ 审计 + 返回 200 status=failed。
     - **superseded**：CAS `UPDATE generation SET status='failed', completed_at=now(), stage_runs=:runs, error='superseded'`（旧 generation 保持 current；v13 F2）。
     - **LLM 失败**：CAS `UPDATE generation SET status='failed', completed_at=now(), stage_runs=:runs, error='llm_failed'`（无 advice 行，旧 generation 保持 current；v13 F2）+ 审计 + **返回 200 status=failed**（artifact 提交，非 422 回滚）。
     - **schema 校验失败**：CAS `UPDATE generation SET status='failed', completed_at=now(), stage_runs=:runs, error='schema_failed'`（旧 generation 保持 current；v13 F2）。
- **后端标注 provenance**（finding 3/6，按 advice_type 映射，用 record_key，在阶段②内存完成得 accepted_advice）：
  - `recall`/`notify_customer` → 反查 shipment snapshot 命中批次的 `{snapshot_id, record_key, source_type:'shipment', stage:'llm_advice'}`
  - `isolate` → 反查 inventory snapshot `{snapshot_id, record_key, source_type:'inventory', ...}`
  - `strict_inspection` → 反查 iqc snapshot `{snapshot_id, record_key, source_type:'iqc', ...}`
  - `alternative` → report-level `{snapshot_id:null, record_key:'report:{report_id}:summary', source_type:'report', ...}`
  - **规则**（v11 F2 + v12 F1）：每条建议 provenance 数组非空且每元素 `record_key` 非空字符串；映射后为空 → **该建议不进 accepted_advice，进 rejected 列表**（不落 advice 行）+ 记 stage_runs error 摘要（含 advice_type/rejection_reason）；**accepted_advice 全空 → 阶段③走 failed 不切 current**；rejected 摘要随 `generation.stage_runs` 持久化（v12 F1，可回读具体过滤原因）
- 后端校验：`target_batch_refs`（非 null 时）须存在于 report.batches 的 batch_key；`advice_text` 客户名还原真名。校验在阶段②内存完成。
- accepted_advice 非空时阶段③ INSERT 多行（绑当前 generation_id，**不存 report_id**，v7 F3 advice 须 generation_id 一致由复合 FK 保证）。
- 写审计 `D3_AI_ADVICE_GENERATED`（成功/失败都写）。
- **stale 超时恢复**（v9 F1）：重试时若 report 下有 started_at 超阈值的 running generation，先 CAS `running→failed`（同 attempt_token + `completed_at=now()`）再建新 running。

```python
             WHERE report_id=report.report_id, is_current=true  # partial UQ；可能为 null（从未生成建议）

                   result_status IN ('completed','in_progress')  # failed 不算有效
```

## 14. 关键约束

- `factory_id` NOT NULL 全表（**7 表**）+ 复合 FK 保证父子一致（finding 6）
- `enqueue_embedding` 不适用（D3 非 RAG 实体）
- 交付顺序：01.1 完成后才进 01.7
- AI_REQUIRED=true：无凭证 BLOCKED
- 状态机：D3_INTERIM→D4_ROOT_CAUSE 线性边已在
- D3 阶段守卫：写端点 `capa.status == D3_INTERIM`
- 不可变 generation 覆盖 run→report→advice_generation→advice + partial UQ is_current
- **execution 归属**（v6 P0）：report_id NOT NULL（业务归属，manual/adopted 都有）+ generation_id nullable（仅 adopted）+ advice_id nullable + CHECK 区分 manual/adopted；复合 FK (generation_id, report_id, factory_id) 保同链
- **advice 只 generation_id 不存 report_id**（finding 3，避免双真源；report 从 generation 派生）；adoption 只 advice_id；run→capa 复合 FK 保证同链
- **统一 ON DELETE RESTRICT + CAPA 软删除**（finding 2）：全链不可物理删；存在 D3 审计实体禁止物理删除 CAPA/run/report/generation；CAPA 用归档不删
- 闸口 adopted execution 须属当前 generation；manual 无 generation 也算（v6 P0，按 report_id 查）
- IQC 查 iqc_inspections
- 发布策略：A+B 原子发布（Slice A/B 仅实现顺序）
- 两阶段事务：A 提交 run/快照，B 生成报告，B 失败不回滚 A；B 获锁后重检 run.is_current，过期 superseded
- record_key：每类快照带 record_key + source_id，**record_key 永不为空只有 snapshot_id 可空**（次1）
- batch_key = `hash(normalized_material + normalized_lot)`，lot 缺失退化 `{snapshot_type}:{source_id}`；batches[].source_refs 保留原始 provenance（finding 4）
- risk floor：`risk_level = max(llm_risk, deterministic_floor)`，unknown+受影响客户→high
- arrival_status 从 erp_raw_data 读，枚举校验，缺失→unknown
- provenance 按 advice_type 映射；alternative 用 report-level record_key 非空
- 建议生成先检查 LLM 凭证再建 generation（次4）
- **短事务三阶段**（v7 F4）：报告/建议生成 = 锁+建 running artifact+提交 → 无锁 LLM → 重锁+确认 current+完成/superseded/failed；LLM 不持 capa 锁（仅阶段①③短暂锁）
- **running 态默认值 + 综合 CHECK**（v8 F1 P0 + v9 F1）：report/advice_generation `is_current` default **false** + `status` default 'running'；综合 CHECK `(running AND !is_current AND completed_at IS NULL) OR (failed AND !is_current AND completed_at IS NOT NULL) OR (done AND completed_at IS NOT NULL)`
- **import_run 5 步晋升 + CHECK**（v10 F1 P0）：is_current default false；5 步（建非current importing→completed→旧false→新true→回滚）；CHECK `is_current=true → status=completed AND completed_at IS NOT NULL`
- **attempt_token CAS 防 stale 复活**（v8 F2）：阶段③条件 UPDATE `WHERE id AND status='running' AND attempt_token`，行数 0 丢弃；stale 恢复先 CAS running→failed；重复请求 202 Accepted+Retry-After
- **快照固化分析数据**（v8 F3 + v10 F2）：import 时 unit/customer_segment/customer_name/arrival_status 固化到 shipment payload；**capa_severity + risk_mapping_version 固化到 `run.analysis_context` 唯一真源**（v10 F2，不散落 snapshot source_query）；报告/prompt/risk floor 只读 payload + run.analysis_context 不查源表；承诺"同一快照产生相同确定性事实和 risk floor 输入"（LLM 解释非确定）
- **原子晋升分步顺序**（v9/v10 F1 P0）：run 5 步、report 4 步、advice generation 5 步；CAS done/is_current 保持 false→旧 false→新 true+completed_at→回滚；防 partial UQ 逐语句撞键；done/failed 必写 completed_at
- **RISK_MAPPINGS 版本注册表**（v11 F1）：服务层常量，旧版本不可删；报告按 `analysis_context.risk_mapping_version` 查表；未知版本→failed 不静默用最新
- **advice 空建议处理**（v11 F2）：阶段②先映射得 accepted_advice；空→阶段③ CAS failed 不切 current；非空→INSERT+advice_count=len+切 current；约束 `done→advice_count>0`
- **重复请求 202 Accepted**（v11 P2）：返回现有 running artifact ID+status+Retry-After，不暴露 UQ 异常
- execution PATCH 全字段审计 + evidence_refs scheme 白名单（次1/次2）
- **running 态 + partial UQ + stale 恢复**（v7 F1/F4）：report/advice_generation status 含 running；running partial UQ 防并发；started_at 超阈 stale→CAS failed
- **多单位数组**（v7 F2）：qty_by_status/impact_qty 是 `[{qty,unit}]` 数组；shipment unit 来源 erp_raw_data/物料主数据，缺失 unknown 不合并
- **advice 同代复合 FK**（v7 F3）：advice UNIQUE(advice_id, generation_id, factory_id)；execution 复合 FK 保证 advice_id 与 generation_id 同代
- **被过滤建议持久化**（v12 F1）：advice_generation `stage_runs` JSONB + `rejected_advice_count`；过滤原因落库可回读，非只返回
- **done 完整性 CHECK**（v13 F1）：report done 必含 5 项确定性结果 + risk_floor + completed_at 非空；防 done 但结果全 NULL 通过闸口
- **失败分支审计全覆盖**（v13 F2）：所有失败分支（report/advice_generation）写 stage_runs + 稳定 error code 枚举（superseded/llm_failed/schema_failed/all_provenance_mapping_failed/unknown_risk_mapping_version）；可回读诊断

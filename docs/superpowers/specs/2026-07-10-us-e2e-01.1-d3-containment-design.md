## 1. 背景与现状

D3（临时/遏制措施）当前仅 `capa_eightd.d3_interim` 文本字段 + `capa_draft_service` 的 AI 文本草稿。故事要求的"数据导入 → 受影响范围分析报告 → AI 遏制建议"链路完全缺失，D3→D4 无闸口。

**可复用基础设施**：
- `ERPInventoryBalance`（material_code/location_code/lot_no/quantity/inventory_status/snapshot_at）— 库存
- `ERPShipment`（shipment_number/customer_code/material_code/lot_no/quantity/shipment_date）+ `ShipmentRecord`（customer_id/batch_no/quantity/destination）— 发货/物流
- `IqcInspection`（supplier_id/lot_no/defect_description/inspection_result/inspection_date/defect_qty）— 查 iqc_inspections 非 iqc_materials
- `SPCAlarm` + `InspectionCharacteristic`（`SPCAnomalySource` 30 天判异口径）— SPC
- `Customer`（customer_code/name/segment）— 客户关键性
- `recommendation_orchestrator` 的 `StageRun` + `RecommendationResult(blocked=True)` 模式
- `capa_draft_service` 的 DB-backed timeout + `_generate_and_validate` 重试 + `MAX_PROMPT_CHARS=8000` 截断 + safety_trailer
- `provider_adapter.complete_json`
- 迁移测试基础设施 `backend/tests/migrations/`（`mig_db_url` + `_cfg`）
- `CapaRootCauseVerification.evidence_attachments`（JSONB `[]`，无受控附件表先例）

**字段缺口**：物流到货状态（arrival_status）在 ERPShipment/ShipmentRecord 均无字段。v7 口径：**从 `ERPShipment.erp_raw_data["arrival_status"]` 读取**，仅接受 `in_transit`/`signed`/`unknown` 枚举值；缺失或非法时回退 `unknown`（finding 4，不制造假事实，也不靠日期/地址推导）；E2E seed mock 在 erp_raw_data 显式注入；**风险下限**：unknown 且有受影响客户时 `deterministic_risk_floor='high'`，后端 `risk_level = max(llm_risk, floor)`（非靠 prompt 指示）。

## 2. 架构总览

D3 遏制链路是独立于 12 阶段 DAG 的 3 阶段流，按不可变 generation 组织（**v4：generation 覆盖到 advice**）：

```
import_run (代根, is_current)
 ├─ import: [inventory, shipment, iqc, spc] 4 子源，库内查询 → JSONB 快照（run 内 UQ type）
 ├─ analyze: 报告 5 项 — 事实确定性计算(批追溯/数量/客户/时间窗) + LLM 风险分级（受后端 floor 约束）+ 解释
 ├─ advice_generation (代, is_current) → llm_advice: LLM 消费报告事实 → 建议绑 generation_id
 └─ execution: 工程师执行记录（manual 或 adopted advice，绑 report generation）
       ↑ adoption: 单一当前决策 UQ(advice_id) + 文本修订审计（只 advice_id，report 从 advice→generation 派生）
                           → D3→D4 闸口（当前 generation，读最新有效 execution）
```

- **不可变 generation 覆盖 run→report→advice_generation→advice**（finding 1）：每层 is_current + partial UQ；adoption/execution 绑当前 generation。
- **两阶段事务 + 重检 is_current**（finding 5）：事务 A 提交 run/快照 → 事务 B 获锁后重检 run.is_current，过期返回 `superseded` 不调 LLM。
- **后端 risk floor**（finding 4）：`risk_level = max(llm_risk, deterministic_floor)`，unknown+受影响客户→floor=high。
- **record_key 定义 + provenance 按 advice_type 映射**（finding 3/6）：每类稳定 record_key；alternative 允许 report-level `{report_id, aggregate_key}` schema。
- **复合 FK 保证 factory 一致**（finding 6）：父表 (id, factory_id) UQ + 子表 (parent_id, factory_id) 复合 FK。
- **审计实体保留 policy**（finding 2）：adoption 只 advice_id（RESTRICT 不可空，advice 不可物理删）；execution `report_id` NOT NULL（业务归属，v6 P0）+ `generation_id` nullable（仅 adopted）+ `advice_id` nullable；CAPA 删除时 adoption/execution 审计行因 RESTRICT 阻断物理删除，须软删 CAPA（归档）。

每阶段产 `StageRun{name, status, hit_count, summary, error?}`。无 LLM 凭证时 analyze/llm_advice BLOCKED。

新增服务 `backend/app/services/capa_d3_containment_service.py`。复用 `StageRun`/`RecommendationResult` 数据结构，不复用 12 阶段 DAG。

## 3. 数据模型（7 张新表，一个 Alembic 迁移）

所有表 `factory_id` NOT NULL。**删冗余可派生列避免双真源**（finding 3）：advice 只留 `generation_id`（report 从 generation 派生，不存 report_id）；adoption 只留 `advice_id`（generation+report 从 advice→generation 派生）。**execution 例外**（v6 P0）：execution 留 `report_id` NOT NULL（业务归属，manual/adopted 都有）+ `generation_id` nullable（仅 adopted 追溯来源，非双真源——report_id 是归属，generation_id 是来源）。run 是代根，存 `capa_id`。

**复合 FK 保证 factory 一致 + 同链**（finding 3/6）：
- run 根：`FOREIGN KEY(capa_id, factory_id) REFERENCES capa_eightd(report_id, factory_id)`（capa_eightd 需加 `UNIQUE(report_id, factory_id)`）。
- snapshot：`FOREIGN KEY(run_id, factory_id) REFERENCES import_run(run_id, factory_id)`。
- report：`FOREIGN KEY(run_id, factory_id) REFERENCES import_run(run_id, factory_id)`。
- advice_generation：`FOREIGN KEY(report_id, factory_id) REFERENCES impact_report(report_id, factory_id)`。
- advice：`FOREIGN KEY(generation_id, factory_id) REFERENCES advice_generation(generation_id, factory_id)`（仅此一列，report_id 不存 → 不可能不一致）。
- adoption：`FOREIGN KEY(advice_id, factory_id) REFERENCES advice(advice_id, factory_id)`。
- execution：`FOREIGN KEY(generation_id, factory_id) REFERENCES advice_generation(generation_id, factory_id)`。
父表均建 `UNIQUE(id, factory_id)`。

**统一 ON DELETE RESTRICT + CAPA 软删除**（finding 2）：capa_eightd/run/report/advice_generation/advice 全链不可物理删除（RESTRICT）；adoption 的 advice_id、execution 的 report_id/generation_id/advice_id 均 RESTRICT（不 SET NULL 不 CASCADE）；CAPA 采用归档/软删除（status=ARCHIVED），不物理删。**政策**：存在 D3 审计实体（adoption/execution）时禁止物理删除 CAPA/run/report/generation（DB RESTRICT 阻断 + 应用层校验给出可读错误）。adoption 的 advice_id 不可空（必有对应 advice）；execution 的 report_id 不可空（业务归属），generation_id/advice_id nullable（manual 时 null，v6 P0）。

### 3.2 `capa_d3_containment_snapshot` — 导入快照

| 列 | 类型 | 约束 |
|---|---|---|
| `snapshot_id` | UUID PK | default uuid4 |
| `run_id` | UUID FK→capa_d3_import_run.run_id | ON DELETE RESTRICT, NOT NULL（v5，finding 2） |
| `factory_id` | UUID FK→factories.id | ON DELETE RESTRICT, NOT NULL |
| `snapshot_type` | String(20) | CHECK IN ('inventory','shipment','iqc','spc'), NOT NULL |
| `payload` | JSONB | NOT NULL — 原始记录副本 |
| `source_query` | JSONB | 生成快照的查询参数 |
| `record_count` | Integer | NOT NULL, default 0 |
| `imported_by` | UUID FK→users.user_id | NOT NULL |
| `imported_at` | DateTime(tz) | server_default now() |
| `created_at` | DateTime(tz) | server_default now() |

**UQ(run_id, snapshot_type)** — run 内每类唯一。**复合 FK**：`FOREIGN KEY(run_id, factory_id) REFERENCES import_run(run_id, factory_id)`。索引：`(run_id)`、`factory_id`。

`payload` 按 type 结构（**v4：每条记录统一带 `record_key` + `source_id`**，finding 3；arrival_status 从 erp_raw_data 读，finding 4）：

每条记录统一头部：`{record_key: str（类型内稳定唯一）, source_id: str（原表 PK 或复合业务键）, ...字段}`

- `inventory`：`[{record_key, source_id: balance_id, material_code, location_code, lot_no, quantity, unit, inventory_status, snapshot_at}]`
- `shipment`：`[{record_key, source_id: erp_shipment_id（含 line_number，不可只用 shipment_number）, shipment_number, customer_code, customer_name, material_code, lot_no, quantity, shipment_date, arrival_status}]`（arrival_status 从 `ERPShipment.erp_raw_data["arrival_status"]` 读，枚举 `in_transit`/`signed`/`unknown`，缺失/非法→`unknown`，**不靠日期/地址推导**）
- `iqc`：`[{record_key, source_id: inspection_id, inspection_no, supplier_id, supplier_name, part_no, lot_no, defect_qty, defect_description, inspection_result, inspection_date}]`（来源 iqc_inspections JOIN suppliers）
- `spc`：`[{record_key, source_id: alarm_id, ic_id, characteristic, triggered_at, rule_violated}]`

**batches[] 结构**（v7 finding 2，字段级数量契约，多单位数组）：
```json
{
  "batch_key": "hash(normalized_material + normalized_lot)",
  "material_code": "str",
  "lot_no": "str|null",
  "qty_by_status": {
    "inventory": [{"qty": number, "unit": "str"}],
    "in_transit": [{"qty": number, "unit": "str"}],
    "shipped": [{"qty": number, "unit": "str"}]
  },
  "source_refs": [{"snapshot_type": "inventory|shipment|iqc|spc", "snapshot_id": "uuid", "record_key": "str"}]
}
```
- **batch_key** = `hash(normalized_material_code + normalized_lot_no)`（normalized = 去空白/统一大小写），跨来源同物料同批号合并为同一受影响批次；lot_no 缺失退化 `batch_key = {snapshot_type}:{source_id}`（不跨来源合并）。
- **数量贡献规则**：只有 inventory（ERPInventoryBalance.quantity）+ shipment（ERPShipment.quantity）贡献 `qty_by_status`；**IQC/SPC 记录只作为 source_refs 证据，不贡献数量**（防 lot_qty+库存+发货=200 的错误求和）。
- **去重**：按源记录主键（source_id）去重，同一 source 记录不重复计入。
- **单位（v7 F2）**：`qty_by_status` 每状态是 `[{qty, unit}]` 数组（同状态多单位分组返回，不合并不同单位）；inventory unit 来自 ERPInventoryBalance.unit；**shipment unit 来源 `ERPShipment.erp_raw_data["unit"]`，缺失时查物料主数据（ERPMaterial/IqcMaterial）基础单位，仍缺失记 `unit='unknown'`，不与已知单位合并**；impact_qty 同数组结构汇总各状态。
- **impact_qty** = 从 `qty_by_status` 汇总，结构同 `{inventory:[{qty,unit}], in_transit:[...], shipped:[...]}`（v7 F2，不再是无单位标量）。
- `source_refs` 保留原始记录 provenance（一个 batch 可来自多个 snapshot 记录，含 IQC/SPC 证据引用）。
target_batch_refs 引用 batch_key，后端校验存在于 report.batches。

**partial unique index**：`UNIQUE(run_id) WHERE is_current = true`（**含义澄清 finding 5**：每 run 至多一条 current report；跨 run 的旧 report 仍可能 is_current=true，故所有查询必须先锁 current run，再在该 run 下取 is_current report，不可直接按 report.is_current 全局查）。`status='done'` 才被闸口认可。**v7 F4 CHECK**：`CHECK NOT (is_current = true AND status != 'done')`（仅 done 可 current）。**running partial UQ**（v7 F4）：`UNIQUE(run_id) WHERE status = 'running'`（每 run 至多一个 running report，防并发重复生成）。**stale 超时恢复**：started_at 超阈值的 running report 视为 stale，重试先标 failed 再建新 running。batches（含 `qty_by_status`/`source_refs`，v7 F2 数组）/impact_qty（数组）/customer_impact/time_window 确定性计算。**risk_level 受后端 floor 约束**（finding 4）：`risk_level = max(llm_risk, deterministic_floor)`，其中 `deterministic_risk_floor` = 若 customer_impact 存在 arrival_status='unknown' 的受影响客户则 `'high'`，否则由 capa.severity 映射（critical/fatal→high，serious→medium，general→low）；floor 存 `risk_floor` 列便于审计。后端校验：`impact_qty` 与 `qty_by_status` 汇总一致（v7 F2）。新增列：`risk_floor` String(8) nullable。**复合 FK**：`FOREIGN KEY(run_id, factory_id) REFERENCES import_run(run_id, factory_id)`。`UNIQUE(report_id, factory_id)` 供 advice_generation/execution 复合 FK。

索引：`(generation_id)`、`factory_id`。**绑 generation_id，不存 report_id**（finding 3，避免双真源；report 从 generation 派生）。**复合 FK**：`FOREIGN KEY(generation_id, factory_id) REFERENCES advice_generation(generation_id, factory_id)`。**UNIQUE(advice_id, generation_id, factory_id)**（v7 F3，供 execution 复合 FK 保证 advice 与 generation 同代）。

**source_provenance schema**（finding 3/次1，**record_key 永不为空，只有 snapshot_id 可空**）：
```json
[{"snapshot_id": "uuid|null", "record_key": "str（永不为空）", "source_type": "inventory|shipment|iqc|spc|report", "stage": "llm_advice"}]
```
- 批次类建议（recall/notify_customer/isolate/strict_inspection）：`snapshot_id` + `record_key` 非空，指向具体快照记录。
- `alternative`（无批次）：`source_type='report'`，`snapshot_id=null`，`record_key='report:{report_id}:summary'`（非空字符串）。
- **规则**：每条建议 provenance 数组非空且每元素 `record_key` 非空字符串；后端按 §4.3 映射，映射后为空 → 拒绝该建议。

| `completed_at` | DateTime(tz) | nullable（v7 F4） |
| `created_at` | DateTime(tz) | server_default now() |

**partial unique index**：`UNIQUE(report_id) WHERE is_current = true`（每 report 至多一条当前 advice generation）。**v7 F1 P0 CHECK**：`CHECK NOT (is_current = true AND status != 'done')`（仅 done 可 current；running/failed 恒 is_current=false）。重生成建议 = 新 generation 先 `running` 非 current（短事务①），LLM 成功才原子切 `done`+is_current=true（短事务③），失败标 `failed` is_current=false（旧 generation 保持 current）。**running partial UQ**（v7 F4）：`UNIQUE(report_id) WHERE status = 'running'`（每 report 至多一个 running generation，防并发重复生成）。**stale 超时恢复**（v7 F4）：started_at 超过阈值（如 2× LLM timeout）的 running generation 视为 stale，重试时先标 failed 再建新 running。**ON DELETE RESTRICT**（不可物理删）。**复合 FK**：`FOREIGN KEY(report_id, factory_id) REFERENCES impact_report(report_id, factory_id)`。`UNIQUE(generation_id, report_id, factory_id)` 供 advice/execution 复合 FK 保同链。

### 3.6 `capa_d3_advice_adoption` — 采纳/拒绝留痕

| 列 | 类型 | 约束 |
|---|---|---|
| `adoption_id` | UUID PK | default uuid4 |
| `advice_id` | UUID FK→capa_d3_ai_advice.advice_id | **ON DELETE RESTRICT**, NOT NULL（v5 改 RESTRICT + 不可空，finding 2/3；删 advice 须先软删 CAPA） |
| `factory_id` | UUID FK→factories.id | ON DELETE RESTRICT, NOT NULL |
| `decision` | String(8) | CHECK IN ('adopted','rejected'), NOT NULL |
| `adopted_text` | Text | nullable |
| `advice_type` | String(24) | 冗余存 |
| `source_provenance` | JSONB | 冗余存 |
| `decided_by` | UUID FK→users.user_id | NOT NULL |
| `decided_at` | DateTime(tz) | server_default now() |
| `created_at` | DateTime(tz) | server_default now() |

**UQ(advice_id)** — 单一当前决策。改决策或改文本 UPDATE 该行（非新增）+ 写 `D3_ADVICE_DECISION_CHANGED` 审计（记 old/new decision + old/new adopted_text）。CHECK：`(decision='adopted' AND adopted_text IS NOT NULL) OR (decision='rejected' AND adopted_text IS NULL)`。**v5 删冗余 report_id/generation_id**（finding 3，从 advice→generation→report 派生，避免双真源）；**advice_id RESTRICT 不可空**（finding 2：adoption 必有对应 advice，advice 不可物理删）。次要1：同 decision 但 adopted_text 变化 → UPDATE + 审计 old/new 文本。**复合 FK**：`FOREIGN KEY(advice_id, factory_id) REFERENCES advice(advice_id, factory_id)`。**仅当前 generation 的 advice 可被采纳**（应用层校验 advice.generation_id == report 当前 generation）。

### 3.7 `capa_d3_execution` — 执行记录（v6：report_id 归属 + generation_id nullable + CHECK + PATCH 全审计）

| 列 | 类型 | 约束 |
|---|---|---|
| `execution_id` | UUID PK | default uuid4 |
| `report_id` | UUID FK→capa_d3_impact_report.report_id | **ON DELETE RESTRICT, NOT NULL**（v6 P0：所有 execution 业务归属当前报告，manual 也有） |
| `generation_id` | UUID FK→capa_d3_advice_generation.generation_id | **ON DELETE RESTRICT, nullable**（v6 P0：仅 adopted 需要；manual 时 null） |
| `factory_id` | UUID FK→factories.id | ON DELETE RESTRICT, NOT NULL |
| `advice_id` | UUID FK→capa_d3_ai_advice.advice_id | **ON DELETE RESTRICT**, nullable（manual 时 null；adopted 时非空） |
| `source` | String(8) | CHECK IN ('manual','adopted'), NOT NULL |
| `measure_text` | Text | NOT NULL |
| `result_status` | String(16) | CHECK IN ('completed','in_progress','pending','failed'), NOT NULL, default 'in_progress' |
| `evidence_refs` | JSONB | default `[]` — schema + scheme 白名单（finding 次要2，见下） |
| `executed_by` | UUID FK→users.user_id | NOT NULL |
| `executed_at` | DateTime(tz) | server_default now() |
| `created_at` | DateTime(tz) | server_default now() |
| `updated_at` | DateTime(tz) | server_default now(), onupdate now() |

**CHECK 约束**（v6 P0，区分 manual/adopted）：
```sql
(source = 'manual'   AND generation_id IS NULL AND advice_id IS NULL)
OR
(source = 'adopted'  AND generation_id IS NOT NULL AND advice_id IS NOT NULL)
```

索引：`(report_id)`、`(generation_id)`、`factory_id`。**report_id NOT NULL 是业务归属**（哪个报告的执行，manual/adopted 都有）；**generation_id nullable 仅 adopted 追溯来源**（非双真源：report_id 是归属，generation_id 是来源）。`source='adopted'` 时 advice_id 非空且须指向 generation_id 对应 generation 的 advice（应用层校验 + 闸口 step 3 校验，finding 1）。**PATCH `/d3/execution/{id}` 支持状态/文本/证据修订**（finding 4，防 in_progress 永久满足闸口）。闸口读每 execution 最新版本（见 §5）。

**复合 FK**（保同链，v7 F3 增强）：
- `FOREIGN KEY(report_id, factory_id) REFERENCES impact_report(report_id, factory_id)`
- `FOREIGN KEY(generation_id, report_id, factory_id) REFERENCES advice_generation(generation_id, report_id, factory_id)`（advice_generation `UNIQUE(generation_id, report_id, factory_id)`；nullable 时 FK 不触发）
- `FOREIGN KEY(advice_id, generation_id, factory_id) REFERENCES advice(advice_id, generation_id, factory_id)`（**v7 F3：保证 advice_id 与 generation_id 同代**；advice `UNIQUE(advice_id, generation_id, factory_id)`；MATCH SIMPLE manual 两列 null 不触发）

**evidence_refs schema**（finding 次要2）：`[{name: str(≤200), url: str(≤500), uploaded_at: ISO}]`，最多 10 条；`url` scheme 白名单：`https://` 或相对路径（`/`、`./`），**拒绝 `javascript:`/`file:`/`data:`** 等；后端校验非法 scheme → 422。

### 4.2 报告生成（事实确定性 + LLM 风险 + 精简 prompt + risk floor）

```python
async def generate_impact_report(db, run_id, user) -> dict
```
- 锁 capa 行 FOR UPDATE（防并发报告重试双 current）。
- **重检 run.is_current**（finding 5）：若 run.is_current=false → 返回 `superseded`，不调 LLM。
- 读当前 run 的 4 类快照。
- **确定性计算 4 项事实**：
  - `_compute_batches(snapshots)` — 按 `batch_key=hash(normalized_material+normalized_lot)` 聚合（lot 缺失退化 `{snapshot_type}:{source_id}`）；每 batch 带 `qty_by_status{inventory,in_transit,shipped}` + `source_refs`；**只 inventory/shipment 贡献数量，IQC/SPC 仅 source_refs 证据**；按 source_id 去重；单位不一致分组返回（v6 F2）
  - `_compute_impact_qty(batches)` — 从 `qty_by_status` 汇总 `{in_transit: sum, inventory: sum, shipped: sum}`；**不混加不同单位**（v6 F2）
  - `_compute_customer_impact(shipment_snapshot)` — join customers，真名
  - `_compute_time_window(spc_snapshot)` — alarm 最早~最晚
  - `_compute_risk_floor(customer_impact, capa.severity)` — 若存在 arrival_status='unknown' 的受影响客户 → `'high'`；否则 severity 映射（finding 4）
- **短事务三阶段**（v7 F4，LLM 调用不持 capa 锁）：
  1. **短事务①**：锁 capa → 重检 run.is_current → 建 `capa_d3_impact_report` 行 `status='running'`, `is_current=false`, `started_at=now()` → 提交释放锁。
  2. **无锁 LLM**：读快照 + 确定性计算 4 项事实 + 精简 prompt（脱敏）+ 调 `provider_adapter.complete_json` + safety_trailer；不持任何行锁。
  3. **短事务③**：重锁 capa → 重检 run.is_current → 若仍 current：成功落 batches/impact_qty/risk_level+risk_floor/risk_explanation（还原真名）+ `status='done'` + `is_current=true`（旧 report is_current=false）+ `completed_at`；若已被取代：`status='failed'`+is_current=false（superseded）；若 LLM 失败：`status='failed'`+is_current=false（旧 report 保持 current）。
- **确定性计算 4 项事实**（在阶段②无锁进行）：
  - `_compute_batches(snapshots)` — 按 `batch_key=hash(normalized_material+normalized_lot)` 聚合（lot 缺失退化 `{snapshot_type}:{source_id}`）；每 batch 带 `qty_by_status`（数组，v7 F2）+ `source_refs`；**只 inventory/shipment 贡献数量，IQC/SPC 仅 source_refs 证据**；按 source_id 去重；shipment unit 来源 erp_raw_data/物料主数据，缺失 unknown 不合并
  - `_compute_impact_qty(batches)` — 从 `qty_by_status` 数组汇总 `{inventory:[{qty,unit}], ...}`；**不混加不同单位**（v7 F2）
  - `_compute_customer_impact(shipment_snapshot)` — join customers，真名
  - `_compute_time_window(spc_snapshot)` — alarm 最早~最晚
  - `_compute_risk_floor(customer_impact, capa.severity)` — 若存在 arrival_status='unknown' 的受影响客户 → `'high'`；否则 severity 映射
- **精简 prompt**（finding 5）：prompt 只含：确定性报告事实 + 每类来源统计摘要（record_count + 高风险项 top N）+ 截断标记 + 原始总数。**不含全量快照**。遵守 MAX_PROMPT_CHARS=8000 截断（截断标 `truncated=true` + `original_total`）。
- LLM 返回 `{risk_level, risk_explanation}` → schema 校验 → 失败重试 1 次 → 仍失败阶段③标 `failed`。
- **后端 risk floor**（finding 4）：`final_risk = max(llm_risk, risk_floor)`（high>medium>low），存 `risk_level` + `risk_floor` 列。
- `prompt_stats={fact_chars, truncated, original_total}` 容量观测。
- 写 `D3_REPORT_GENERATED` 审计（成功/失败/superseded 都写）。
- 无 LLM 凭证 → BLOCKED（阶段①前检查，不建 running report；返回 blocked 给 import 端点；独立 /d3/report 端点才 422）。
- **stale 超时恢复**（v7 F4）：重试时若发现 run 下有 started_at 超阈值的 running report，先标 failed 再建新 running。

```python
current_run = SELECT run_id WHERE capa_id, is_current=true  # partial UQ 保证唯一
if not current_run: raise ValueError("D3→D4 需先导入遏制数据")
# 校验 factory 一致（finding 6）：current_run.factory_id == capa.factory_id
types = SELECT snapshot_type FROM snapshots WHERE run_id=current_run
if set(types) != {'inventory','shipment','iqc','spc'}:
    raise ValueError("D3→D4 需当前导入 4 类数据齐全")

# 2. 当前 run 下 current 报告 status='done'（不可直接按 report.is_current 全局查，finding 5）

    raise ValueError("D3→D4 需受影响范围报告已生成")

# 2b. 当前 report 的 current advice_generation（若有 advice 流程）
current_gen = SELECT generation_id FROM advice_generation
             WHERE report_id=report.report_id, is_current=true  # partial UQ；可能为 null（从未生成建议）

# 3. 有效执行记录（按 report_id 查；manual 无 generation 也算；adopted 须属当前 generation，v6 P0）
exec_count = count(execution WHERE report_id=report.report_id,
                   result_status IN ('completed','in_progress')  # failed 不算有效
                   AND (
                     source='manual'  # manual 无 generation_id，不受建议重生成影响
                     OR (source='adopted' AND generation_id=current_gen)  # adopted 须属当前 generation
                   ))
if exec_count == 0:
    raise ValueError("D3→D4 需记录遏制执行结果")
```

**主流程断言**（只验结构/状态/来源，不验文字）：

8. 审计回读：D3_DATA_IMPORTED + D3_REPORT_GENERATED + D3_AI_ADVICE_GENERATED + D3_ADVICE_ADOPTED + D3_EXECUTION_RECORDED + TRANSITION

**反向/边界断言**（含 finding 次要3 + v4 补充）：
- 未导入→拒
- 只导 3 类→拒（缺类）
- 有快照无报告 done→拒
- 有报告无 execution→拒
- 纯人工 execution + 报告 done→推进成功
- 重复 import→新 run，旧 run is_current=false；报告读新 run 不重复计数
- 报告重生成→新 generation，旧 report is_current=false；旧 report 的 execution 不满足当前闸口（finding 4）
- **advice 重生成→新 advice_generation，旧 generation is_current=false；旧 advice 不可采纳/执行（finding 1）**
- **先执行旧 generation 建议→重生成 advice→闸口失败（旧 adopted execution 不属当前 generation，finding 1）**
- manual execution 不受建议重生成影响（finding 1）
- **从未生成 AI 建议→纯 manual execution 可建可推进（v6 P0）**
- **advice LLM 失败→200 status=failed + 旧 generation 保持 current（v6 F3）**
- 并发报告重试→partial UQ 防双 current（finding 2）
- **双 import 交错→事务 B 重检 run.is_current，过期返回 superseded 不调 LLM（finding 5）**
- import 后自动报告 blocked→快照仍提交（事务 A 独立，finding 1）
- execution 状态降级（completed→failed）→闸口不再满足（finding 4）
- adopt→reject 切换 + adopted_text 修订→UPDATE + D3_ADVICE_DECISION_CHANGED 审计（次要1）
- 无 batch provenance（strict_inspection/alternative）→provenance 从 IQC/report-level 生成非空（finding 6）
- **alternative provenance 用 `{source_type:'report', record_key:'report:{id}:summary'}` 非空字符串（finding 3）**
- **unknown arrival_status + 受影响客户→risk_level=high（后端 floor，非靠 LLM）（finding 4）**
- 跨 CAPA advice_id 拒绝→404/403
- **跨工厂 advice_id/execution_id 拒绝→404/403（finding 6，复合 FK）**
- **evidence_refs url 含 javascript:/file:→422 拒绝（次要2）**
- 无凭证→/d3/report + /d3/advice 返回 422 blocked；import 仍 200 + report_status=blocked

## 14. 关键约束

- `factory_id` NOT NULL 全表（**7 表**）+ 复合 FK 保证父子一致（finding 6）
- `enqueue_embedding` 不适用（D3 非 RAG 实体）
- 交付顺序：01.1 完成后才进 01.7
- AI_REQUIRED=true：无凭证 BLOCKED
- 状态机：D3_INTERIM→D4_ROOT_CAUSE 线性边已在
- D3 阶段守卫：写端点 `capa.status == D3_INTERIM`
- 不可变 generation 覆盖 run→report→advice_generation→advice + partial UQ is_current
- **execution 归属**（v6 P0）：report_id NOT NULL（业务归属，manual/adopted 都有）+ generation_id nullable（仅 adopted）+ advice_id nullable + CHECK 区分 manual/adopted；复合 FK (generation_id, report_id, factory_id) 保同链
- **advice 只 generation_id 不存 report_id**（finding 3，避免双真源；report 从 generation 派生）；adoption 只 advice_id；run→capa 复合 FK 保证同链
- **统一 ON DELETE RESTRICT + CAPA 软删除**（finding 2）：全链不可物理删；存在 D3 审计实体禁止物理删除 CAPA/run/report/generation；CAPA 用归档不删
- 闸口 adopted execution 须属当前 generation；manual 无 generation 也算（v6 P0，按 report_id 查）
- IQC 查 iqc_inspections
- 发布策略：A+B 原子发布（Slice A/B 仅实现顺序）
- 两阶段事务：A 提交 run/快照，B 生成报告，B 失败不回滚 A；B 获锁后重检 run.is_current，过期 superseded
- record_key：每类快照带 record_key + source_id，**record_key 永不为空只有 snapshot_id 可空**（次1）
- batch_key = `hash(normalized_material + normalized_lot)`，lot 缺失退化 `{snapshot_type}:{source_id}`；batches[].source_refs 保留原始 provenance（finding 4）
- risk floor：`risk_level = max(llm_risk, deterministic_floor)`，unknown+受影响客户→high
- arrival_status 从 erp_raw_data 读，枚举校验，缺失→unknown
- provenance 按 advice_type 映射；alternative 用 report-level record_key 非空
- 建议生成先检查 LLM 凭证再建 generation（次4）
- **短事务三阶段**（v7 F4）：报告/建议生成 = 锁+建 running artifact+提交 → 无锁 LLM → 重锁+确认 current+完成/superseded/failed；LLM 不持 capa 锁
- **running 态 + partial UQ + stale 恢复**（v7 F1/F4）：report/advice_generation status 含 running；CHECK 禁 is_current=true AND status!=done；running partial UQ 防并发；started_at 超阈 stale→failed
- **多单位数组**（v7 F2）：qty_by_status/impact_qty 是 `[{qty,unit}]` 数组；shipment unit 来源 erp_raw_data/物料主数据，缺失 unknown 不合并
- **advice 同代复合 FK**（v7 F3）：advice UNIQUE(advice_id, generation_id, factory_id)；execution 复合 FK 保证 advice_id 与 generation_id 同代
- execution PATCH 全字段审计 + evidence_refs scheme 白名单（次1/次2）

## 1. 目标与成功标准

**作为** 现场质量工程师 / 8D 团队负责人，**想要** D4 根因与 D7 预防 node-action 关联到 FMEA Cause/Prevention 节点，并从 FMEA 反查关联 8D，**以便** 双向追溯、关联可审计。

**成功标准（一句话）**  
从 8D 能跳到关联 FMEA 节点并**实际高亮/选中该节点**；从 FMEA（文档或节点）能反查到正确 8D 且带来源标签；**每一次**关联建立都写 `FMEA_LINKAGE_CREATED`（含 capa_id、fmea_id、node_id、方向）；跨工厂不可越权。

## 2. 现状与 Gap

| 能力 | 现状 | Gap |
|---|---|---|
| 8D→FMEA 文档级 | `link_fmea` + `CAPAEightD.fmea_ref_id` / `fmea_node_id`，审计 `LINK_FMEA` | 缺统一 `FMEA_LINKAGE_CREATED` |
| D7→Prevention | `CapaD7NodeAction` 含节点字段；`confirmed`/`skipped`/`auto_filled` 同表 | 反查须排除 `skipped`；缺统一 linkage 审计 |
| FMEA→8D 反查 | `GET /api/capa/by-fmea-node/{fmea_id}` + `RelatedCAPAList` | 只查 header；**无 factory 过滤**；不查 D7/D4 |
| D4 根因→Cause | `source_ref` JSONB 未规范化；UI 无 Cause 选择 | 写路径 + 校验 + UI + 反查 + 审计 |
| 深链 `?node=` | 编辑器仅匹配 `failureModeNodeId` | Cause/Prevention **不会**选中；须改契约 |
| 反查索引 | 无 `fmea_ref_id` / D7.`fmea_id` / source_ref JSONB 表达式索引 | 全表扫描风险 |
| E2E | 无专属 spec | 需新增（含节点高亮与分路径审计） |

**决策摘要**

| 议题 | 选择 |
|---|---|
| 反查匹配范围 | header + D7（仅 confirmed/auto_filled）三节点 + D4 `source_ref.cause_node_id` |
| D7 skipped | **不纳入**反查；不贡献 `d7_*` sources |
| 列表展示 | 同一 8D 去重一行 + `link_sources` 标签（规范顺序见 §4.2） |
| 审计 | **实现**故事契约 `FMEA_LINKAGE_CREATED`（与既有 `LINK_FMEA` / `D7_NODE_*` / `D4_VERIFICATION_*` **并存**） |
| 工厂 | 三源查询 + 目标 FMEA 可见性均强制 factory scope |
| 深链 | 统一 `/fmea/{id}?tab=graph&highlightNode={node_id}` |
| D4 Cause 写路径 | 完整 UI + 规范化 `source_ref` + 反查纳入 |
| Cause 候选 | 仅已关联 FMEA 的 `type === "FailureCause"` 节点 |
| 索引 | 本切片迁移补文档级 + JSONB 表达式索引 |
| D7 confirmed Prevention | **服务端**从 canonical recommendation 复制 `prevention_control_node_id`/名称，不信客户端 |
| 写路径不变量 | `capa.factory_id == fmea.factory_id` 且 `capa.product_line_code == fmea.product_line_code`（header/D4/D7/seed） |
| rule 兜底 | `fmea_id is None` → **不写** `FMEA_LINKAGE_CREATED` |
| related-capa 节点优先级 | 用户当前图选择优先于 URL `highlightNode` |
| header 幂等 | `link_fmea` 对 CAPA `SELECT … FOR UPDATE` 后再比 old/new |

## 4. 数据契约

不新建业务表。三类关联复用既有列：

| 源 | 实体 / 字段 | 反查命中条件 |
|---|---|---|
| header | `CAPAEightD.fmea_ref_id` + `fmea_node_id` | `fmea_ref_id == fmea_id`；若传 node 则 `fmea_node_id` 相等；**且** `factory_id ∈ scope` |
| D7 | `CapaD7NodeAction` 节点字段 | `fmea_id` 匹配；`action IN ('confirmed','auto_filled')`；若传 node 则三字段任一相等；**且** `factory_id ∈ scope` |
| D4 Cause | `source_ref` | `source_ref->>'fmea_id'`；可选 `->>'cause_node_id'`；**且** verification / capa `factory_id ∈ scope` |

### 4.1 `source_ref` 规范化形状

```json
{ "fmea_id": "<uuid-str>", "cause_node_id": "<str>" }
```

规则：

1. 仅允许上述两键；多余键 → `ValueError`（400）。
2. `capa.fmea_ref_id` 为空 → 400「须先关联 FMEA」。
3. `fmea_id` 必须等于 `str(capa.fmea_ref_id)`（标准 UUID 字符串）。
4. 目标 FMEA 必须满足 **同厂同产品线**（§5.0）；否则 400/403。
5. `cause_node_id` 必须存在于该 FMEA `graph_data.nodes` 且 `type == "FailureCause"`。
6. `source_ref = null` 合法。
7. update：省略 = 不改；显式 `null` = 清空。
8. **相同值 PATCH**：规范化后与现库相等 → **不写** `FMEA_LINKAGE_CREATED`，也 **不写** `D4_VERIFICATION_UPDATED`（幂等）。
9. **passed / failed 记录允许事后改 Cause**（与 method/result 可改一致）；**建立/更换/清空** 均写 verification 侧审计（见 §5.2 / §6）。不因 conclusion 冻结 source_ref。

### 4.2 反查响应

```json
{
  "report_id": "...",
  "document_no": "8D-...",
  "title": "...",
  "status": "D4_ROOT_CAUSE",
  "product_line_code": "DC-DC-100",
  "link_sources": ["d4_cause", "d7_prevention", "header"]
}
```

**`link_sources` 规范顺序**（固定字典序，实现与测试共用常量）：

```
d4_cause < d7_failure_cause < d7_failure_mode < d7_prevention < header
```

| 值 | 含义 |
|---|---|
| `header` | 命中 header 文档/节点 |
| `d4_cause` | 命中验证 `source_ref.cause_node_id` |
| `d7_failure_mode` | 命中 D7 FM（且 action∈confirmed/auto_filled） |
| `d7_failure_cause` | 命中 D7 Cause |
| `d7_prevention` | 命中 D7 Prevention |

同一 `report_id` **一行**；`link_sources` 去重后按上表排序。列表排序：`document_no ASC`。

**不存在** `d7_skipped` 来源——跳过记录不出现在反查结果中。

## 5. API 与服务

### 5.0 跨模块关联不变量（写路径统一）

凡建立 8D↔FMEA 关联，必须同时满足（与现有 D7 `_fetch_fmea_for_d7` 对齐）：

```
capa.factory_id == fmea.factory_id
capa.product_line_code == fmea.product_line_code
```

| 路径 | 应用方式 |
|---|---|
| `link_fmea` | 加载目标 FMEA 后校验；失败 → 403/400（与 D7 一致：跨厂/跨产品线 `PermissionError`→403） |
| D4 `source_ref` | `_normalize_and_validate_source_ref` 内校验 |
| D7 | **已有**，保持 |
| E2E seed | 只构造同厂同产品线对 |

**禁止**多工厂用户写入 `CAPA(factory=A) → FMEA(factory=B)`——否则反查按 effective factory 过滤后必断双向。

### 5.1 反查端点（path 不变）

```
GET /api/capa/by-fmea-node/{fmea_id}?fmea_node_id=<optional>
```

#### 权限与范围（本切片强制）

| 检查 | 行为 |
|---|---|
| CAPA VIEW | `< VIEW` → 403 |
| 目标 FMEA 存在性 | 不存在 → 404 |
| 目标 FMEA 工厂可见性 | 1）`check_factory_access(fmea.factory_id, scope)`（accessible）；2）若 `scope.effective_factory_id is not None`，则 **必须** `fmea.factory_id == effective_factory_id`，否则 **404**（不泄露其它厂文档）。现有 `check_factory_access` **不**检查 effective——本端点必须显式补第二步 |
| 结果集工厂 | 三源查询 `factory_id` 过滤：`effective_factory_id` 优先（`==`），否则 `IN accessible_factory_ids`；`accessible=[]` → `[]`；group admin（`accessible=None`）且无 effective → 不加 factory 谓词 |
| 产品线 | 合并后 `EXPLICIT` 过滤 / `NONE` → `[]`（保持） |

服务签名扩展（示意）：

```python
async def get_capas_by_fmea_node(
    db, fmea_id: str, fmea_node_id: str | None,
    *, accessible_factory_ids: list[UUID] | None,  # None = all
    effective_factory_id: UUID | None = None,
) -> list[dict]
```

API 层从 `RequestScope` 传入 scope，并先做 FMEA 可见性（含 effective）。

#### 查询语义

| 参数 | 行为 |
|---|---|
| 仅 `fmea_id` | 任意关联该 FMEA 的 8D（header 文档级 OR D7 采纳 OR D4 source_ref） |
| + `fmea_node_id` | 仅节点命中 |

#### 实现策略

单事务内最多三次查询 + 应用层按 `report_id` 合并：

1. **header** — `capa_eightd` where `fmea_ref_id` + factory 谓词；node 过滤 `fmea_node_id` → `header`
2. **D7** — `capa_d7_node_action` where `fmea_id` **AND `action IN ('confirmed','auto_filled')`** + factory；node 过滤三字段 OR → 按命中字段贡献 `d7_*`  
   - 仅 fmea_id、无 node：该 capa 在该 FMEA 上有任一采纳 action 即命中；sources 按该 action **非空**节点字段并集贡献（prevention 空则不贡献 `d7_prevention`）
3. **D4** — verification join capa where `source_ref->>'fmea_id'` + factory；node 过滤 cause → `d4_cause`
4. 批量加载 CAPA 头 → 合并 sources（规范序）→ `document_no ASC` → API 层 PL 过滤

### 5.2 D4 写路径

| 模型 | 变更 |
|---|---|
| `VerificationCreate.source_ref` | 保留；服务层规范化+校验 |
| `VerificationUpdate` | **新增** `source_ref`（`exclude_unset`） |
| `VerificationResponse` | 已有，无改 |

`_normalize_and_validate_source_ref(db, capa, source_ref) -> dict | None`  
在 create / update 写入前调用。读 FMEA 时强制 §5.0 同厂同产品线 + 图节点类型校验。

**source_ref 实际变化时的审计（强制，非可选）**

| 变更 | verification 审计 | `FMEA_LINKAGE_CREATED` |
|---|---|---|
| 建立/更换 Cause | 结论跃迁 → PASSED/FAILED 的 `changed_fields` 含 `source_ref`（+ `old_source_ref`）；**无**跃迁（含 pending）→ **必须**写 `D4_VERIFICATION_UPDATED` | **必须**写（source=`d4_cause`） |
| 清空 Cause → null | 同上：**必须**写 PASSED/FAILED 字段或 `D4_VERIFICATION_UPDATED` | **不写** |
| 相同值 | 不写 | 不写 |

**同时改 conclusion 与 source_ref**：

- 先应用字段，再派生 `is_verified`
- PASSED/FAILED 的 `changed_fields` **必须含** 最终 `source_ref` 与（若变）`old_source_ref`
- source_ref 实际建立/更换时另写一条 LINKAGE

### 5.3 D7 confirmed：Prevention 落库（阻断修复）

**现状**：`D7NodeActionCreate` 无 `prevention_control_node_id`；前端 confirm 不传；`record_d7_action` 虽拿到 canonical `rec`，**未**复制 Prevention 到 action 行 → confirmed 的 prevention 恒 null → 反查/深链/E2E 均不可用。

**本切片定稿**（不信任客户端字段）：

1. `record_d7_action` 在 key 命中 canonical `rec` 后，**服务端**复制：
   - `prevention_control_node_id` ← `rec` 中对应字段（若有）
   - `prevention_control_name_before` / `prevention_control_name_after` ← `rec` 中对应名称字段（若有；字段名以实现中 rec 形状为准）
2. 适用范围：
   - **新建** confirmed / skipped（skipped 也复制节点引用，便于审计对照；**反查仍排除 skipped**）
   - **skipped→confirmed** 与 **任意 action 变更**：同步刷新上述字段 + `recommendation_hash`
   - **幂等同 action+reason**：可刷新 hash 与 prevention 字段至 canonical（与现 hash 刷新策略一致），**不**写新 LINKAGE
3. 若 canonical `rec` **无** Prevention：落库 null；LINKAGE 的 `node_id` / `source` 回退：`prevention` → `failure_cause` → `failure_mode`（仅非 null 的第一项）
4. **不**扩展客户端 schema 强制传 prevention（可选加只读响应字段即可）；复制只发生在服务端
5. 单测：**图中已有 Prevention 的 rec → confirmed 后 DB 非 null → 按 prevention node 反查命中 `d7_prevention`**

auto_fill 路径已写 prevention——保持；本切片补齐 **confirmed 与 auto_fill 一致可反查**。

### 5.4 写路径增补 `FMEA_LINKAGE_CREATED`

| 路径 | 既有审计 | 本切片追加 LINKAGE |
|---|---|---|
| `link_fmea` | `LINK_FMEA` | 仅当 `fmea_ref_id` 或 `fmea_node_id` **实际变化**；写前对 CAPA **`SELECT … FOR UPDATE`** 再读 old 比较（防并发双写） |
| `record_d7_action` 新建 confirmed | `D7_NODE_*` | **仅当 `req.fmea_id is not None`**；node/source 按 §5.3 回退序 |
| `record_d7_action` 幂等同 action | 无新审计 | **不**写 LINKAGE |
| confirmed→skipped | `D7_ACTION_CHANGED` | **不**写；反查立即不命中 |
| skipped→confirmed | `D7_ACTION_CHANGED` | **仅当 `fmea_id is not None`** 写 LINKAGE；并同步 Prevention 字段 |
| rule 兜底 `fmea_id is None` | `D7_NODE_*` | **永不**写 LINKAGE（禁止 `fmea_id="None"` / `rule:*` 节点记入 FMEA 关联） |
| auto_fill 写入 prevention | 既有 | **仅当 fmea_id 非 null** 写 LINKAGE（source=`d7_prevention`） |
| D4 source_ref 建立/更换 | PASSED/FAILED/UPDATED | 写 LINKAGE（§5.2） |

### 5.5 path 行为

- `link_fmea` / D7 / 反查 **path 不变**
- `link_fmea` **语义收紧**：同厂同产品线 + 行锁 + LINKAGE

## 6. 审计：`FMEA_LINKAGE_CREATED`

对齐故事字段级契约（`US-E2E-01.4` 验收契约表）：

```python
AuditLog(
    table_name="capa_eightd",
    record_id=capa.report_id,          # capa_id
    action="FMEA_LINKAGE_CREATED",
    changed_fields={
        "capa_id": str(capa.report_id),
        "fmea_id": str(fmea_id),
        "node_id": node_id_or_null,     # header 可无节点 → null
        "direction": "8d_to_fmea",      # 本切片仅此方向；反查只读不写
        "source": "header" | "d4_cause" | "d7_failure_mode" | "d7_failure_cause" | "d7_prevention",
    },
    operated_by=user_id,
    factory_id=capa.factory_id,
)
```

| 规则 | 说明 |
|---|---|
| 与既有审计 | **并存**，不删除 `LINK_FMEA` / `D7_NODE_*` / `D4_VERIFICATION_*` |
| 幂等 | 相同关联无实际变更 → 不写；header 依赖行锁 |
| 前置 | **`fmea_id` 必须为真实 FMEA UUID**；rule 兜底不写 |
| 方向 | 本切片只产生 `8d_to_fmea`；反查不写 |
| E2E | **分别**断言本场景实际建立的每一种关联都有对应 `FMEA_LINKAGE_CREATED`（禁止「有任一 linkage 即过」） |

**D4 pending / 无结论跃迁时的 verification 审计（强制）**：

- 建立/更换 Cause：`D4_VERIFICATION_UPDATED`（`verification_id`、`source_ref`、`old_source_ref`）**+** `FMEA_LINKAGE_CREATED`
- 清空 Cause：`D4_VERIFICATION_UPDATED` **必须**写；**不**写 LINKAGE  
验收：LINKAGE 覆盖「建立」；UPDATED 覆盖「字段变更含解除」。

## 7. 前端

### 7.1 深链契约（统一）

**所有** 8D→FMEA 节点跳转使用：

```
/fmea/{fmea_id}?tab=graph&highlightNode={node_id}
```

| 组件 | 行为 |
|---|---|
| `RelatedFMEALink` | 有 `fmeaNodeId` 时改用上述 URL（替换仅 `?node=`） |
| D4 Cause Tag | 同上 |
| D7 Prevention Tag | 同上 |
| 仅文档级（无节点） | `/fmea/{fmea_id}`（可无 query） |

**编辑器**（`FMEAEditorPage`）：

- 既有 `?tab=graph&highlightNode=` 路径已支持图节点高亮——本切片 **复用**，不扩展 `?node=` 去匹配 Cause。
- **可选兼容**：若仍收到 legacy `?node=` 且能解析为图节点 id，可内部重定向/等同 `highlightNode`；**非必须**。新代码只产新契约。
- related-capa tab 的 `effectiveNodeId`（**用户当前选择优先于 URL**，避免深链锁死）：

```
effectiveNodeId =
  selectedGraphNode?.id
  ?? searchParams.highlightNode
  ?? selectedFunctionId
  ?? undefined
```

实现注意：首次应用 `highlightNode` 时应写入组件选中状态（`selectedGraphNode` / 等价 state）；之后用户点击其它图节点只改 state，**不必**清 URL，但 effective 已以 state 为准。

E2E **必须**断言目标节点被选中/高亮（graph 选中态、详情面板 node id、或稳定 testid），**禁止**只断言 URL 字符串。
### 7.2 `D4VerificationCard`

- prop：`fmeaRefId: string | null`

## 8. 测试矩阵

### 8.1 工厂与权限

1. 单工厂用户：仅见本厂关联 8D  
2. 多工厂用户 + `effective_factory_id`：仅有效工厂；FMEA 属其它 accessible 厂但非 effective → 反查 **404**  
3. 无工厂权限（accessible=[]）：`[]`  
4. group admin：可见跨厂（在 PL 规则内）  
5. 目标 FMEA 不在 accessible：404  
6. CAPA VIEW 不足：403  
7. **定稿**：反查只要求 CAPA VIEW + FMEA 行 factory/effective 可见，**不**额外要求 FMEA 模块权限  
8. `link_fmea` 跨厂或跨产品线 → 403；同厂同产品线才成功  
9. D4 source_ref 指向跨厂 FMEA → 400/403  

### 8.2 反查语义

1. 仅 header → `["header"]`  
2. 仅 D7 **confirmed** 且 prevention 已从 rec 落库 → 含 `d7_prevention`  
3. D7 **skipped** 同节点 → **不命中**  
4. skipped→confirmed → 命中且 prevention 已同步；confirmed→skipped → 消失  
5. 仅 D4 cause → `["d4_cause"]`  
6. 三源同 capa → 一行 + sources 并集且 **规范序**  
7. 传 node 过滤正确  
8. 无关联 → `[]`  
9. PL scope  
10. confirmed 后 DB `prevention_control_node_id` 等于 canonical rec（有 Prevention 时）  

### 8.3 source_ref / 审计

1. 合法 Cause 落库  
2. 未关联 FMEA / 错 fmea_id / 非 FailureCause / 未知节点 / 多余键 / 跨厂跨 PL → 4xx  
3. update 显式 null 清空 → **必须** `D4_VERIFICATION_UPDATED`；**无** LINKAGE  
4. 建立 Cause → UPDATED 或 PASSED/FAILED 字段 + LINKAGE（source=`d4_cause`）  
5. 相同 source_ref PATCH → 无新 UPDATED、无新 LINKAGE  
6. 同时改 conclusion + source_ref → PASSED/FAILED 含 source_ref/old，且 LINKAGE 一条  
7. passed 后改 Cause → 允许 + LINKAGE  
8. `link_fmea` 变更 → LINKAGE source=`header`；并发相同请求 → 仅一条 LINKAGE（行锁）  
9. D7 confirmed（`fmea_id!=null`）→ LINKAGE；幂等 → 无新 LINKAGE  
10. D7 confirmed **`fmea_id is None`（rule）→ 无 LINKAGE**  
11. auto_fill prevention → LINKAGE source=`d7_prevention`

## 9. 索引迁移

本切片 Alembic 增加（名称可微调，语义固定）：

```sql
-- header 反查
CREATE INDEX IF NOT EXISTS ix_capa_eightd_fmea_ref_id
  ON capa_eightd (fmea_ref_id)
  WHERE fmea_ref_id IS NOT NULL;

-- 可选复合：工厂 + FMEA（反查主路径）
CREATE INDEX IF NOT EXISTS ix_capa_eightd_factory_fmea
  ON capa_eightd (factory_id, fmea_ref_id)
  WHERE fmea_ref_id IS NOT NULL;

-- D7 反查（采纳过滤 + fmea）
CREATE INDEX IF NOT EXISTS ix_capa_d7_fmea_action
  ON capa_d7_node_action (fmea_id, action)
  WHERE fmea_id IS NOT NULL;

-- D4 source_ref 表达式
CREATE INDEX IF NOT EXISTS ix_capa_rcv_source_fmea
  ON capa_root_cause_verification ((source_ref->>'fmea_id'))
  WHERE source_ref IS NOT NULL;

CREATE INDEX IF NOT EXISTS ix_capa_rcv_source_cause
  ON capa_root_cause_verification ((source_ref->>'cause_node_id'))
  WHERE source_ref IS NOT NULL;
```

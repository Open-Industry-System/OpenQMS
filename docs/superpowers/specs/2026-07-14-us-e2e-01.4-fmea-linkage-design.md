## 1. 目标与成功标准

**作为** 现场质量工程师 / 8D 团队负责人，**想要** D4 根因与 D7 预防 node-action 关联到 FMEA Cause/Prevention 节点，并从 FMEA 反查关联 8D，**以便** 双向追溯、关联可审计。

**成功标准（一句话）**  
从 8D 能跳到关联 FMEA 节点；从 FMEA（文档或节点）能反查到正确 8D 且带来源标签；header / D7 / D4 关联建立均可在审计中追溯。

## 4. 数据契约

不新建表。三类关联复用既有列：

| 源 | 实体 / 字段 | 反查命中 |
|---|---|---|
| header | `CAPAEightD.fmea_ref_id` + `fmea_node_id` | `fmea_ref_id == fmea_id`；若传 node 则 `fmea_node_id` 相等 |
| D7 | `CapaD7NodeAction.fmea_id` + `failure_mode_node_id` / `failure_cause_node_id` / `prevention_control_node_id` | `fmea_id` 匹配；若传 node 则任一节点字段相等 |
| D4 Cause | `CapaRootCauseVerification.source_ref` | `source_ref->>'fmea_id'` + 可选 `->>'cause_node_id'` |

### 4.1 `source_ref` 规范化形状

唯一合法非空形状：

```json
{ "fmea_id": "<uuid-str>", "cause_node_id": "<str>" }
```

规则：

1. 仅允许上述两键；多余键 → `ValueError`（400），不静默剥离。
2. `capa.fmea_ref_id` 为空 → 不可写 Cause（400：「须先关联 FMEA」）。
3. `fmea_id` 必须等于 `str(capa.fmea_ref_id)`（标准 UUID 字符串）。
4. `cause_node_id` 必须存在于该 FMEA `graph_data.nodes` 且 `type == "FailureCause"`。
5. `source_ref = null` 合法（未选 Cause）。
6. update：省略 = 不改；显式 `null` = 清空。

### 4.2 反查响应（向后兼容扩展）

```json
{
  "report_id": "...",
  "document_no": "8D-...",
  "title": "...",
  "status": "D4_ROOT_CAUSE",
  "product_line_code": "DC-DC-100",
  "link_sources": ["header", "d4_cause", "d7_prevention"]
}
```

`link_sources` 取值（可多选，去重后稳定排序）：

| 值 | 含义 |
|---|---|
| `header` | 命中 header 文档/节点 |
| `d4_cause` | 命中验证 `source_ref.cause_node_id` |
| `d7_failure_mode` | 命中 D7 `failure_mode_node_id` |
| `d7_failure_cause` | 命中 D7 `failure_cause_node_id` |
| `d7_prevention` | 命中 D7 `prevention_control_node_id` |

同一 `report_id` **只返回一行**，`link_sources` 合并。排序：`document_no ASC`。

## 5. API 与服务

### 5.1 反查端点（path 不变）

```
GET /api/capa/by-fmea-node/{fmea_id}?fmea_node_id=<optional>
```

- 权限：`Module.CAPA` ≥ VIEW（不变）
- 产品线：`EXPLICIT` 过滤 / `NONE` → `[]`（不变）
- 工厂：本切片**不新增**服务层 factory 过滤（与现实现一致，避免行为突变）

#### 查询语义

| 参数 | 行为 |
|---|---|
| 仅 `fmea_id` | 任意关联该 FMEA 的 8D（header 文档级 OR D7.fmea_id OR D4 source_ref.fmea_id） |
| + `fmea_node_id` | 仅节点命中（header.fmea_node_id OR D7 三节点 OR D4 cause_node_id） |

#### 实现策略

单事务内最多三次查询（或等价 UNION），应用层按 `report_id` 合并：

1. **header** — `capa_eightd` where `fmea_ref_id`；node 过滤 `fmea_node_id` → 贡献 `header`
2. **D7** — `capa_d7_node_action` where `fmea_id`；node 过滤三字段 OR → 按实际命中字段贡献 `d7_*`；仅 fmea_id 时按非空字段并集贡献
3. **D4** — `capa_root_cause_verification` where `source_ref->>'fmea_id'`；node 过滤 `cause_node_id` → 贡献 `d4_cause`
4. 批量加载 CAPA 头字段 → 合并 sources → `document_no ASC`

旧客户端忽略 `link_sources` 即可，其余字段语义不变。

### 5.2 D4 写路径

| 模型 | 变更 |
|---|---|
| `VerificationCreate.source_ref` | 保留；服务层规范化+校验 |
| `VerificationUpdate` | **新增** `source_ref: dict \| None`（`exclude_unset`） |
| `VerificationResponse` | 已有 `source_ref`，无改 |

服务函数：`_normalize_and_validate_source_ref(db, capa, source_ref) -> dict | None`  
在 `create_verification` / `update_verification` 写入前调用。`ValueError` → API 400（与现网 verification 错误映射一致）。

**不**强制每条验证必须有 Cause；**不**改 D4→D5 gate。

### 5.3 不改 path 的既有写路径

- `link_fmea` — 保持
- `record_d7_action` / auto_fill — 保持（本切片最多补 FE 跳转）

## 6. 审计

| 关联建立路径 | action | changed_fields |
|---|---|---|
| header `link_fmea` | 既有 `LINK_FMEA` | old/new `fmea_ref_id`、`fmea_node_id` |
| D7 confirm/skip/auto_fill | 既有 `D7_NODE_*` / `D7_ACTION_CHANGED` 等 | `fmea_id`、节点字段 |
| D4 create → passed/failed | 既有 `D4_VERIFICATION_PASSED` / `FAILED` | **增补** `source_ref` |
| D4 create/update 变更 `source_ref` 且无结论跃迁 | **新增** `D4_VERIFICATION_UPDATED` | `verification_id`、`source_ref`、update 时 `old_source_ref` |
| FMEA→8D 反查 | **不写** | 只读 |

**不**引入 `FMEA_LINKAGE_CREATED`。故事契约中的该事件名解释为「关联建立有审计」的意图，映射到上表。

## 10. 风险与取舍

| 风险 | 缓解 |
|---|---|
| JSONB `source_ref` 历史脏数据 | 反查用 `->>` 安全比较；写路径严格校验；脏数据不命中不崩溃 |
| FMEA 图节点删除后悬空 cause_node_id | 反查仍可能命中历史关联（可接受）；新写会 400 |
| related-capa 仅绑 Function 导致 Cause/Prevention 反查空 | `effectiveNodeId` 含 URL `node` 与 selectedGraphNode |
| 审计 action 增殖 | 仅新增 `D4_VERIFICATION_UPDATED` 一处；不引入 linkage 总线事件 |
| 反查三次查询性能 | 单 8D/节点场景数据量小；不做分页 |

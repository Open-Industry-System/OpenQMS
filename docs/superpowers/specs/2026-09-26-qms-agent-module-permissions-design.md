# OpenQMS 模块级 Agent 权限设计

日期：2026-09-26
状态：设计已确认；尚未实施。
范围：业务模块向独立 AI 插件开放的上下文、业务能力、审批与敏感数据边界。各模块的完整能力清单和逐项审批矩阵须在接入切片中盘点确认。

关联：[当前权限参考](../../permissions.md)、[既有决策 ADR-0006](../../DECISIONS.md)。本文承接独立插件、模块能力目录、任务级读写授权、模块最低审批和页面/工具共用业务服务的架构方向；目标契约不是现有 API 或已实施权限矩阵。

## 1. 目标与取舍

每个业务模块说明 Agent 可以读取哪些业务上下文、可以申请执行哪些业务能力，以及每项能力的最低审批要求。业务模块持有数据投影、脱敏和业务规则；平台统一计算身份、插件、任务和数据外发限制；插件不能自行授予权限。

选择“模块能力目录＋分层授权”，而不是扩展单一 `VIEW/EDIT` 级别或维护脱离业务模块的插件工具白名单。前者不能表达同模块内不同数据与命令的差异；后者容易形成第二套规则。此设计是既有角色权限之上的 Agent 专用能力边界，不替换人类用户的角色矩阵，也不引入可对任意业务对象求值的通用 ACL/策略引擎。

本次先固定权限语义并定向盘点现有代码，再用 8D D4/D5 做纵向样板，最后逐模块接入；不一次性移动全部业务代码或替换旧 Agent 功能。

## 2. 已确认决策

| 编号 | 决策 | 约束 |
|---|---|---|
| P01 | 模块按业务上下文类别声明可读项 | 例如 8D 问题、D3 证据；不是开放任意表或要求管理员逐字段勾选。敏感字段由模块输出契约处理。 |
| P02 | 模块逐项声明业务能力 | 查询、保存候选、采纳、验证、推进阶段等分别授权；工具不提供任意字段更新或 SQL。 |
| P03 | 跨模块读取分别授权 | 8D 任务需要 FMEA 或 IQC 数据时，必须取得数据所属模块的读取授权；关联关系不自动授予读取权。 |
| P04 | 每项上下文或能力有独立审批要求 | 同一模块可同时存在自动放行、两阶段模型审核与员工审批；最低要求由模块声明，管理员仅能收紧。 |
| P05 | 敏感数据先脱敏，再判断员工审批 | 模块先提供脱敏投影，再根据数据类别和任务情境决定是否要求员工审批；原文是独立的例外申请，不因脱敏版获准而开放。 |
| P06 | 原文读取例外严格绑定 | 默认只提供脱敏版；确需原文时，由具备指定审批权限、对象范围且非申请人的员工对本次任务、指定对象和字段审批，撤权、过期或范围变化后不再有效。 |
| P07 | 读取与外发分别授权 | 员工批准平台内读取（原文或脱敏版），不自动许可发送给独立插件或外部模型。对实际投影、数据类别、插件运行环境及目标模型分别执行外发策略；脱敏后也须重新获准，禁止外发时拒绝交付。 |
| P08 | 执行身份、插件与任务同时受限 | 用户任务用用户身份、后台任务用服务身份；插件长期授权和本次任务授权必须同时满足，读写范围独立。 |
| P09 | 页面与 Agent 共用业务服务 | 授权不能绕过模块的状态机、证据要求、业务审计与并发检查。 |
| P10 | 派生内容继承来源限制 | 建议、修订、报告、搜索索引及其他派生物不得因写入另一个模块而解除来源数据的敏感等级和访问限制；放宽可见性必须经受控降敏。 |

P04 的“自动”不是不校验：确定性的身份、租户、工厂、产品线、任务范围、业务前提检查始终执行。两阶段模型审核先判定 `needs_review`；标记待复核或信息不足时进入深入审核，未标记的请求仅在策略允许时放行。审核结果不授予新权限或证明业务事实成立。

## 3. 权限契约与职责

### 3.1 模块声明

模块公开稳定的上下文 ID 与命令 ID，不将 URL、ORM 字段或模型提示词当作能力标识。每项声明至少说明：模块归属、业务含义、契约版本、所需用户/服务身份权限、对象和作用域类型、数据类别、脱敏投影或业务命令、最低审批路径、审批者所需权限/对象范围与自批规则、业务前提、来源/版本及错误语义。上下文类别可以有 `masked` 与受限 `raw` 两种投影；原文不是脱敏版授权的隐含升级。具体传输字段和 HTTP/MCP 选择在接口规格中确定。

模块负责行级/对象级访问、业务规则和业务审计。业务服务返回当前规范数据及版本；搜索索引、向量结果与图投影只是发现线索，不是授权或正式写入的权威来源。统一搜索按对象所属模块的可读投影与范围过滤，详情仍由所属模块重新授权；无权对象不得通过命中数、摘要或错误信息泄漏存在。

模块发布最低审批要求；管理员可以在该模块允许的边界内减少可用能力、缩小范围、提高审批级别，不可降低最低要求。模块版本和策略变化须记录，正在进行的调用按当前有效权限和策略复核。目录按调用者过滤用于发现，出现于目录不等于调用保证成功；必需能力不足时阻止任务启动，可选能力允许明确降级。

### 3.2 平台判定与插件

平台将执行身份的现有角色权限及行级范围、插件长期授权、本次任务读/写授权、模块声明和管理员限制取交集；任一层缺失即拒绝。平台管理任务生命周期、审批、审计、数据外发策略与目录版本。独立进程内的插件一旦收到数据，平台无法只靠接口约束其后续外发；对于有外发限制的原文或脱敏投影，只有部署环境可验证且外发受控的可信插件才可接收，否则即使员工批准也不得向该插件交付，可改由人工页面处理。具体可信部署与外发控制机制须在实施前确定。跨模块读取分别计算交集，写入只针对任务明确授权的对象。插件声明所需能力、按需查询和提出调用请求，但声明不构成授权，且不能传入用户身份或租户来覆盖服务端身份。

旧的 `PermissionLevel` 仍是执行身份的模块权限上限；新增细粒度授权只限 Agent 接入，不改变页面用户角色的等级含义。审批接口校验审批者当前身份、模块声明的专用审批能力、对象范围和自批规则；仅有读取权不能批准插件读取。敏感原文和正式业务写入禁止申请人自批；其他能力默认禁止自批，模块确有业务依据时可显式声明例外，管理员只能收紧。后台服务身份发起的操作，仅在适用策略要求员工审批时，由具备该能力审批权限和对象范围的员工审批；服务身份不得充当人工审批者。其他操作仍按模块最低要求及管理员策略处理。任务创建及其范围授权是否需要员工确认，由独立的任务授权策略决定，不等同于逐次操作审批。审批不能扩大执行身份、插件或任务的已有权限。审批决议分别记录执行身份与审批身份，并绑定能力、投影、任务、对象与范围、参数、关键依据版本及有效期；批准其他请求或更改其中一项不能复用。调用时和审批后执行前均复核当前授权、业务前提和版本；撤权后不可沿用创建任务时的旧授权。

### 3.3 跨模块写回与派生数据

插件提交建议、修订或报告时，须引用平台提供的来源与版本。目标模块记录来源模块/对象引用、来源敏感等级及可见范围；生成的内容默认采用所有来源中更严格的限制，不能仅依赖插件自报的来源或“已脱敏”结论。来源不明或自由文本无法确认不含受限内容时，保守标记为受限并等待复核，不能直接写入更宽可见的对象或索引。写入前由目标模块按自身契约校验内容和目标可见范围，拒绝无法保留限制的写入；业务操作的授权不等于放宽保密等级的授权。

读取未降敏的派生部分时，既要满足目标模块的读取权，也要满足来源模块的对应数据权限、对象范围和当前任务范围。业务对象可以为可公开部分提供独立的安全投影；若无法可靠拆分，则整个派生对象按最高敏感等级受限。受控降敏须由有资格的员工按模块规则核验内容、来源与目标范围并留下依据和审计，降敏后只对经过核验的投影放宽可见性，不自动修改原始来源的等级。平台搜索、摘要、嵌入、缓存、导出与模型输入继承相同限制；来源撤权或降敏失效时不继续返回旧投影。

## 4. 读取与操作流程

1. **任务建立**：认证执行身份与插件，确定任务目标、读写对象范围及能力申请；必需能力和当前授权不满足则不启动。可信授权信息与业务文本分离。
2. **读取上下文**：模块先确认对象与范围。普通数据返回获准投影；敏感数据先生成脱敏投影，再按策略直接放行或等待员工审批。向独立插件交付任何投影前，须按实际数据类别和插件部署环境检查交付/外发策略；被禁止时不交付，即使已经脱敏。未经原文专项批准，不将原文作为可复用投影缓存，也不向插件返回原文；模块内部脱敏所需的读取仍受业务访问控制。对已批准原文的每次访问仍检查有效期、对象、字段、当前授权与插件运行环境的外发控制；审批等待期间不将原文交给审核模型。
3. **跨模块查询**：搜索和详情分别由每个数据所属模块校验；结果带来源、版本、验证状态和截断/索引滞后标记。获取证据的权限不等于修改证据对象的权限。
4. **外发模型**：在模型调用或模型审核之前，根据数据类别、实际投影、模型部署位置与外发策略再次判断。原文被拒绝外发时，可以生成脱敏投影并**重新**检查其外发策略；只有该投影对目标模型和插件均明确获准时才发送，否则拒绝本次模型调用，不自动降级放行。不能以员工原文读取批准替代外发许可。平台日志、缓存和错误信息同样不得回填被隐藏的原文。
5. **业务能力调用**：先完成不可被模型推翻的身份、能力、读写范围和业务前提检查，再按模块最低要求及管理员策略走直接放行、两阶段模型审核、员工审批或拒绝；审核异常、超时或无法解析时不执行。审批中不预先执行写入。
6. **执行与结果**：写回前核对来源标签、目标可见范围与派生内容限制；审批后重新校验执行身份与审批者的当前权限/范围、自批约束、参数、关键证据和对象版本，在业务服务的事务或等效并发控制中执行；冲突要求重新评估，必要时重新审批。写入携带幂等键，超时后先按键查询结果。审计记录插件与执行身份、能力、作用域、投影、审批策略和结果，不将“读取批准”“建议保存”“事实验证”混为一类。

失败响应需区分无权/不可见、待审批、前提不满足、授权或审批失效、依据版本冲突、外发受限及暂时失败；对无权对象的响应不披露对象存在。策略缺失、未知能力、未知投影、审核器故障默认不执行。拒绝和失效应可追踪，但审计记录避免存储不必要的敏感原文。

## 5. 首个样板与推广边界

先盘点 8D D4/D5 的现有 API、业务服务、校验、工厂/产品线限制、搜索和 Agent 工具；对每项能力建立“所属模块—业务语义—上下文/命令—数据类别—审批下限—业务服务入口—测试”的清单。下表仅是盘点起点，**不是已经生效的审批矩阵**：

| 类别 | 待盘点的 8D 样板能力 | 首版设计边界 |
|---|---|---|
| 上下文 | 8D 问题与 D3 措施、根因/验证状态 | 返回有权限的业务投影、来源与版本。 |
| 敏感读取 | 客户身份、供应商保密资料 | 先脱敏；脱敏版可视情形要求员工审批；原文必须专项员工审批并另查模型外发策略。 |
| 跨模块证据 | FMEA 节点、IQC 检验记录 | 分别检查 FMEA、IQC 的读取能力及对象范围。 |
| 建议命令 | 保存候选根因、条件性措施、验证方案 | 与正式采纳区分；具体自动/模型/员工审批由业务责任方确认。 |
| 正式命令 | 采纳、提交验证结论、推进阶段 | 分别授权，保留现有业务状态与审批门禁；审批下限需逐项确认。 |

样板验收后按模块逐项迁移：先确认数据与业务命令的归属，再声明能力和审批矩阵，补平台适配与页面/工具共用业务服务，最后覆盖测试。未迁移的旧 Agent 接口继续依旧规则运行，但不得把新能力目录误当作它们已受新治理覆盖；切换前需确认并行入口没有权限旁路。完整模块清单、默认审批级别、管理员操作界面、授权续期和兼容期，属于后续各切片的接口与交互规格，不在本文件中臆定。

## 6. 验收与实施前待定

验收至少覆盖：同模块细粒度授权；跨模块、跨租户、跨工厂与产品线隔离；搜索摘要、命中数、缓存及错误无越权泄漏；除获准的受限原文例外，敏感数据在插件和模型可见前已脱敏；脱敏版按策略待审批；原文申请绑定任务/对象/字段及到期撤权；无审批资格、跨范围或自批被拒；撤销审批者权限后批准失效；原文可读但模型外发不允许；脱敏版对目标插件或模型也禁止外发时不交付；仅外发策略重新许可的脱敏投影可发送；管理员不能降低模块最低审批；模型审核异常不执行；审批后参数/关键版本变化使批准失效；并发与幂等；供应商保密原文写入 8D 候选根因后，只有 8D 权限的其他插件和员工不得从详情、搜索、摘要、嵌入或导出取得该内容；经受控降敏后仅核验过的投影可扩大可见性；页面和工具共享业务规则；必需能力缺失阻止启动、可选能力显式降级；旧接口迁移前无旁路。

实施前仍需为每个接入切片明确：模块的实际上下文/能力清单、数据分类、脱敏字段规则及派生内容的来源/标记/降敏契约；逐项最低审批矩阵与自动审核评测阈值；插件凭据、可信部署与外发控制机制及传输协议；任务授权确认与过期交互；模型服务的部署位置与可外发数据策略；原文例外的有效期和审计保留期；接口字段、错误码与版本兼容方案。未确认这些细节，不开放对应敏感读取或正式写入能力。

当前代码锚点：角色权限见 `backend/app/core/permissions.py`；Agent 工具元数据见 `backend/app/services/agent/registry.py`；现有调用判定见 `backend/app/services/agent/gateway.py`；任务/会话见 `backend/app/models/agent.py`。它们提供接入基础，但本文件描述的模块上下文目录、任务级交集、脱敏与外发决策尚未因写入本规格而实现。

## 目标

在 8D 状态机的 `D8_GATE_PENDING→D8_APPROVAL_PENDING` 边接入文档更新审核门禁：D7 完成后系统（经显式 POST）用 LLM 分析受影响受控文档（控制计划、FMEA），D8 关闭审批前自动审核这些文档的版本更新与关键点覆盖情况，未通过则阻断推进；延期记录待办但仍阻断。镜像 D3 的生成-审核-决策链与 BLOCKED/重生成/failed 回读语义。

## 非目标（本子故事不做）

- SOP / 检验 SOP / 其他受控文档实体的版本管理（系统无此模型，本故事不新建——见「契约修订」）
- 受影响文档本身的更新操作（在 FMEA/控制计划模块完成，本故事只识别+审核+门禁）
- 文档更新内容的质量审核（只验「是否更新到位」，内容质量归各模块）
- 延期处理的到期跟踪闭环（后续迭代）
- 审批壳（01.3 负责；本故事只衔接 D8_GATE_PENDING→D8_APPROVAL_PENDING 门禁）

| # | 决策 | 依据 |
|---|---|---|

| C2 | **显式 POST 镜像 D3**。LLM 影响分析走独立 `POST /impact` + `GET /impact`（latest-by-created_at 含 failed），不进 `advance_capa` 路径。门禁 edge 只跑同步 DB 查询审核（无 LLM） | D3 终审教训：LLM 进 advance 会阻塞状态跳转 + 失败难处理 |
| C3 | **审核粒度：版本 bump + 关键点覆盖**。version_bump = 后版本 created_at > capa.created_at 且 sha256 变化；关键点覆盖 = 复用 `version_service.build_sync_preview` 的 ModifiedNode diff，LLM 产出的 key_point（node_id+field）命中 diff 即 covered | 第二轮澄清；既有 `build_sync_preview` + `NodeChange` 设施 |

## 数据模型（3 张新表，前缀 `capa_docg_`）

镜像 D3 表族：所有表 `factory_id NOT NULL` + 复合 FK（parent+factory）+ `is_current` partial-UQ + `status` enum CHECK + `attempt_token` CAS。迁移文件 `backend/alembic/versions/20260713_doc_gate.py`。

### `capa_docg_analysis`（影响分析生成根）

镜像 `capa_d3_impact_report`。LLM 产出受影响文档清单 + 每项关键更新点。

| 字段 | 类型 | 约束 |
|---|---|---|

| `capa_id` | UUID | FK capa_eightd.report_id, NOT NULL |
| `factory_id` | UUID | FK factories.id, NOT NULL（复合 FK `(capa_id,factory_id)` → capa_eightd）|
| `is_current` | bool | NOT NULL default false；partial-UQ `uq_docg_analysis_current` (capa_id WHERE is_current=true) |
| `status` | str(10) | NOT NULL default 'running'；CHECK ∈ {running,done,failed}；状态机 CHECK（同 D3 report：running→is_current=false+completed_at NULL；failed→is_current=false+completed_at NOT NULL；done→completed_at NOT NULL）|
| `affected_docs` | JSONB | done 时 NOT NULL；结构见下 |
| `llm_available` | bool | NOT NULL default false |
| `model` | str(40)? | — |
| `prompt_stats` | JSONB? | — |
| `error` | Text? | failed 时填 |
| `attempt_token` | UUID | NOT NULL default uuid4（CAS）|
| `started_at` | tz | server_default now() |
| `completed_at` | tz? | done/failed 时填 |

| `generated_at` / `created_at` | tz | server_default now() |

**`affected_docs` JSONB 结构**（done 时）：
```json
[{
  "doc_type": "control_plan",        // control_plan | fmea（sop/inspection_sop/other 保留枚举不产出）
  "doc_id": "<uuid>",
  "doc_name": "控制计划-DC-DC-100-v2",
  "key_points": [
    {"node_id": "fm-001", "field": "prevention_control", "expected_direction": "新增防错"}
  ]
}]
```

done 完备性 CHECK（同 D3 report done_complete）：`status='done'` 要求 `affected_docs IS NOT NULL AND llm_available=true AND completed_at IS NOT NULL`。

### `capa_docg_audit`（审核记录，每受影响文档一行）

| 字段 | 类型 | 约束 |
|---|---|---|
| `audit_id` | UUID PK | default uuid4 |
| `analysis_id` | UUID | FK capa_docg_analysis.analysis_id, NOT NULL（复合 FK `(analysis_id,factory_id)` → analysis）|
| `factory_id` | UUID | FK factories.id, NOT NULL |
| `doc_type` | str(16) | NOT NULL；CHECK ∈ {control_plan,fmea,sop,inspection_sop,other} |
| `doc_id` | UUID | NOT NULL |
| `doc_name` | Text | NOT NULL |
| `status` | str(16) | NOT NULL；CHECK ∈ {passed,pending_update,incomplete} |
| `version_before` | JSONB? | `{major,minor,sha256_8}` 审核时该 doc 最新版本 |
| `version_after` | JSONB? | 审核时新版本（无新版本则 NULL）|
| `version_bump` | bool | NOT NULL default false |
| `coverage` | JSONB | default []；`[{key_point:{node_id,field,expected_direction}, covered:bool, evidence:str?}]` |
| `covered_count` / `total_count` | int | NOT NULL default 0（coverage 派生计数，便于查询）|
| `audited_by` | UUID | FK users, NOT NULL |
| `audited_at` / `created_at` | tz | server_default now() |

### `capa_docg_decision`（门禁决策）

| 字段 | 类型 | 约束 |
|---|---|---|
| `decision_id` | UUID PK | default uuid4 |
| `analysis_id` | UUID | FK, NOT NULL（复合 FK `(analysis_id,factory_id)` → analysis）|
| `factory_id` | UUID | FK factories.id, NOT NULL |
| `decision` | str(10) | NOT NULL；CHECK ∈ {passed,blocked,deferred} |
| `no_affected_confirmed` | bool | NOT NULL default false |
| `defer_reason` | Text? | deferred 时 NOT NULL；passed/blocked 时 NULL（CHECK）|
| `defer_owner` | UUID? | FK users; deferred 时 NOT NULL |
| `defer_deadline` | date? | deferred 时 NOT NULL |
| `decided_by` | UUID | FK users, NOT NULL |
| `decided_at` / `created_at` | tz | server_default now() |

**decision 读取语义**：decision 行 append-only（每次 `run_audit`/`record_defer`/`confirm_no_affected` 各插一行，保留历史）。`_d8_doc_gate_gate` 与 `GET /decision` 读**最新行**（`ORDER BY decided_at DESC LIMIT 1`），与 `get_latest_analysis` 的 latest-by-created_at 模式一致。不做 `is_current` partial-UQ（避免同一 analysis 的多次 decision 互相冲突；append-only + latest-read 更简单且可审计历史）。

**decision 派生规则**（`run_audit` 插入新 decision 行时）：
- 全 audit 行 `status=passed` → decision=passed
- 任一 audit 行 `status ∈ {pending_update, incomplete}` → decision=blocked
- 空清单 + 工程师 `confirm_no_affected` → 插 decision=passed(`no_affected_confirmed=true`) 行
- 工程师 `record_defer` → 插 decision=deferred 行（**门禁 edge 仍 raise**，C5；latest-read 读到 deferred 仍阻断）

## 服务层：`backend/app/services/capa_doc_gate_service.py`

镜像 `capa_d3_containment_service.py` 结构。

### `generate_impact_analysis(db, capa, user_id)` — POST，LLM
1. `pc = build_client(...)`；`pc is None` → 写 `status='failed'`+`error='LLM 未配置'`+`llm_available=False` 行（`is_current` 不置）+ raise `ValueError("BLOCKED: 无 LLM 凭证")` → API 映射 **422 + `detail.blocked=True`**（同 D3/D4 BLOCKED 模式）
2. 建 `status='running'` 行（`attempt_token` CAS）+ 置 `is_current`（CAS 单 UPDATE WHERE status='running' + started_at + attempt_token，同 D3 终审 stale recovery）
3. 组 prompt（8D 根因/d5_correction/d7_prevention/severity + 该产品线 CP/FMEA 清单）→ `provider_adapter.complete_json`
4. 成功 → `status='done'` + `affected_docs` + `is_current=true` + `completed_at`
5. LLM 失败 → `status='failed'`+`error`，`is_current` 不置（GET 回读可查失败态，同 D3 终审第五轮）
6. 写审计 `DOC_IMPACT_ANALYZED`（`affected_doc_count`, `llm_available`, `status`）

### `get_latest_analysis(db, capa)` — GET，latest-by-created_at
镜像 D3 GET：返回最新 analysis（含 `status='failed'`），前端据此渲染重试按钮。

### `run_audit(db, capa, user_id)` — POST，同步 DB 查询，无 LLM
1. 查 `capa_docg_analysis` current 行（无 → raise "未生成影响分析"）
2. 遍历 `affected_docs`，对每项：
   - 查该 doc 在 `capa.created_at` 之后的最新版本（`version_service.get_latest_cp_version`/`get_latest_fmea_version`）
   - `version_bump` = 新版本 `created_at > capa.created_at` 且 `sha256_hash` 变化
   - 调 `build_sync_preview`-style diff 得 `ModifiedNode` 列表；逐个 key_point：node_id + field 命中 diff → `covered=True` + evidence
   - status = passed（version_bump 且所有 key_point covered）/ pending_update（无新版本）/ incomplete（有新版本但 key_point 未全覆盖）
3. insert `capa_docg_audit` 行 + insert `capa_docg_decision` 行（派生：全 passed→passed；否则 blocked；见上「decision 派生规则」）
4. 写审计 `DOC_UPDATE_AUDITED`（`per_doc_status`）+ `DOC_GATE_PASSED`/`DOC_GATE_BLOCKED`

### `record_defer(db, capa, reason, owner, deadline, user_id)` — POST
defer 仍阻断（decision=deferred，门禁 edge 仍 raise，C5）。写审计 `DOC_GATE_DEFERRED`（reason/owner/deadline）。

### `confirm_no_affected(db, capa, user_id)` — POST
空清单确认：analysis.current.affected_docs 为空时，工程师手动确认 → decision=passed(`no_affected_confirmed=true`)。写审计 `DOC_GATE_PASSED(reason="空清单人工确认")`。

## 门禁 edge 接入

`backend/app/services/capa_service.py` `advance_capa`，把 01.3 的占位改为真实 gate：

```python
elif current == EightDState.D8_GATE_PENDING and target == EightDState.D8_APPROVAL_PENDING:
    await _d8_doc_gate_gate(db, capa)   # 替换 01.3 的 pass 占位
```

`_d8_doc_gate_gate(db, capa)`：
1. 查 `capa_docg_analysis` 的 current 行（`is_current=true`）；无 → raise "请先生成文档影响分析"
2. 在该 analysis 下查 `capa_docg_decision` 最新行（`WHERE analysis_id=? ORDER BY decided_at DESC LIMIT 1`）
3. 无 decision 行 → raise "请先运行文档审核"
4. `decision != 'passed'`（含 deferred）→ raise `ValueError("文档门禁未通过：<原因>")` → API 400
5. `decision == 'passed'` → 通过（advance 继续 mutation + TRANSITION 审计）

## 风险与取舍

- **C1 窄范围 vs 故事「≥3 类」**：契约修订（见上）。SOP 无实体，新建 SOP 版本表超本故事范围；保留枚举供前向兼容是诚实做法，不伪造第三类。
- **关键点覆盖判定的近似性**：`build_sync_preview` 的 ModifiedNode diff 是结构级（node_id+field），LLM 产出的 key_point 须约束在 node_id+field 粒度才能匹配。prompt 工程须明确要求 LLM 输出 `node_id`（从 8D 关联的 fmea_node_id / CP item source_fmea_node_id 派生）+ field 名。无法匹配的 key_point → covered=false → status=incomplete。可接受：宁可误判 incomplete（人工复核）也不放过。
- **空清单人工确认的风险**：C4 防漏报，但依赖人工诚实。审计留痕（`no_affected_confirmed=true` + `decided_by`）可追溯。
- **defer 仍阻断**：C5 与故事一致，但 deferred 状态下 8D 长期卡在 D8_GATE_PENDING——到期跟踪归后续迭代（故事第 90 行明确排除）。
- **门禁 edge 同步审核无 LLM**：`run_audit` 是纯 DB 查询 + diff，快且不阻塞 advance；但须先 POST /audit 生成 decision 行，否则 edge raise "请先运行文档审核"。前端按钮门控保证顺序。
- **复用 D3 模式的一致性收益**：BLOCKED/重生成/failed 回读/CAS/审计事件全套复用，降低复审摩擦（D3 已 6 轮硬化）。表前缀 `capa_docg_` 与 D3 `capa_d3_` 平行，命名清晰。

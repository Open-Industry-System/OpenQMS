# R7 第二片：来料检验异常到 8D 调查建议

日期：2026-11-18。状态：两项产品取舍已确认，已纳入三项复审修订。

## 1. 目标与交付边界

质量工程师在异常来料检验单的 Agent 侧栏点「准备调查」，无需先创建 8D。Agent 读取正式检验记录，在授权范围内补查，生成调查建议卡，回答「已经确认了什么、还缺什么、下一步建议做什么」。材料足够时，附可供员工使用的 8D D2 问题描述草稿。

本片验证 IQC 能否成为任务起点，复用平台的权限、独立运行、多轮取数、证据引用和受控审阅。平台可保存任务、不可变建议、证据引用与审计。审阅是员工查看、核对和判断，不新增认可、审批或采纳状态。正式创建或关联 8D、SCAR、批次放行或隔离、通知供应商，均是另行授权的业务动作；生成、打开及复制建议不会触发这些动作。

通用机制引用[第一片规格][slice1] §3–§4、§7–§9：授权交集、来源继承、部署绑定、交付围栏、原子结果保存、历史读取、幂等及晚到结果处理。本规格定义 IQC 的事实语义、业务锚、查询范围和卡片合同；PFMEA 的双对象准入、逐措施结论与图覆盖回执不适用于本片。

### 2.2 员工今天如何处理异常

1. [IQC 详情页](../../../frontend/src/pages/iqc/IqcInspectionDetailPage.tsx)经[前端 API](../../../frontend/src/api/iqc.ts)、[IQC API](../../../backend/app/api/iqc.py)调用[检验服务](../../../backend/app/services/iqc_inspection_service.py)。处理状态依次为 `pending → inspecting → judged → closed`，检验结论独立保存为 `pending / accepted / rejected / concession`。

2. 页面提供项目结果录入和判定入口，持久模型与读取服务支持项目及测量记录。不过当前详情页把文本框字符串传给更新接口，DTO 又未包含服务定位项目所需的 `item_id`，录入链存在静态契约断点，本次未实测能完整录入。本片读取已存在的正式记录，不顺带修复录入链。`judge_inspection` 保存员工提交的结论、缺陷数、抽样量、描述、判定人和时间；它没有依据实测值或 Ac/Re 自动推导整单结论。AQL 方案不能代替正式判定，也不证明计划样本已经全部测量。

3. 页面在 `judged + rejected` 且员工可编辑 IQC 时提供「发起 SCAR」「申请复检」，另有让步接收、关闭动作。「发起 SCAR」调用 `POST /api/iqc/inspections/{id}/trigger-scar`，成功后跳到 SCAR；[SCAR 详情页](../../../frontend/src/pages/scar/SCARDetailPage.tsx)再提供「创建关联 8D」。后者先创建 CAPA，再关联 SCAR，是两个写请求，且不会自动形成 D2 正文。未发现 IQC 页面直接创建 8D 的入口。

4. `request_reinspect` 实际新建 `…-R1` 等检验单，用 `parent_inspection_id` 关联原单，复制项目与规格但不复制测量结果。原单保持原判定；复检接收不会把原拒收改成接收。让步接收则修改原单 `inspection_result`，并追加让步原因。

本次在页面、路由、模型和服务中未发现独立 NCR/MRB 不合格处置单或 IQC 批次隔离、退货、返工、报废状态机。现有拒收、让步和关闭是检验业务事实；「已隔离」「已退货」「已放行」须有各自正式执行证据。CAPA D3 已能读取 IQC 快照，属于已有 8D 下的遏制调查上下文，不是 IQC 已关联该调查的证明。参见 [D3 服务](../../../backend/app/services/capa_d3_containment_service.py) 的 `_query_iqc` 与 `_compute_batches`。

因此，「准备调查」放在员工决定发起或继续 SCAR/8D 之前，也允许已有调查时准备补充材料。它帮助整理信息，不接管现有人工业务动作。

## 3. 事实表与表述规则

以下均以所属模块的正式持久记录为来源。首次上下文提供本单事实及完整性标记；明细、复检和关联调查按 §5 补查。空值、不适用、无记录、查询失败与无权交付分别处理。

| 卡片所需信息 | 正式来源 | 可用条件 | 缺失时如何展示 |
|---|---|---|---|
| 检验单、状态、结论、判定时间 | `IqcInspection` 的 ID/编号、`status`、`inspection_result`、`judged_by/at`、`inspection_date` | 当前记录已正式判定且可读 | 缺判定不准入；检验日期缺失单列，判定时间只能标为判定时间 |
| 物料与供应商 | 单据 `part_no/name`、`material_id`、`supplier_id`；名称补查各模块 | 关联来源另行授权；当前主数据与当时单据分开 | 显示「单据未记录物料编号/名称」；当前主数据只作带版本的补充，不回填成历史事实 |
| 批次与批量 | 单据 `lot_no / lot_qty` | 可空；批号相同不等于同一异常 | 「批次未记录」「批量未记录」，不按供应商或创建时间猜测 |
| 抽样量、方案与判定数 | 单据 `sample_qty`、AQL/水平/字码、Ac/Re、`sampling_standard`；项目 `sample_size / accept_no / reject_no` | 字段已保存；整单与各项目口径分别展示 | 标明「记录抽样量」或「项目计划样本量」；无实测覆盖证据不称已全部抽检；标准缺失不补成某一标准 |
| 不合格现象与数量 | 单据 `defect_description / defect_qty`；项目 `result / defect_qty / remark` | 员工正式记录，不等于已验证根因；数量口径须可解释 | 默认 `defect_qty=0` 与拒收矛盾时提示核对，不写无缺陷；项目缺陷数不能相加冒充去重后的不合格件数 |
| 规格限与目标值 | 实例项目 `spec_lower / spec_upper / target_value` | 详细检验生成项目时保存的值；可为单侧限 | 「本次项目未记录规格限」，不拿当前模板或物料规格替代当时规格 |
| 实测值／定性结果 | `IqcItemMeasurement` 的序号、`measured_value / attribute_result / remark`，归属项目 | 实际保存且可核对；序号不是独立样件标识；快速检验可无项目，定性检验可无数值 | 分别显示「仅有定性判定」「未保存逐样本记录」「尚未查完」；不生成虚拟实测值 |
| 单位、检验方法 | 实例项目名/备注中的明确记录；模板另有 `unit / inspection_method` | 实例未单独快照这两个字段；当前模板只能作为当前参考 | 数值显示「单位未在本次记录中明确」；方法未知。物料 `unit` 不推定为尺寸测量单位 |
| 复检与当前差异 | `re_inspection / parent_inspection_id` 及关联检验单正式记录 | 核查父子链与各自范围、版本；不能只看本单布尔值 | 「本次已核范围内未见复检记录」或「复检信息未核全」；不写未经证明的未复检 |
| 已有调查及现实处置 | §2.3 精确关系；SCAR/CAPA 所属模块的可见摘要与正式执行证据 | 来源模块授权；无关联不代表无人工调查；拒收不代表处置完成 | 「已核对当前可见关联范围，未取得已有调查记录」；处置无证据写「尚无可核实的执行记录」 |

事实只陈述记录能支持的范围。只有判定和文字的快速检验仍能生成建议卡。记录互相矛盾时并列原值并列入缺口，Agent 不替检验员修正。数值比较可标为「按已存规格核对」，附测量与规格引用，不能改写正式项目或整单结论。缺少独立样件对应关系或计数口径时，测量条数、超限条数不能换算为不合格件数或比例；有可靠依据的样本缺陷比例也只说明这批样本。整批拒收不表示整批每件都不合格。

## 4. 任务入口、身份与版本

### 4.1 入口与员工所见

在 `/iqc/inspections/:id` 接入统一侧栏，显示检验单号、当前判定、所用模型部署及「准备调查」。服务端返回准入状态，页面据此显示入口及原因。

| 当前单据 | 入口行为 |
|---|---|
| `judged / closed` 且 `rejected` | 可发起。卡片同时显示原拒收及当前处理状态，关闭单可用于复盘 |
| `judged / closed` 且 `concession` | 可发起。卡片同时显示有正式依据的原异常、当前「已让步接收」及处理状态 |
| `pending / inspecting` 或结论 `pending` | 不可发起，显示「请先完成检验判定」 |
| `accepted` | 不提供本片新任务入口；仍有权的员工可看本单历史建议。若原拒收单的复检已接收，可从原单准备历史异常调查，必须呈现复检差异 |
| 字段组合非法或正式判定不可核实 | 显示「检验记录需先核对」，不调用模型 |

发起人须同时具备 IQC VIEW、当前检验单读取权和该 Agent 专项授权，并符合任务准入及安装/任务权限交集。同事审阅需具备 IQC VIEW、当前检验单读取权及建议全部来源的当前读取权。复盘只生成建议，检验单保持关闭或原处理状态，判定及处置结果保持原值。

共享卡片的输入仅限受权正式投影和服务端定义的结构化操作。发起人使用「准备调查」「重新准备」等固定操作和既有运行控制。本 profile 不提供自由文本输入或附件入口，服务端也拒绝从通用消息入口追加此类内容。初始生成、重试、恢复和重新准备均按白名单组装上下文，排除私聊、其他任务历史及其派生摘要。此边界适用于整份共享结果，包括建议、理由、活动摘要和可复制的 D2。复制沿用当前结果授权及清除旧内容规则。

### 4.2 服务端固定业务锚

新任务类型为 `iqc_investigation_advice.v1`，锚为 `iqc_inspection`。绑定由服务端生成：租户 ID 与 generation、发起/执行员工、安装和插件版本、检验单 ID、工厂、适用产品线、检验版本、上下文投影版本、获准能力/补查范围、不可变模型部署与接收方。客户端只提交对象引用、所见版本、请求键和获准部署选择；模型不能提交身份、工厂或产品线来扩大范围。

- 工厂从正式单据确定，使用 `RequestScope` 与 `core/factory_scope.py` 校验；同名批次或跨租户同 UUID 不形成关联。
- 非空产品线核验员工、安装、任务范围及该线所属工厂。补查限定同租户、同工厂及任务明确允许的产品线，本片不开放跨工厂检索。
- 单据产品线为空时保留为空，不用当前页面选择补写。只有当前具有该工厂全产品线读取范围且被明确授权「无产品线 IQC」的身份可启动；补查限本单及可核验的直接关系，停用按产品线历史搜索。其他员工看到「当前范围不足以准备调查」。
- 检验单关联供应商、物料、复检单若范围不一致，模块拒绝该来源交付，不把错误关系当通行证。任务不要求 `report_id`，也不创建空 8D。

### 4.3 IQC 的可信版本

现有 IQC 没有正式版本号或完整历史快照。由 IQC 为可见检验事实维护单调 `inspection_revision`，覆盖允许进入事实投影的抬头、项目、实测、判定、让步及关闭，内容改回原值也会推进修订。每张单另绑定不可复用的身份代际。复检家族版本绑定正式父子关系集合以及成员身份代际和检验事实修订。

- **检验事实版本**绑定本单身份代际、事实修订、复检家族版本和正式事实投影摘要，用于创建预览、运行及历史核验。此绑定及其游标、幂等输入和可见状态基于事实投影，排除整行 `updated_at`、`linked_scar_id`、`linked_capa_id`、全局关联修订以及由调查关联变化衍生的值。只写调查关联的事务不会推动检验事实修订或家族版本。同时更正正式检验事实时，按事实变更处理。
- **调查关系版本**由所属模块按当前获准查询范围内的可见集合生成。直接指针和反向关联都先经过授权过滤，再参与比较。回执绑定任务/run、查询范围、完整性和可见集合版本，获准空集也继承该范围的权限。已使用的范围撤权按来源撤权处理。运行重验本次受权调查依据。审阅通过完整来源授权后，以同一可比较范围判断时效，并按当前读者可见性显示关联变化。新增或改动仅对其他人可见的关系，不改变该员工可观察到的版本、运行结果或卡片状态。仅凭全局计数、整行时间戳或未过滤的关联指针不能判为过期。

历史存量从接入时的当前正式记录建立新版本基线，不补造过去的修订。版本基线在接入时准备，后续由正式业务维护；生成和审阅仅读版本，不推动业务修订。模块封存本次获准投影，平台回执引用其不可变证据版本，支持生成时材料回看；这是证据快照，不是第二套可编辑检验记录。无法认证旧快照、对象身份或历史读取权时，保留安全状态，隐藏正文。

启动、每次读取/入模和最终保存重核完整版本；保存与最后复核使用模块版本/权限围栏，锁等待后再验，并与结果、全部来源关系和终态原子提交。IQC 修订、家族与关联版本的维护属于 IQC/关联模块，平台只比较模块签发的绑定。权限与版本同时失效时先按权限处理。

## 5. 所属模块接口与受控补查

以下是拟新增合同，不是现有 API。员工侧提供 `GET /api/iqc/inspections/{id}/investigation-context`、`POST /api/iqc/inspections/{id}/investigations`，以及该锚下的任务/结果列表、详情和证据入口。创建请求携带 `expected_version`、幂等键及 `model_deployment_id`；范围与当前版本冲突时返回刷新提示，不悄悄绑定另一版。运行控制复用既有任务合同并按 IQC 锚授权。

首次上下文包含：单据 ID/编号和版本、工厂/适用产品线、模式/状态/正式判定、单据内物料与供应商引用、批号/批量、日期/判定人时间、记录抽样量及已存方案、缺陷数/描述、各项目摘要及明细记录数量、单据内父单的经授权摘要、缺失/冲突标记。只给可交付字段；不透传未授权关联 ID。项目和测量过多时返回有界摘要、实际覆盖范围、续查句柄与截断标记，首次包不伪装完整。员工预览不等于已向插件或模型释放，实际交付另签回执。

| 只读能力及归属 | 输入与返回 | 使用范围及降级 |
|---|---|---|
| IQC · `iqc.inspection.context.v1` | 已绑定检验句柄；返回上述首次包及正式来源引用 | 必需；固定本单版本，授权或版本不符停止运行 |
| IQC · `iqc.inspection.items.v1` | 当前检验/已签项目句柄、有界游标；返回项目规格、判定、逐样本数值/属性与记录备注 | 明细按需读取；游标绑定 run、版本和筛选，返回已读/总量与是否完整 |
| IQC · `iqc.inspection.reinspection_chain.v1` | 绑定本单；返回经核验的父子/同源复检记录及各自结论、日期、版本和可续查句柄 | 允许沿正式父子关系查询；新单结果与原单分别呈现，禁止按批号自行拼成复检 |

| IQC／供应商 · 当前主数据摘要 | 已授权关联句柄；返回物料/供应商显示信息及版本 | 可选；按检验单绑定的引用读取最小字段，由 IQC/供应商模块分别核验对象与权限。标注为查询时的主数据。任一摘要不可用时沿用本单已记录的字段与缺口，卡片仍可生成 |

每个模块的页面与 Agent 适配器共用其公开读取服务，Agent 无数据库、SQL、任意 HTTP、知识库写入或跨模块通用搜索能力。多轮先取摘要、再查必要项目/复检/关联调查，顺序由插件决定。服务端继承现有轮次、时间和字节预算，并为新增分页设硬上限；超限显式返回已查范围和截断，不能凭一页空结果宣称排除全部历史。最终补查预算在接口冻结时明确，本规格不增大现有模型预算。

结果区分：当前获准查询完整结束且零结果、尚未查全、来源暂不可用、版本冲突、通用不可访问。对可选来源的权限缺失，在读取业务正文前裁掉该能力，交付与有无隐藏对象无关的范围说明；不返回隐藏对象存在性、数量或 ID。若某来源已经释放给本 run 后被撤权，则整次运行按 §7 停止，不能删除其引用后继续保存。服务端累计全部实际释放来源和继承来源，插件省略引用也不会减掉权限约束。

模型部署和外发沿用[既有模型出口政策][model-egress]。第一片候选实际限制为 `local` 且回环接收方；本片推荐沿用同一受控试点条件，不能把它描述成云端现成可用。未来使用云端仍须实际部署和全部 IQC/补查来源具有对应外发批准与单独启用；本片不新增云端选择或许可。LOCAL 同样需要全部输入可交付，失败不切换其他接收方。获准 Responses 的 `store=false` 等协议规则继续沿用。

## 6. 调查建议卡合同与完整示例

### 6.1 卡片结构和完成条件

| 部分 | 内容与校验 |
|---|---|
| 抬头 | 检验单、生成时间、输入版本、模型部署、已核范围、当前/过期状态；由服务端绑定 |
| 已确认 | 正式记录中的事实、记录者/时间及字段级证据引用。正式判定、数值核对与现实执行事实分别标注 |
| 还缺什么 | 具体缺口、为何影响判断、建议由谁补充；区分未记录、未查全、不适用和来源不可用 |
| 下一步建议 | 建议的核对/取证/调查动作、理由和所依据证据；状态为「建议、尚未执行」。原因假设只能列待验证，不进入正式根因 |
| 已有调查 | 已授权的精确关联调查、状态与入口；若有多个则全部列出并提示员工核对，优先建议补充已有调查 |
| D2 草稿 | 就绪时展示可复制文本、限定范围和证据；未就绪则说明阻碍，保留事实摘要 |
| 证据 | 指向本次实际返回的检验单/项目/测量/复检或关联调查版本；历史证据不跳到当前同名记录 |

至少完成本单正式事实读取和复检关系检查，或明确列出无法核全的范围。可选调查查不到/不可用不阻断一张明确有局限的卡片，但不得给出「无已有调查」的绝对结论。

调查类下一步采用结构化动作。服务端根据本单及获准复检家族的精确关联查询回执校验和呈现动作。

- 推荐新建 SCAR/8D 前，当前 run 必须完成 §2.3 的精确关联查重，持有服务端签发且保存前仍有效的完整回执，并且在该授权范围内未发现已有调查。结果只能表述已核范围。
- 有可见的既有调查时，展示已授权入口并建议核对或补充。没有回执、授权范围不足以完成该查询、结果截断、失败或关系有歧义时，下一步显示「先核对已有调查」。事实卡和满足自身条件的 D2 仍可交付。
- 服务端拒绝原样发布缺回执或与回执冲突的新发建议，允许重提为安全动作。调查类动作及其理由由服务端根据动作代码、回执和已签发证据呈现。D2 只接收问题描述字段，其他区块按各自语义校验。提交把新发建议夹带到其他区块时，服务端同样拒绝发布。

平台校验必要区块、正式判定与绑定一致、引用实际签发且字段/版本匹配、完整依赖和 D2 就绪条件；合格后原子保存一个不可变结果。结构通过不代表模型技术判断已被批准。

D2 的最小依据是可定位的物料/对象与批次、发生或发现的明确时间、具体可观察现象、正式判定和明确的观察范围。可以是定性现象，不强制有规格限或数值；样本量未记录时直接写「抽样量未记录」，不编造数量或比例。只有「拒收」而无具体现象、缺批次/对象、缺可解释时间、相互矛盾且影响问题描述，或复检范围未核清时不提供就绪 D2。检验日期与判定时间有别，只知后者可以写「于某时判定」，不能写成缺陷发生时间。D2 不填写未经验证的原因、责任归属和已完成措施。

## 7. 权限、变更与重复时员工最终看到什么

来源继承及历史可见性沿用第一片 §4、§7。IQC、SCAR、CAPA 各自校验当前/历史对象和全部继承来源；不因员工能读检验单就允许读补查材料。先鉴权再显示时效，不按权限残缺拆出部分旧建议。

| 情况 | 运行与保存行为 | 员工最终所见 |
|---|---|---|
| 发起人跨租户、异工厂、无适用产品线或无 IQC 权 | 启动/读取拒绝，无业务正文或模型调用 | 入口不可用或通用「当前不可访问」，不泄露对象存在性 |
| 发起前缺 SCAR/CAPA 等可选模块权限 | 不读取其正文、不签该来源回执；允许仅基于获准检验记录生成 | 固定说明「关联调查仅核对当前可见范围」；有无隐藏调查均使用相同说明，不给隐藏计数、编号或特定提示 |
| 运行中撤 IQC、已用补查来源、安装或接收方权 | 下一围栏拒绝；尽力取消在途模型请求，丢弃回包；无成功结果 | 原发起人仅见可授权的通用停止状态；不能删去受限证据后继续提交旧分析 |
| 成功后撤审阅者任一完整来源权 | 不删除历史结果；该读者列表/详情/活动/证据均不交付整份内容，客户端清除旧内容 | 通用不可用，无摘要、D2、来源编号和隐藏结果计数；其他仍有完整权的员工独立核验后可读 |
| 检验结果、描述、数量、实测值或规格更正，含改回原值 | IQC 修订变化，在途停止；不能拼接新旧记录 | 旧卡有权且历史可认证时标「已过期：检验依据已变化」，只回看生成时证据；显示「按当前记录重新准备」 |
| 新建复检单，尚未判定 | 家族版本变化使在途绑定失效 | 旧卡标过期；重新准备时并列「原检拒收／复检待判定」，不得称复检通过，D2 暂不就绪 |
| 复检由拒收改为接收，或原单让步接收 | 家族/本单修订变化；旧任务不复活 | 新卡显示各单日期、结果及「结论已发生变化」，保留原检事实；不再基于旧拒收直接建议新发 8D、隔离或通知供应商，由员工判断是否仍需调查 |
| 已授权范围新增正式 SCAR/8D 关联，或可见调查状态变化 | 重核该范围关系版本，在途停止或以新任务读取；旧卡不能继续显示为当前 | 重新准备后优先显示已授权调查入口；打开旧卡时显示过期并附当前可见关联提示，不改写旧卡正文。比对和显示范围按 §4.3。仅他人可见的关联变化不会触发本人的过期或停止 |
| 同一员工双击、网络丢响应、重复提交 | 同租户、员工、键及规范参数返回同任务/结果；同键改单据/版本/部署为冲突，返回前重鉴权 | 看见一次任务与一次结果；无重复 SCAR/8D。新键也不自动复用他人的私有任务 |
| 显式「重新准备」、暂停/取消后的旧包 | 新键新任务、当前版本重读，关联可见前版；旧 run/epoch 不可发布 | 历史卡不覆盖，新卡有自己的版本。暂停/取消/失败只影响 Agent 任务，业务单据状态不回滚 |
| 旧证据无法认证、源对象删除/重绑 | 历史授权/版本校验不通过，不以现 ID 或标签重定位 | 隐藏正文并提示「历史建议当前不可用」，不展示无法核实的旧 D2 |

明确发起与幂等重试的区别。相同异常允许员工在材料变化后重新准备；已有正式调查不阻止准备材料，但影响建议方向。审阅当次返回前复查关联版本与完整权限，来源链接再次授权，避免从已过期卡跳到另一版事实。

**共享详情的当前操作提示。** 服务端先核验读者可读取原结果及全部来源，按 §4.3 核验原始依据的时效。原卡正文、生成时的查重范围及回执按原样保留，并明确标为生成时的判断。若原卡建议考虑新建调查，打开详情时服务端还应以当前读者的身份，在本单及获准复检家族内重新做精确关联查询。

- 查到可见关联 → 当前提示引导读者查看或补充已有调查，并提供当次鉴权的入口。原建议仅作为生成时的记录展示。
- 获准范围内完整空集 → 原卡仍有效时，可继续显示考虑新建的提示，并注明已核范围。
- 无法完成查询、查询有歧义，或原卡已过期且无可见调查 → 当前提示为「先核对已有调查」。

当前提示只随该读者的响应返回，不写回共享结果、回执或公共活动。不同读者的提示不共用缓存，界面切换身份时清除旧提示。读者看不到的关联不触发过期提示，也不改变其当前操作提示。

## 10. 精简验收场景

本轮只检查规格与链接。以下是将来实施的验收合同；第一片的通用租约、部署/出口、回执原子性及旧 run 围栏用例直接复用，新增 IQC 场景使用独立测试库。真实模型建议质量与确定性协议验证分别记录。

| 场景 | 输入 | 员工操作 | 可观察结果 |
|---|---|---|---|
| IQC-正常异常 | §6.2 详细拒收单，无 8D；全部来源可读 | 从检验单准备调查，Agent 读摘要后补查实测和关联 | 得完整三段卡及 D2；引用含项目、50 条实测和关系版本；区分 2 条超限记录、单据缺陷数 2 与未知独立不合格件数，不称整批全不合格；无预建 8D |
| IQC-定性与缺失 | 一张有批次/时间/外观黑点的定性拒收单，抽样量未知；另一张仅 rejected 无现象/批次 | 分别准备并审阅 | 前者 D2 明确定性、抽样量未知，无虚构尺寸/比例；后者有缺口和补查建议，无就绪 D2。快速无项目、默认缺陷数 0 矛盾也有明确提示 |
| IQC-已有调查 | `linked_capa_id` 为空，但来源 SCAR 指向已有 8D；另造多个来源 SCAR 或不一致关系 | 准备调查并跟随已有入口 | 找到精确关联、去重并显示状态/关系依据，建议补充已有调查；多条或矛盾提示员工核对，不自动创建/换绑 |
| IQC-私聊隔离 | 发起人私聊中有仅其可见的合成供应商说明，同事有本卡全部正式来源的读取权 | 尝试通过追加接口给 IQC 任务传同一文本，随后生成和重新准备。同事打开详情并复制 D2 | 追加被拒。模型输入、结果、活动摘要和剪贴板均未携带私聊或其摘要。同事可正常读到正式来源生成的卡 |
| IQC-跳过查重 | 本单已有可见关联 8D，插件跳过查询直接提交新建建议。另测截断、失败和获准完整空集 | 发起任务并审阅提交结果 | 原新建建议不发布。补查发现已有 8D 后可发布补充建议。未查全时可发布「先核对已有调查」和符合条件的 D2。完整空集才通过新建建议的查重门槛 |
| IQC-隐藏关联变化 | 同一单据由甲乙各生成一份建议并启动新运行。两人的授权查询范围不同，之后仅改关联指针并新增一条只对甲可见的正式关联 | 甲乙刷新旧卡并观察运行 | 甲的旧依据失效，重新准备时可见已有调查。乙的事实/家族版本、旧卡时效和在途结果与未新增该关联的对照一致，列表、活动及详情无差异提示 |
| IQC-同卡共享审阅 | 乙在获准范围内查重为空并生成可考虑新建调查的卡。甲可读该卡及全部原始来源，且可见乙无权读的已关联 8D | 乙生成后，甲打开乙卡，随后乙再次打开同一个结果 ID | 两人看到相同的生成时卡片和依据。甲的当前提示引导查看或补充已有 8D，链接经鉴权。乙仍只得到自身范围内的提示，无该关联或变化提示。原卡、回执及活动未被甲的读取改写 |
| IQC-可选历史与主数据 | 同供应商同料号记录分布在窗口两侧，另有不同物料、异厂、异产线及无权记录。当前物料与供应商摘要有各自版本 | 准备调查并触发两个可选查询，另测任一来源无权、缺失或查询失败 | 历史仅返回任务窗口内获准匹配记录。当前摘要标为查询时资料，实际使用的版本进入证据。不可用时仍可依正式单据生成，卡片区分缺失、无权或暂不可核的范围，不透露隐藏记录 |
| IQC-范围与可选权 | 跨租户同 UUID、异工厂、异产品线；另有合法 IQC 但无 CAPA/SCAR 权；无产品线单分别用受限/全工厂身份 | 发起、篡改明细句柄或打开结果 | 越界无正文/模型释放；可选模块缺权仍可准备 IQC 卡，不泄露隐藏调查；无产品线按 §4.2 限定，不借页面选择扩权 |
| IQC-来源撤权 | 先合法读取补查来源，保存前撤发起人该来源权；另在保存后撤审阅者来源权 | 让旧回包抵达；同事刷新列表/活动/直达与证据 | 前者无成功结果；后者整份不可见、客户端旧正文清空，无摘要和隐藏计数。其他完整授权同事可继续审阅 |
| IQC-复检变化 | 原拒收单生成卡，随后新增 R1；R1 由待检到接收，另测原单让步 | 查看旧卡，再重新准备 | 新增复检即使原单 `updated_at` 不变也使旧卡过期；新卡并列原检/复检，待判不出就绪 D2，接收后不把旧拒收当当前结论，不自动撤销或建立调查 |
| IQC-更正与历史 | 更改单项实测/描述/规格后改回原值；新增 SCAR 关联；旧证据删除或同 ID 重绑 | 在途生成及打开历史卡 | 修订/关系版本识别变化，在途拒绝混版；可认证历史标过期，链接指旧版；不可认证则隐藏，不按新对象重定位 |
| IQC-重复与晚到 | 同键双击、丢响应、同键改版本/部署、显式新键重评、暂停后旧结果 | 重试、重新准备或取消 | 唯一任务/结果、参数冲突、新版关联前版、旧 run 不发布；不产生任何重复 SCAR/8D |
| IQC-多轮不完整 | 测量记录分页截断、关联服务失败、仅关键词历史查询空集、规格与判定矛盾 | 让 Agent 继续补查或提交 | 可见已查范围及具体缺口；无全量排除或自动纠正结论；复检未核清则 D2 不就绪；权限拒绝不伪装业务空集 |
| IQC-业务状态不变 | 记录本单/复检、SCAR/CAPA、库存/隔离放行及相关通知/outbox 的基线，含已让步或已关闭的异常单 | 发起、生成、审阅、复制草稿，并尝试调用写工具 | 卡片并列有正式依据的原异常和当前状态。检验单未重开，正式字段、判定、关联、业务版本、处置执行与通知均不变；无新 8D/SCAR、供应商通知或业务 outbox。仅任务/run、建议、证据快照/回执及访问审计允许增长；写工具拒绝 |

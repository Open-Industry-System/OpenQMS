# OpenQMS 公开展示首页设计

**日期：** 2026-09-09  
**状态：** 已确认  
**范围：** 前端页面代码与本地验证；不包含公网服务器、域名和正式部署

## 1. 背景与目标

当前 OpenQMS 的根路径位于认证区域，未登录访客首先看到登录页，无法在登录前了解项目。作为开源项目，OpenQMS 需要一个无需认证即可访问的公开首页，用于说明项目定位、AI 的实际作用、核心质量能力、技术架构和开源入口。

本次目标：

1. 将 `/` 建成公开、中英双语的项目展示首页。
2. 保持 `/login`、`/dashboard` 和现有业务模块的认证行为不变。
3. 采用“知识图谱科技风”，突出 AI 驱动的质量知识连接与闭环。
4. 提供 GitHub、文档、Viewer 只读演示和业务系统入口。
5. 完成响应式、可访问性、单元测试和前端构建验证。

## 2. 非目标

本次不包含：

- 公网服务器、域名、HTTPS、CDN 或部署流水线。
- 新的后端接口或数据库表。
- 可编辑的 Engineer / Manager 公开演示账号。
- 演示数据自动重置、防滥用和多人共享沙箱。
- 首页内容管理后台、访问统计或 SEO 服务端渲染。
- 对现有业务页面进行视觉重构。

后续目标是多角色演示，但在具备独立演示环境、数据自动重置和限流机制前，本轮只开放 Viewer 只读体验。

## 3. 路由与架构

采用单一 React/Vite 前端中的“公开官网 + 受保护业务系统”结构：

```text
/                    公开项目展示首页
/login               登录页
/dashboard           登录后仪表盘
/fmea、/capa ...     现有受保护业务页面
```

设计约束：

- `/` 永远公开，不包裹 `ProtectedRoute`。
- 已登录用户也可以访问 `/`，不会被自动重定向到仪表盘。
- `/dashboard` 及现有业务路由继续使用当前认证和模块权限门禁。
- `PublicHomePage` 按现有路由模式懒加载。
- 首页使用静态翻译内容，不请求后端；后端暂不可用时首页仍可显示。
- 不新增状态管理或 UI/动画依赖。

## 4. 品牌与视觉方向

采用已确认的“知识图谱科技风”：

- 深蓝黑背景，青绿色作为主要强调色。
- 使用细网格、节点、连线和轻量光晕表达质量知识网络。
- 用较强的标题排版建立开源技术产品形象。
- 保持工业软件所需的可信、克制和可读性，不使用炫技式 3D 或大体积视频。
- 页面样式限定在公开首页作用域内，不覆盖现有 Ant Design 管理界面。
- 所有装饰动画遵守 `prefers-reduced-motion`。

## 5. 信息架构

首页按以下顺序组织：

### 5.1 顶部导航

- OpenQMS 品牌标识
- AI 质量智能
- 核心能力
- 技术架构
- 开源社区
- 中文 / English 切换
- 进入系统

锚点导航使用原生页面内跳转或平滑滚动，不引入滚动监听库。

### 5.2 Hero 首屏

核心中文标题：

> 让质量数据，转化为可执行智能。

说明 OpenQMS 是面向制造业的一体化开源质量管理平台，并将 AI 嵌入 FMEA、8D、过程分析和知识复用流程。

主行动入口：

- 在线体验（Viewer 只读演示已启用时显示）
- 进入系统
- GitHub

右侧使用 CSS/SVG 构成质量知识网络，节点代表 FMEA、SPC、8D、供应商质量和知识图谱。

### 5.3 项目信任指标

以精简指标建立可信度：

- 20+ 质量模块
- AIAG-VDA 七步法
- IATF 16949 核心流程覆盖
- MIT License

文案避免宣称未经认证的“合规认证”；仅描述流程覆盖与设计目标。

### 5.4 AI 核心章节

AI 是首页第一个重点内容章节，而非普通功能卡之一。

核心定位：

> AI 是质量工程师的副驾驶，不是黑盒决策者。

用四步机制解释 AI 在系统中的作用：

1. **连接质量上下文**：FMEA、CAPA、SPC、IQC、MES、供应商质量和经验库。
2. **多路径知识召回**：知识图谱、语义搜索、规则引擎和历史案例。
3. **融合与生成建议**：候选去重、排序、上下文增强及 LLM 结构化输出。
4. **人工确认并留痕**：权限门禁、人工审批、来源标签、采纳记录和审计日志。

展示四类已经实现的 AI 使用场景：

- **FMEA 智能推荐**：辅助补全功能、失效、原因、控制措施和优化行动。
- **8D 根因与措施推荐**：通过 12 阶段编排整合质量数据并输出可解释候选。
- **质量知识问答**：通过 RAG 混合检索，在用户权限和产品线范围内返回结果。
- **趋势解读与内容草拟**：辅助解释质量趋势，并生成 8D 步骤和管理评审内容草稿。

可信 AI 标签：

- 来源可见
- 采纳可审计
- 工厂数据隔离
- 权限范围约束
- 输入 / 输出 Guardrails
- 多 Provider 配置

公开文案不得暗示 AI 会绕过业务状态机、自动批准质量决策或替代质量工程师。

### 5.5 完整质量能力

AI 章节之后用六组能力说明底层业务系统的完整性：

1. 风险与策划：FMEA、APQP、PPAP、控制计划。
2. 过程与测量：SPC、MSA、IQC、特殊特性。
3. 问题与改进：8D/CAPA、SCAR、客诉、RMA。
4. 供应链质量：供应商绩效、风险预警、客户质量。
5. 治理与合规：审计、管理评审、RBAC、多工厂。
6. 开放集成：ERP、MES、PLM 和 API。

## 6. Viewer 公开演示

公开演示必须显式配置，不能在所有部署中默认暴露种子账号。

建议使用 Vite 环境变量控制：

```text
VITE_PUBLIC_DEMO_ENABLED=false
VITE_PUBLIC_DEMO_USERNAME=
VITE_PUBLIC_DEMO_PASSWORD=
```

行为：

- 未启用时，首页不显示“在线体验”，只显示“进入系统”。
- 启用时，“在线体验”进入 `/login?demo=viewer`。
- 登录页在该模式下显示 Viewer 只读体验提示和配置提供的凭据，并提供一键填充；一键填充不得自动提交登录表单。
- 页面明确标识“只读演示，无法修改数据”。
- 默认配置为关闭，避免私有部署意外公开默认账号。
- 演示凭据出现在前端包中是公开演示的预期行为，因此只能使用专用 Viewer 账号，不能复用管理员或真实环境账号。

多角色演示为后续独立范围，需要至少补充：独立演示租户、定时重置、写操作限流、危险操作禁用和会话隔离。

## 7. 组件与文件边界

保持最少文件和清晰职责：

- `frontend/src/pages/public/PublicHomePage.tsx`
  - 页面语义结构、锚点、CTA 和静态内容渲染。
- `frontend/src/pages/public/PublicHomePage.css`
  - 页面视觉、响应式、动效和 reduced-motion 规则。
- 中英文 `home` 翻译资源
  - 所有用户可见首页文案。
- `frontend/src/App.tsx`
  - 将 `/` 改为公开页面，保留其余受保护路由。
- `frontend/src/pages/login/LoginPage.tsx`
  - 仅增加受环境变量控制的 Viewer 演示提示与填充入口。
- 对应测试文件
  - 路由公开性、CTA、翻译和演示配置行为。

页面内部不会为了单次使用的静态区块拆出大量组件；只有出现独立交互或测试边界时才抽取。

## 8. 响应式与可访问性

- 使用语义化 `header`、`nav`、`main`、`section`、`footer`。
- 保持可见焦点态和键盘可操作性。
- 装饰节点和连线标记为非可访问内容，不制造无意义朗读。
- 桌面端显示全部锚点导航；窄屏隐藏锚点列表，只保留语言切换和“进入系统”按钮，不新增汉堡菜单或菜单状态。
- 能力卡从桌面多列降为平板双列、手机单列。
- 页面不得产生横向滚动。
- 文本和交互颜色满足 WCAG AA 对比度目标。
- 动画关闭后仍保留完整视觉层级和信息。

## 9. 数据流与异常处理

首页没有运行时 API 数据流：

```text
路由进入 → 加载页面 chunk → 读取 i18n 与 Vite demo 配置 → 渲染静态内容
```

因此不增加加载骨架、请求重试或错误边界。外部链接使用 `target="_blank"` 和 `rel="noreferrer noopener"`。演示环境变量缺失或不完整时按“演示关闭”处理，不渲染半配置状态。

## 10. 测试与验收

1. 未登录访问 `/` 可以看到 Hero，不跳转 `/login`。

4. 中文 / English 切换后首页关键文案变化。

10. reduced-motion 条件下不执行非必要动画。

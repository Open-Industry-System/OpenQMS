关联：[运行时产品边界](2026-09-26-qms-agent-task-plugin-runtime-design.md)、[租户基础](2026-09-27-independent-tenant-migration-design.md)、[R1 计划](../plans/2026-09-26-agent-task-plugin-runtime-foundation.md)。

## 1. 本轮交付与门槛

交付持久任务、固定插件版本的运行、按序消息、安装凭据和独立进程的多轮元数据查询。独立示例插件以确定性逻辑进行至少两次 HTTP 查询后返回结构化分析结果，不依赖模型凭据；该验证证明传输与授权，不声称具备自由文本根因分析。任务/消息/结果为平台元数据写入，不修改 CAPA 或其他质量对象。

租户基础的空租户、结构对照、排空重建、代际失效、恢复和完整检查通过，且 R1 Task 1 复审清零后，才能执行 R1 Task 2。R1 的公共增量和独立租户增量均验收后才能接 R2。CAPA 默认规范声明仍为 DENY，运行时开关默认关闭；完整链路测试只对一次性库中的合成数据使用服务端测试声明，同时回归默认 DENY 的拒绝路径。本轮不启用生产能力、不合并或推送工作树。

## 2. 任务、运行与凭据

- 任务固定执行用户、目标 CAPA、发起者、插件安装及请求幂等键；每次创建、列表、详情和消息追加重新检查当前用户、CAPA VIEW、当前可访问工厂集合及产品线，不用页面选择的工厂缩小原已授权范围。
- 运行固定 task ID、安装 ID、插件版本；租约 epoch、安装 credential epoch、租户 generation 分别使旧运行、旧安装密钥和重建前凭据失效。一个任务最多有一个非终止运行。
- 安装长期 secret 只在注册或轮换响应中返回一次，数据库只存 hash；用户、平台和 refresh JWT 不能充当运行凭据。运行 JWT 使用专门的 issuer/audience/type，最多按配置初值五分钟生效。
- JWT 中的租户 ID/generation、run ID、安装 ID、版本与 epoch 均经签名验证后，再从当前平台登记和租户内实际行核对。schema 从当前登记选择，不由插件 payload、未验签 JWT 或保存的旧任务 schema 决定；停用租户或错误 generation 在业务查询前拒绝。
- R1 提供凭据服务而不提供业务交付。R2 的服务端 dispatch/claim 仅在任务可运行且插件长期授权覆盖任务时签发短期凭据；安装 secret 不能直接读取 CAPA。续期/重连同样重验当前状态，不延长已失效授权。

## 3. HTTP v1 和消息接入

人类端保持 R1 的创建、列表、详情、追加消息接口。插件端采用独立 `/api/agent/runtime/` 路由和运行身份依赖：

| 操作 | 请求与结果 | 当前状态检查 |
|---|---|---|
| 领取运行 | POST claim，安装 ID、安装密钥及幂等键；返回任务/运行 ID、短期 token、租约 epoch 与到期时间 | 当前安装密钥、固定版本、任务可运行、执行人及所需能力授权；不返回目标报告 ID |
| 能力发现 | GET capabilities；只返回该运行可使用的规范能力和拒绝/可选降级状态 | 用户、目标、插件、任务 grant、租户 generation、目录声明 |
| 消息领取 | POST messages/claim；按 sequence 返回未接入消息与领取批次 ID | task/run 行锁、租约 epoch；每轮只取固定有界批次 |
| 消息确认 | POST messages/ack；提交批次 ID 与截至 sequence | 只能确认实际领取的连续批次；重复确认幂等；旧 epoch 拒绝 |
| 元数据查询 | GET capa/context，report ID 可省略并由服务端选择任务固定目标；显式 ID 必须为该目标，view 为 report 或 verifications | 当前 CAPA VIEW、工厂/产品线、三层 grant、规范声明及显式交付守卫 |
| 进度与结果 | POST events/results，带每运行唯一 idempotency key | 当前运行状态和 receipt 来源；重试不重复事件或结果 |

插件请求不能传执行用户、工厂范围、schema、授权或任意 SQL。确认消息后更新 accepted_message_seq；消息追加继续由发起者按 task 行锁递增 sequence。重新领取尚未确认批次沿用批次 ID，不把断线视为已经采纳；暂停/取消使运行 epoch 失效并拒绝下一次调用。检查点和业务补偿仍属于后续 R3/R5，不在本轮创建伪恢复功能。

## 4. 元数据投影和交付

复用既有白名单：报告 ID、单据编号、状态、严重度、工厂 ID、产品线、updated_at，以及 D4 验证 ID/结论/是否通过。标题、D1–D8 正文、团队姓名、附件、客户/供应商标识和 AI 推荐均不得进入响应或日志。

报告与验证子记录取自同一已绑定租户的 REPEATABLE READ READ ONLY 快照。快照必须先设置事务隔离和只读属性，再执行租户控制面门禁查询，不能在普通 session 的 after_begin 已查询后才设置隔离级别。独立连接先开启快照，再经现有业务事务门禁验证 active/generation 和共享锁，随后读取业务字段。单租户路径固定 public；多租户缺绑定、缺表或代际变化拒绝且无公共回退。

每次查询都计算完整投影的稳定 digest，两个 view 只是选择展示字段，不能用父报告 updated_at 代替版本。取得快照后、生成 receipt 或返回内容前，重新读取执行人、角色权限、工厂/产品线成员关系、安装、任务、运行及插件/任务 grant，再执行规范 authorize 和显式交付守卫；先前 RuntimeIdentity 保存的范围不能作为最终交付权限。快照中的产品线必须与最终获授权目标一致，不能借报告和 grant 已迁往另一产品线而交付原产品线快照。查询过程中撤权或报告及 grant 同时迁移的真实双事务测试必须拒绝内容且不生成 receipt。独立插件只在服务端确认的可信部署策略下取得允许的投影；插件自报内网、脱敏、无外发或 manifest 不构成证明。测试部署使用审查过的确定性示例和合成数据，实际生产可信部署仍需独立运维验收。

## 5. 事件、来源与结果

R2 增加租户内事件、证据 receipt 与结果记录。receipt 由平台在一次成功投影交付后生成，绑定 task/run、租约 epoch、租户 generation、CAPA ID、projection ID、digest 和来源敏感等级；插件只能引用本运行当前租约的 receipt，不能自造来源或宣称结果已脱敏。结构化结果包含候选说明、支持/反对证据、缺失信息和条件性建议；首版内容来自元数据，保持明确的分析限制。

任务消息和自由文本结果默认 restricted。结果读取同时重查任务目标权限以及每个来源对象的当前权限和敏感等级；失效、缺来源或不可见时不返回正文、摘要或数量。用户读取历史结果不依赖运行仍活跃、租约仍有效或插件仍启用；保留业务数据的租户维护也不使历史结果失效。历史 receipt 记录保存时的 epoch/generation，当前请求仍须通过租户事务门禁及任务、来源访问检查；插件写入则只接受当前运行、租约和 generation 的 receipt。结果不进入统一搜索、知识库、embedding 或正式 8D 字段。只读示例不会调用模型或外部搜索。

## 6. 验收证据

1. 公共空库和空租户均能走公共/独立向前链创建 task/run/message 表，旧静态基线保持不变；最新两条链结构相等。
2. 消息顺序、并发追加、幂等、撤权、他人任务、列表/count 过滤与新会话持久化有真实数据库测试。
3. 用户/平台/refresh token、过期 token、错误租户/generation、旧 lease/credential epoch、插件禁用均在下一次调用拒绝；重建前同 UUID token 不能进入新 schema。
4. 真正独立进程使用 HTTP v1 至少两轮：读取报告元数据 → 按结果再查 D4 验证 → 保存带服务器 receipt 的结果。服务端审计可关联 task/run/user/source，业务表前后内容一致。
5. 过程中切换页面工厂不改变目标，插件试图查询未授权报告或跨租户相同 UUID 被拒；查询时撤权/禁用/暂停后不能继续读取。
6. 默认 DENY 与默认关闭路径通过；白名单测试确认正文、附件和敏感标识未进入插件输入、结果来源元数据或审计。没有真实环境能力激活或模型外发。
7. 聚焦检查、独立测试库完整后端检查、前端类型检查与构建通过；规格和代码质量审查无未解决的重要问题。

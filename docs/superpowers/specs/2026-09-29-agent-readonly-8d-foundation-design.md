# Agent 只读 8D 试点：授权与投影基础设计

日期：2026-09-29
状态：按审查意见修订；单租户内部基础已实施，能力仍为 `DENY` 且无外部交付；多租户路径待逐事务隔离验收。
范围：单租户下的身份绑定、单报告任务授权持久化、CAPA D4 只读投影。多租户启用依赖逐事务隔离改造验收；独立插件传输和侧栏运行属于下一切片。

关联：[模块权限设计](2026-09-26-qms-agent-module-permissions-design.md)、[已实现的权限内核](../plans/2026-09-26-agent-module-permission-kernel.md)。

## 1. 目标与边界

为指定 8D 报告建立可撤销、可过期的只读任务授权，并由 CAPA 模块生成明确字段的投影。授权不能由插件提交的 user、tenant、factory 或 capability 字段决定。现有 `capa.d4.summary.masked.v1` 继续保持 `DENY`，本切片不让旧 Agent 网关或外部插件读取该投影；在外发矩阵、可信部署和插件凭据经过单独验收前，不开放交付。

本切片不修改 8D 业务状态、不生成候选根因、不调用模型、不接统一搜索，也不复用现有 `AgentSession.task_state` 作为授权真源。只读指不修改质量业务对象；创建、撤销任务及记录读取尝试仍属于平台元数据写入。

## 2. 两种落地方式及选择

| 方式 | 优点 | 问题 |
|---|---|---|
| **新增租户内的只读任务与授权表（选择）** | 与旧 Agent 会话隔离；授权有独立状态、过期时间和数据库约束；按报告绑定 | 需要迁移和服务层 |
| 直接扩展 `agent_sessions.task_state` | 表面改动少 | JSONB 授权缺少约束；旧会话和新任务容易互认；撤权及审计难以证明 |

第一版只支持一个 CAPA 报告、一个只读能力。后续跨模块证据读取通过独立能力授权加入，不把 CAPA 授权扩展解释为 FMEA/IQC 授权。

## 3. 身份与租户绑定

- 单租户模式沿用认证身份与 `RequestScope`，业务表固定在 `public`。服务层不接受调用方提供的租户 schema；本切片不新增 HTTP 入口。
- **多租户启用前置条件**：先完成并验收数据库会话的逐事务租户绑定与隔离改造。当前 `get_db()` 仅在会话开始执行 `SET search_path TO tenant, public`，`commit()` 后新事务或重新取得连接不能保证仍绑定原租户，且租户缺表时可能回退到 `public` 业务表。不能把当前实现当作本切片的可信租户边界。
- 前置改造须在每个事务开始、任何业务查询之前，从已认证且 active 的 `request.state.tenant` 绑定 schema；租户业务查询的 `search_path` 不包含 `public` 业务表回退。提交、回滚或连接池重新取连接后，新事务必须重新绑定；租户 schema 缺表时拒绝访问，不查公共表。独立后台会话也须显式绑定，缺少可信租户上下文时拒绝创建或使用任务。
- 前置改造的跨事务、连接复用、缺表及跨租户验收通过前，多租户模式下的 `create_read_task`、`revoke_read_task`、`check_read_task` 和投影构建在业务查询前拒绝调用；单租户模式可实施。不能只靠 `agent_read_tasks.tenant_schema` 字段或一个功能开关声称隔离已成立。
- 建任务时记录发起者 `user_id`、可信租户标识、报告 ID、工厂 ID、产品线代码及到期时间。多租户模式将记录写在当前租户 schema；持久化的租户标识用于后续校验和审计，不作为选择数据库 schema 的输入。
- 每次读取先用当前认证身份和当前数据库连接的租户上下文核对任务绑定，再重新解析现时 CAPA 模块权限、工厂与产品线范围及报告状态。任务创建时的权限快照不替代现时授权。
- 任务 ID、报告 ID 和工厂 ID 只在当前租户 schema 查询；跨租户的相同 UUID、旧 JWT、停用租户、schema 不匹配或无法确定租户一律拒绝，不尝试切换到任务保存的 schema。
- 只有发起者可以使用或撤销这项任务授权。管理员代办、服务身份及多发起者任务另立契约。

## 4. 持久化契约

新增 `agent_read_tasks` 租户内表：`task_id` UUID 主键，`initiator_user_id`、`tenant_schema`、`capa_id`、`factory_id`、`product_line_code`、`capability_id`、`status`、`expires_at`、`created_at`、`revoked_at`。`status` 仅为 `active/revoked`，到期由 `expires_at` 判定，不依赖清理任务。`capability_id` 固定为 `capa.d4.summary.masked.v1`；`capa_id + factory_id` 使用现有 CAPA 复合唯一键作为外键目标，防止跨厂误绑。租户内的用户和工厂也使用外键。

创建任务需要 CAPA VIEW、报告可见及产品线可见；服务端固定 24 小时有效期，不接受调用方自定的权限集合或截止时间。创建、撤销和授权检查写平台审计时只记录 ID、能力、范围和原因码，不复制 CAPA 自由文本。撤销写入立即生效；后续接入传输时须在交付前再次检查任务状态，以覆盖检查后发生撤销的竞态。

现有权限内核的 `Grant` 由数据库授权行在服务端构造；`AccessAttempt` 的身份级别、工厂和产品线来自现时 `RequestScope` 与权限查询。插件长期授权在本切片仍为缺失，故公开 `authorize()` 结果继续拒绝；内部服务测试可使用受控测试授权验证任务行转换和交集，不在生产创建伪插件授权。

## 5. CAPA 脱敏投影

CAPA 模块新建专用投影函数，不复用 `CAPAResponse` 或对它做事后字段删除。v1 投影仅包含：报告 ID、单据编号、状态、严重度、工厂 ID、产品线代码、D4 验证记录的 ID/结论/是否通过，以及仅作展示时间的报告 `updated_at`。标题、D1-D8 自由文本、团队姓名、附件、供应商/客户标识、来源引用和 AI 推荐内容均不进入此投影；因此 v1 是**元数据摘要**，不声称已对自由文本实现可靠脱敏。

投影返回 `projection_id=capa.d4.summary.masked.v1`、`source_capa_id`、`projection_digest` 和 `data_class=internal`，让后续交付检查有规范标签。`projection_digest` 为投影契约版本和**全部实际输出的业务字段**的规范 JSON（固定键名与格式、验证记录按 ID 排序）计算 SHA-256；报告 `updated_at` 也纳入摘要，但单独的 `updated_at` 不能充当版本。新增验证记录或更改结论/是否通过时，即使报告行未更新，摘要也必须变化；同一内容和顺序的重复读取摘要稳定。

报告与验证记录须在同一个已绑定租户的只读 `REPEATABLE READ` 事务中读取，序列化与摘要均取自该事务的同一快照。不得分别提交后拼接数据，也不得先读报告、再从另一个连接读子记录。后续审批或交付若绑定该摘要，执行前须重新读取并比较；若内容变化则旧决定失效。若需要文本摘要，CAPA 模块须另行明确可保留字段、降敏规则和来源继承测试；不能把 v1 的 `masked` 名称当作所有内容均可对外发送的证明。

## 6. 服务与错误路径

`create_read_task`、`revoke_read_task` 和 `check_read_task` 位于平台服务层；CAPA 模块提供内部 `build_masked_d4_projection`。**本切片不新增 HTTP 或插件端点**，以免出现可创建但无法执行的用户任务。任务检查顺序为：可信租户/身份 → 当前任务及到期状态 → 规范能力声明及 CAPA VIEW → 报告存在和当前工厂/产品线范围。检查规范声明只确认身份与授权行的能力 ID 一致，不把仍为 `DENY` 的能力变成可交付。对无权或跨租户报告统一表现为不可见，不泄露报告是否存在；任务过期或撤销返回明确的不可用原因，但不返回业务内容。

CAPA 投影函数只供内部契约测试及后续受控交付适配器调用，不能由外部插件 API、旧 Agent 工具或模型上下文引用。即使任务检查成功，实际交付仍须通过插件授权、任务授权交集和显式外发守卫；目前能力 `DENY`，交付结果始终拒绝。

## 7. 验收

- 全新测试库迁移可升级/降级；表约束拒绝不存在或跨工厂的报告绑定。
- 本租户同报告授权可创建、内部检查、撤销和过期；重复撤销幂等；报告换厂/产品线、用户权限撤销后检查失败。
- 跨租户同 UUID、跨厂、跨产品线、他人任务、请求伪造租户或插件授权均不能读取，响应不泄露对象存在。
- 多租户路径保持关闭，直到逐事务绑定的集成测试覆盖首次查询、`commit()` 后新事务、`rollback()` 后新事务、连接归还与复用、租户 schema 缺表、公共表有同名数据，以及跨租户同 UUID；任一场景不得从 `public` 业务表读取或写入。
- 投影字段白名单由契约测试锁定；CAPA 自由文本、供应商和附件不会进入序列化输出或审计。
- 同一事务快照中的投影与 `projection_digest` 一致；新增 D4 验证记录、改变结论及其派生的 `is_verified` 后摘要变化，未改动投影内容时摘要稳定；并发修改不能产生报告与子记录混合版本。
- `capa.d4.summary.masked.v1` 仍为 `DENY`；旧 Agent 路由行为不变，没有插件或模型能从该服务入口获得数据。
- 聚焦测试和 `make check` 通过；更新架构、能力盘点、权限文档及 `PROGRESS.md`，只提交本切片文件。

# Oracle 自动部署设计

## 目标

PR 创建或更新并通过检查后，在现有 Oracle 主机上提供独立预览；PR 关闭时清理。合入 main 并通过检查后，按生产发布门禁部署。预览地址采用 `pr-<编号>.preview.openqms.smartindustry.world`。

## 已确认的基线

- 2026-11-14 只读检查确认服务器运行 `d8648c15`，生产容器健康；GitHub `main` 为 `2dbb84b1`，不包含生产 Compose、生产包装器和 Oracle 目标数据库身份检查。两者共同祖先后分别有 50 和 266 个独有提交，合并预检存在多处代码和文档冲突；须先完成受验证的集成，不能直接将 main 发布到现有生产库。
- 生产工作树的发布流程包含不可变源码、镜像身份、目标数据库身份、隔离测试库、迁移和 preflight 门禁。不能用根工作区现有开发 Compose 或简化脚本替代。
- 工作区和生产工作树均存在已有未提交改动；集成前须保护这些改动，不直接覆盖线上工作目录。

## 预览环境

- 每个 PR 使用独立项目名、数据库、持久卷、应用密钥与网络；不得连接或复制生产数据和秘密。后台依赖也需独立或禁用，具体依据实际生产配置确定。
- 不可信 PR 代码可能主动读取环境变量、访问网络或攻击同机服务。独立 Compose 项目不是安全沙箱；在信任边界和网络隔离经验证前，不向 fork PR 或未经信任的代码发放部署凭据，也不运行其容器。可信范围由仓库权限确定。
- PR 更新应以提交 SHA 标识版本，防止旧任务覆盖新版本；关闭和部署对同一 PR 串行化，并检查 PR 的最新状态。清理只删除该 PR 专属资源。
- 预览流量通过已有反向代理接入，使用配置的域名和有效 HTTPS。通配符证书所需 DNS 验证或其他证书策略以实际 DNS 服务商及反向代理为准。
- 为预览设置资源和数量上限，防止影响生产服务。预览失败应保留可诊断日志，不改变生产运行状态。

## 生产发布

- 仅在 main 对应提交的必要检查成功后发布；生产发布串行，确保最终运行版本与受检提交一致。
- 延续生产工作树中的 `make deploy-release` 和目标身份、源码与镜像身份、迁移、独立测试库、preflight 及 rollout 门禁。发布前备份与失败恢复遵循实际服务器 runbook；不自动回退数据库迁移。
- 发布凭据、生产配置和数据库凭据不暴露给 PR 代码。GitHub Actions 与服务器连接必须验证主机身份，并采用受限权限。

## 验收与待核实事项

实施前确认服务器实际版本、当前反向代理和目录、数据库与备份、可用资源、部署连接方式，以及 GitHub Actions 的权限和保护规则。配置预览域名后验证 DNS 和 HTTPS。验收须覆盖 PR 创建、更新、关闭、失败和并发，以及 main 发布、失败短路、版本一致性和预览与生产数据隔离。禁止使用生产数据库作为测试库。

已通过 Tailscale 只读确认生产版本和容器状态，GitHub CLI 登录有效。服务器当时报告约 9.5 GiB 可用内存、85 GiB 可用磁盘；实际预览容量仍需测量。GitHub 经典 branch protection 接口对 main 返回 404，尚需检查 rulesets，不应假设已有强制检查。自动部署尚未启用。

# US-E2E-01.5 8D → SCAR 触发与回写 — Design

**日期**: 2026-07-15  
**状态**: 设计定稿（待实现）  
**子故事**: `docs/user-stories/US-E2E-01-capa-8d-closed-loop/US-E2E-01.5-scar-trigger.md`（定稿 v1，2026-07-08）  
**AI_REQUIRED**: false  
**Gap**: `docs/superpowers/specs/2026-07-08-us-e2e-01-gap-analysis.md` §01.5  

## 1. 目标

现场质量工程师在来料不良 8D 的 D3 及之后阶段，可一键发起 SCAR，携带 8D 上下文；SCAR 单号回写 8D；SCAR 状态变更在 8D 侧可读可见并写同步审计。不改造 SCAR 模块自身全流程。

## 2. 已有基建（复用，不重造）

| 资产 | 用途 |
|---|---|
| `SupplierSCAR.capa_ref_id` → `capa_eightd.report_id` | SCAR → 8D 外键已存在 |
| `scar_service._create_scar_without_commit` | 与客诉/RMA/风险告警同路径建 SCAR |
| `create_scar_from_complaint` / `create_scar_from_rma` / IQC `trigger_scar` | 源实体「一键建 SCAR + 回写 ref」模式 |
| `POST /scars/{id}/link-capa` | 既有 SCAR→CAPA 关联（本设计补双向一致） |
| `listSuppliers` + SCAR 详情页 `/scars/{id}` | UI 选供应商 + 跳转 |
| D3 E2E supplier seed | E2E 可复用供应商 |

**缺口**: CAPA 无 `scar_ref_id`；无 8D 侧触发入口；无 8D 侧 SCAR 状态投影；`transition_scar` 不通知 CAPA；`source_type` schema 未含 `capa`。

## 3. 决策摘要

| 决策 | 选择 | 理由 |
|---|---|---|
| 关联基数 | **1:1** | 与客诉/RMA 一致；故事契约 `capa.scar_ref_id` |
| 状态同步 | **读时投影** `linked_scar` + transition 写 `SCAR_STATUS_SYNCED` | 无双写列；满足「创建/关闭可见」 |
| 供应商来源 | **请求体必填 `supplier_id`** | CAPA 无 supplier_id；不猜 |
| 实现路径 | **对齐客诉模式** `POST …/trigger-scar` | 最小增量、模式成熟 |
| 触发窗口 | **D3+ 且非 ARCHIVED**（拒 D1/D2/ARCHIVED） | 覆盖故事 D3/D4，避免后续 D 步卡死 |
| `source_type` | **`capa`**（扩 Pydantic/TS Literal；DB 无 CHECK） | 可区分来源；与 iqc/complaint/rma/manual 并列 |

## 4. 数据模型

### 4.1 迁移

- 表 `capa_eightd` 新增：
  - `scar_ref_id UUID NULL REFERENCES supplier_scars(scar_id) ON DELETE SET NULL`
  - 部分索引 `ix_capa_eightd_scar_ref_id ON capa_eightd (scar_ref_id) WHERE scar_ref_id IS NOT NULL`
- revision 挂在实现时 parent 真 head 之后（合并前再确认，禁止复制 parent 迁移进 feature 分支）
- 不改 `supplier_scars` 表结构（`capa_ref_id` 已在）

### 4.2 不变量

1. **1:1**: `capa.scar_ref_id IS NOT NULL` 时拒绝再次 `trigger-scar`（400，明确文案）
2. **同厂**: `supplier.factory_id == capa.factory_id`，否则 400
3. **权限**: `canEdit('capa')`（与 D 步编辑同级）
4. **状态门**: `capa.status ∉ {D1_TEAM, D2_DESCRIPTION, ARCHIVED}`（注：实际状态字面以 `eightd_state.py` 为准；D2 正式枚举名为 `D2_DESCRIPTION`）
5. **双向一致**（触发路径）:
   - `scar.capa_ref_id = capa.report_id`
   - `scar.source_type = "capa"`
   - `scar.source_id = capa.report_id`
   - `scar.factory_id = capa.factory_id`
   - `scar.product_line_code = capa.product_line_code`
   - `capa.scar_ref_id = scar.scar_id`

### 4.3 描述拼装

- Body `description` 若提供则原样使用
- 否则默认：
  ```
  {document_no} {title}
  {d2_description or d4_root_cause or ""}
  ```
  合理截断（与既有 Text 列容量一致，实现时对齐 `SupplierSCAR.description`）
- 可选 `affected_batches: string[]`：若有，追加到 description 尾部（`受影响批次: a, b, …`），**不另建表/列**

## 5. API / 服务

### 5.1 `POST /api/capa/{report_id}/trigger-scar`

**Request**

```json
{
  "supplier_id": "uuid",
  "description": "optional",
  "requested_action": "optional",
  "due_date": "YYYY-MM-DD | null",
  "affected_batches": ["optional", "lot codes"]
}
```

**行为**

1. 解析 CAPA + `check_factory_access` + `canEdit('capa')`
2. 状态门 / 已关联 / supplier 存在且同厂
3. 同一事务：
   - `scar = await _create_scar_without_commit(...)`  
     `source_type="capa"`, `source_id=report_id`, `capa_ref_id=report_id`,  
     `factory_id=capa.factory_id`, `product_line_code=capa.product_line_code`,  
     `issued_by=user_id`
   - `capa.scar_ref_id = scar.scar_id`
   - `AuditLog(table_name="capa_eightd", record_id=report_id, action="SCAR_TRIGGERED", changed_fields={scar_id, scar_no, supplier_id, source_type: "capa"})`
   - `commit`（与 complaint 路径一致：源侧审计 + 一次 commit；SCAR 侧不另写 CREATE，跟随 `_create_scar_without_commit` 现状）
4. 返回 `SCARResponse`（与 `/scars` 创建响应同形）

**错误**

| 条件 | 语义 |
|---|---|
| CAPA 不存在 / 不可见 | 404 |
| 无编辑权限 | 403 |
| D1/D2/ARCHIVED | 400 |
| 已有 `scar_ref_id` | 400 |
| supplier 缺失 / 跨厂 | 400 |

### 5.2 CAPA 读模型投影

`CAPAResponse`（及 list item 若已含详情字段则同形；至少 **GET by id** 必含）增加：

```ts
scar_ref_id?: string | null;
linked_scar?: {
  scar_id: string;
  scar_no: string;
  status: string;       // open | in_progress | responded | verified | closed
  supplier_id: string;
} | null;
```

- 由 `scar_ref_id` join `supplier_scars`；无则 `null`
- **不**在 CAPA 表镜像 `scar_status` 列

### 5.3 `transition_scar` 同步审计

在 `scar_service.transition_scar`，状态变更成功后、commit 前：

- 若 `scar.capa_ref_id` 非空：
  - `AuditLog(table_name="capa_eightd", record_id=scar.capa_ref_id, action="SCAR_STATUS_SYNCED", changed_fields={scar_id, scar_no, old_status, new_status})`
- 不更新 CAPA 行字段
- 既有 SCAR 侧 `TRANSITION` 审计保留

故事「至少创建/关闭可见」：创建靠 `linked_scar.status=open` 投影；关闭靠 transition→`closed` 后投影 + `SCAR_STATUS_SYNCED`。中间态（in_progress 等）同样投影，不额外裁剪。

### 5.4 `POST /scars/{id}/link-capa` 一致性修补

成功路径额外：

1. 若目标 CAPA 已有 `scar_ref_id` 且 ≠ 当前 `scar_id` → 400（避免抢绑）
2. 写 `capa.scar_ref_id = scar.scar_id`（与 `scar.capa_ref_id` 双向）
3. 既有 SCAR 侧 `LINK_CAPA` 审计保留；可选 CAPA 侧轻量字段变更审计（实现时若与 YAGNI 冲突可只做双向指针，主审计仍 `LINK_CAPA`）

本故事主路径是 trigger；link-capa 修补防止历史半关联。

### 5.5 Schema 扩展

- `backend/app/schemas/scar.py`：`SCARCreate.source_type` Literal 增加 `"capa"`（若 trigger 走专用 body 可不经 SCARCreate，仍须保证 Response/列表过滤接受该值）
- `frontend/src/types`：`SupplierSCAR.source_type` 联合类型增加 `'capa'`
- DB：`source_type` 为 `String(20)`，**无** CHECK — 无需迁移改约束

## 6. 前端

### 6.1 位置

`CAPADetailPage` 右侧「报告信息」`DataCard`：

- 行「关联 SCAR」
  - 无 `linked_scar` + 可触发：按钮 `data-e2e="capa-trigger-scar"`
  - 有 `linked_scar`：`data-e2e="capa-linked-scar"` 展示 `scar_no` + 状态 Tag，点击 `navigate(/scars/{scar_id})`
  - viewer / 不可编辑：无按钮，有关联仍只读可见

### 6.2 触发门禁（与后端一致）

```
canEdit('capa')
&& !['D1_TEAM','D2_DESCRIPTION','ARCHIVED'].includes(status)
&& !linked_scar
```

### 6.3 Modal

- 供应商 Select（`listSuppliers`，必填）
- description TextArea（预填 document_no + title + d2/d4）
- requested_action / due_date 可选
- affected_batches 可选（多行 → string[]）
- 确认 → `triggerScar(reportId, body)` → 重新 `getCAPA` 刷新 `linked_scar`

### 6.4 API client

`frontend/src/api/capa.ts`：`triggerScar(id, body)` → `POST /capa/{id}/trigger-scar`

### 6.5 i18n

`frontend/src/locales/{zh-CN,en-US}/capa.json`：trigger 按钮、Modal 标题/校验、linked 标签、错误文案。

## 7. 审计契约

| action | table_name | record_id | changed_fields（关键） |
|---|---|---|---|
| `SCAR_TRIGGERED` | `capa_eightd` | CAPA `report_id` | `scar_id`, `scar_no`, `supplier_id`, `source_type` |
| `SCAR_STATUS_SYNCED` | `capa_eightd` | CAPA `report_id` | `scar_id`, `scar_no`, `old_status`, `new_status` |

既有 SCAR 表上的 `CREATE`/`TRANSITION`/`LINK_CAPA` 行为不删除。

## 8. 测试

### 8.1 Backend

- trigger 成功：指针双向 + `source_type=capa` + `SCAR_TRIGGERED`
- 重复 trigger → 400
- 跨厂 supplier → 400
- D1 / D2 / ARCHIVED → 400
- 无编辑权限 → 403
- GET CAPA 含 `linked_scar` 投影
- `transition_scar` 在 `capa_ref_id` 存在时写 `SCAR_STATUS_SYNCED`；无关联不写
- `link-capa`：回写 `scar_ref_id`；CAPA 已被其他 SCAR 占用 → 400
- migration：列可空 + FK + 部分索引

### 8.2 Frontend (vitest)

- 按钮门控（状态 / 权限 / 已关联）
- Modal 提交调用 `triggerScar`
- linked tag 展示与导航

### 8.3 E2E

`frontend/e2e/specs/m1-core/capa-story-scar-trigger.spec.ts`：

1. Seed：来料向 8D 处于 D3 或 D4 + 已知供应商（复用 D3 E2E supplier）
2. engineer 登录 → 详情 → 发起 SCAR → 见 `capa-linked-scar` / scar_no
3. 将 SCAR 推进至 closed（UI 或经 API 捷径，与既有 e2e 风格一致）
4. 回 8D 详情：`linked_scar.status === closed`
5. admin 审计日志客户端过滤：存在 `SCAR_TRIGGERED` 与至少一条 `SCAR_STATUS_SYNCED`（关闭时）

只验结构/关联，不验业务文案质量。

## 9. 明确不在范围

- SCAR 模块完整业务流程改造 / 状态机改枚举
- 8D 关闭自动关闭 SCAR

## 10. 实现顺序建议（plan 阶段细化）

1. migration + model/schema（CAPA `scar_ref_id` + response 投影字段）
2. service `trigger_scar_from_capa` + API 路由 + 测试
3. `transition_scar` 同步审计 + `link-capa` 双向
4. FE types/api/Modal/Detail 接线 + vitest
5. seed_e2e（若需专用 CAPA）+ Playwright
6. PROGRESS / gap analysis 勾选 + deploy note（若有）

## 11. 风险与注意

- **Alembic head**: feature 分支实现时必须 `alembic heads` 对 parent tip 链式挂接；禁止把 parent 上已有 revision 文件拷进分支（01.4 教训）
- **状态字面量**: 以 `backend/app/state_machines/eightd_state.py` 为准（D2 为 `D2_DESCRIPTION` 等）
- **`_create_scar_without_commit` 不写 CREATE 审计**: 与 complaint 一致，源侧 `SCAR_TRIGGERED` 为故事主审计
- **循环 FK 语义**: CAPA→SCAR 与 SCAR→CAPA 双指针；删除 SCAR 时 CAPA `scar_ref_id` SET NULL；删除 CAPA 时 SCAR `capa_ref_id` 既有 SET NULL 行为保持

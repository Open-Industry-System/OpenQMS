# US-E2E-01.8 8D → 知识库沉淀 — Design

**日期**: 2026-07-16  
**状态**: 设计定稿（待实现）  
**子故事**: `docs/user-stories/US-E2E-01-capa-8d-closed-loop/US-E2E-01.8-knowledge-sink.md`（定稿 v1，2026-07-08）  
**AI_REQUIRED**: true（无 LLM → 阻断 D8 关闭）  
**Gap**: `docs/superpowers/specs/2026-07-08-us-e2e-01-gap-analysis.md` §01.8  

## 1. 目标

D8 审批关闭时，系统自动将完整 8D 报告沉淀为**结构化知识条目**，进入可扩展的知识库骨架；条目可被：

1. **产品/产品线检索**（后续产品设计查历史 8D 经验）
2. **01.2 推荐编排**（新 8D 触发 D4/D5 推荐时语义命中本条）

形成「当前 8D → 知识库 → 未来 8D」闭环。本轮只接入 **8D 关闭** 作为首个写入源；表与 API 按多源实时 RAG 总线设计，后续 FMEA/SCAR/客诉等只加 writer。

**非目标**（本轮不做）：

- 知识条目人工编辑/审核工作流
- 多源 writer 全量接入（仅预留 `source_type`）
- 检索质量/召回率评测
- 改动或废弃既有 `capa_lessons_learned` 句级路径
- 01.9 横向扩散

## 2. 已有基建（复用，不重造）

| 资产 | 用途 |
|---|---|
| `capa_lessons_learned` + `_extract_lessons` / `_extract_d8_with_cleanup` | D7/D8 **句级** lessons；stage-5 `LessonsLearnedSource` 继续用；**本轮不改写路径** |
| `enqueue_embedding` + `embedding_sync_worker` + `document_embeddings` | 向量化管道；扩 `entity_type=knowledge_entry` |
| `provider_adapter.complete_json` + `build_client` | LLM 摘要/标签（与 P1-D 一致） |
| `advance_capa` 边闸口模式（D7 lessons / D8 doc gate / D3→D4） | D8_APPROVAL_PENDING→D8_CLOSURE 挂 fail-closed sink |
| 01.4 FMEA reverse lookup / `scar_ref_id` /（若已合）01.6 risk inputs | `fields.linkage` 拼装 |
| `AuditLog` 约定 | `KNOWLEDGE_SUNK` |

**Gap（对照故事）**：

| 验收 | 现状 | 本设计 |
|---|---|---|
| D8 关闭自动沉淀 | D7 advance / D8 保存时切句 lessons，非关闭后全报告 | 关闭边同事务 sink 整单 entry |
| 结构化 8 字段 | `lesson_text` 句级，非 8 字段 | `knowledge_entries.fields` JSONB |
| 推荐命中闭环 | lessons stage-5 仅句级 | 新 source `knowledge_entry` 并列 stage 5 |
| 按产品检索 | 无 | `GET /api/knowledge/entries` |
| 无 LLM BLOCKED | lessons 启发式无 LLM | 无 LLM / LLM 失败 → 关闭 422 |

## 3. 决策摘要

| 决策 | 选择 | 理由 |
|---|---|---|
| 实体形态 | **新表 `knowledge_entries`（通用骨架）** | 多源可扩展；与句级 `capa_lessons_learned` 解耦 |
| 与 lessons 关系 | **共存，不替换** | 01.2 句级召回不破坏；entry=整单快照 |
| 范围 | **KB 骨架 + 8D 首源** | 用户确认；非本轮全模块入库 |
| 无 LLM | **阻断 D8 关闭**（422 `blocked`） | 故事 AI_REQUIRED=true 字面 |
| 触发时机 | **`D8_APPROVAL_PENDING→D8_CLOSURE` 同事务** | fail-closed；与 D7 lessons 闸口同模式 |
| 幂等 | **`uuid5(knowledge:capa:{report_id})` + UNIQUE(source_type, source_id)** | 手动重触发 = upsert |
| LLM 职责 | **仅 `lesson_summary` + `tags`** | 确定性 7 字段服务层拼装，可测 |
| 推荐接入 | **新 source kind `knowledge_entry`，与 `lessons_learned` 并列 stage 5** | provenance 清晰，不污染句级源 |
| `KNOWLEDGE_RETRIEVED` | **本轮不写热路径审计** | 避免推荐噪音；E2E 用响应体断言命中；强制审计仅 `KNOWLEDGE_SUNK` |
| 空业务字段 | **允许空串，8 个 key 必须齐全** | 不因缺 D 步文本卡关闭；缺 key=实现 bug |
| 01.6 未合入 | **`linkage.supplier_risk_alert_ids=[]`** | 不阻塞 01.8；合入后拼装补读 |

## 4. 数据模型

### 4.1 新表 `knowledge_entries`

```python
class KnowledgeEntry(Base):
    __tablename__ = "knowledge_entries"

    entry_id: Mapped[uuid.UUID] = mapped_column(UUID(as_uuid=True), primary_key=True)
    # 确定性: uuid5(NAMESPACE_URL, f"knowledge:{source_type}:{source_id}")

    source_type: Mapped[str] = mapped_column(String(32), nullable=False)  # 本轮仅 "capa"
    source_id: Mapped[uuid.UUID] = mapped_column(UUID(as_uuid=True), nullable=False)

    factory_id: Mapped[uuid.UUID] = mapped_column(
        UUID(as_uuid=True), ForeignKey("factories.id", ondelete="RESTRICT"), nullable=False
    )
    product_line_code: Mapped[str] = mapped_column(String(20), nullable=False)

    document_no: Mapped[str] = mapped_column(String(40), nullable=False)
    title: Mapped[str] = mapped_column(String(200), nullable=False)
    severity: Mapped[str | None] = mapped_column(String(20), nullable=True)

    fields: Mapped[dict] = mapped_column(JSONB, nullable=False)
    status: Mapped[str] = mapped_column(String(16), nullable=False, default="active")
    # active | 预留 superseded
    llm_status: Mapped[str] = mapped_column(String(16), nullable=False, default="done")
    # 关闭成功路径恒为 done（严格 BLOCKED 下不会出现 skipped entry）

    embedding_text: Mapped[str] = mapped_column(Text, nullable=False)
    # worker 只读此列，不解析 fields

    created_at / updated_at: timestamptz
```

**约束与索引**：

- `UNIQUE (source_type, source_id)` — 一源一条 entry
- `INDEX (factory_id, product_line_code, status)` — 产品检索
- `CHECK (status IN ('active', 'superseded'))`（若实现时加枚举约束）
- `CHECK (source_type IN ('capa'))` 本轮可只在服务层校验；迁移 CHECK 可选，避免后续加源要改约束——**推荐服务层白名单 + 无 DB CHECK on source_type**

**外键**：不对 `source_id` 建多态 FK（多源）；CAPA 删除策略：

- 选项：**ON 应用层** — CAPA CASCADE 不自动删 entry（保留历史知识）；或 entry `source_id` 无 FK，CAPA 删后 entry 仍在且 `document_no` 可追溯。
- **本设计选定**：`source_id` **无 FK**；CAPA 行删除（若发生）不级联删知识。E2E/生产 CAPA 极少物理删。手动清理不在范围。

### 4.2 `fields` JSONB 契约（8 逻辑块）

键必须齐全：

```json
{
  "d2": "string",
  "d3": "string",
  "d4_root_cause": "string",
  "d5": "string",
  "d7_node_action": "string",
  "linkage": {
    "fmea_ids": ["uuid-str", "..."],
    "scar_id": "uuid-str | null",
    "supplier_risk_alert_ids": ["uuid-str", "..."]
  },
  "closure": "string",
  "lesson_summary": "string",
  "tags": ["string", "..."]
}
```

说明：故事称「8 字段」——业务块为 d2/d3/d4/d5/d7/linkage/closure/lesson_summary；`tags` 为 LLM 附属，与 summary 同生命周期，存在 `fields` 内便于单次读写。

### 4.3 `embedding_text` 稳定拼装

```
[{document_no}] {title}
严重度: {severity or ""}
D2: {fields.d2}
D3: {fields.d3}
D4: {fields.d4_root_cause}
D5: {fields.d5}
D7: {fields.d7_node_action}
关闭: {fields.closure}
摘要: {fields.lesson_summary}
标签: {", ".join(fields.tags)}
```

顺序固定，便于单测快照。

### 4.4 与 `capa_lessons_learned` / embeddings

```
capa_eightd ──1:1──► knowledge_entries (source_type='capa')
       │
       └──1:N──► capa_lessons_learned     # 不变
                        │
document_embeddings ◄───┴── entity_type ∈ {…, capa_lesson, knowledge_entry}
```

- Worker / backfill：`ENTITY_TYPES` 与 `ENTITY_TABLE_MAP` 增加  
  `knowledge_entry` → `(knowledge_entries, entry_id, product_line_code, factory_id)`  
  chunk 文本列：`embedding_text`（entity_field 可用 `"embedding_text"`）。
- Upsert 前存在性检查（对齐 capa_lesson R9）。
- `document_embeddings.entity_type` 现 `String(20)`：`knowledge_entry` 长度 15，无需扩列。

## 5. 服务与状态机

### 5.1 `knowledge_sink_service.sink_capa_on_close(db, capa, user_id, *, manual=False)`

同事务、fail-closed，**不** `commit`、**不**改 `capa.status`。

步骤：

1. **LLM 可用性**  
   `pc = build_client(...)`（与 capa draft/recommend 同源配置）。  
   `pc is None` → `raise ValueError` 带结构化信息（API 映 422 blocked）。

2. **拼装确定性字段**（§5.2）→ 得到 partial fields（无 summary/tags）。

3. **LLM**  
   `complete_json(prompt, schema)` → `{lesson_summary, tags}`。  
   校验：summary 非空 strip；tags 为 list[str]，长度 3–8（不足可 pad 拒绝——**拒绝并失败**，不静默填）。  
   超时/异常/schema 失败 → `raise ValueError`。

4. **组装**  
   `fields` 合并；`embedding_text` 拼装；`entry_id = uuid5(..., f"knowledge:capa:{capa.report_id}")`。

5. **Upsert**  
   `INSERT ... ON CONFLICT (source_type, source_id) DO UPDATE` 更新 fields/embedding_text/title/severity/llm_status/updated_at。  
   若冲突更新（重触发）：  
   - cancel pending outbox `entity_type=knowledge_entry AND entity_id=entry_id`  
   - delete existing `document_embeddings` for that entity  
   - 再 `enqueue_embedding`  
   （可复用 d8 lessons cleanup 小 helper。）

6. **Enqueue**  
   `await enqueue_embedding(db, "knowledge_entry", entry_id, capa.product_line_code, capa.factory_id)`  
   **必须在 commit 前**（项目约定）。

7. **审计**  
   `AuditLog(action="KNOWLEDGE_SUNK", table_name="knowledge_entries", record_id=entry_id, factory_id=..., operated_by=user_id, changed_fields={capa_id, product_line_code, entry_id, document_no, manual})`  
   亦允许 `table_name="capa_eightd", record_id=capa.report_id` 并在 changed_fields 带 entry_id——**选定**：`table_name="capa_eightd"`, `record_id=capa.report_id`，与既有 CAPA 审计时间线一致；`changed_fields` 含 `entry_id`。

### 5.2 确定性字段拼装细则

| key | 来源 |
|---|---|
| `d2` | `capa.d2_description or ""` |
| `d3` | `capa.d3_interim or ""`；若存在当前 done 的 D3 impact/report 摘要，追加「受影响范围：…」（实现时读既有 d3 服务/表；无则仅 interim） |
| `d4_root_cause` | `capa.d4_root_cause or ""` + 最新 `conclusion=passed` 的 `CapaRootCauseVerification` 一行摘要（method / verified_at）；无验证行则仅根因文本 |
| `d5` | `capa.d5_correction or ""` |
| `d7_node_action` | 聚合 `capa_d7_node_action` 中 status∈{confirmed, auto_filled}：`node_id + action + fmea ref`；无行则 `capa.d7_prevention or ""` |
| `linkage.fmea_ids` | 复用 01.4 反查（header / D4 source_ref / D7 节点）去重列表；失败/无 → `[]` |
| `linkage.scar_id` | `str(capa.scar_ref_id) if capa.scar_ref_id else null` |
| `linkage.supplier_risk_alert_ids` | 若 01.6 表/API 已存在则读；否则 `[]` |
| `closure` | `capa.d8_closure or ""` |

### 5.3 LLM prompt 契约

- **输入**：document_no, title, severity, product_line_code, 确定性 7 块文本（截断单块过长时每块 max ~2k 字符，防爆 context）。
- **输出 JSON schema**：
  ```json
  {
    "type": "object",
    "required": ["lesson_summary", "tags"],
    "properties": {
      "lesson_summary": {"type": "string", "minLength": 1},
      "tags": {"type": "array", "items": {"type": "string"}, "minItems": 3, "maxItems": 8}
    }
  }
  ```
- **超时**：默认 30s（或项目 CAPA LLM 统一配置，实现时与 `capa` draft 对齐并写死常量名）。
- **审计模型名**：可写入 `changed_fields.llm_model`（可选）。

### 5.4 `advance_capa` 接入

现有：

```python
elif current == D8_APPROVAL_PENDING and target == D8_CLOSURE:
    pass
```

改为：

```python
elif current == D8_APPROVAL_PENDING and target == D8_CLOSURE:
    await sink_capa_on_close(db, capa, user_id, manual=False)
```

顺序保持：**闸口成功 → `capa.status = D8_CLOSURE` → TRANSITION + D8_APPROVED 审计**。  
sink 失败 → 不改 status，异常上抛。

API 层 `ValueError` → HTTP：

- 消息含 blocked / llm → **422**  
  `{"detail": {"blocked": true, "reason": "llm_unavailable" | "llm_failed", "message": "..."}}`  
- 其他 ValueError → 既有 400 映射

与 01.2 推荐 `blocked` 响应形状对齐，前端可复用 banner。

### 5.5 手动重触发

`POST /api/capa/{report_id}/sink-knowledge`

- 权限：`canEdit('capa')` + factory/PL scope
- 状态：`capa.status ∈ {D8_CLOSURE, ARCHIVED}`
- 体：空或 `{}`
- 调用同一 `sink_capa_on_close(..., manual=True)`
- 成功 200 + entry 摘要；失败 422 blocked / 400

## 6. 检索与推荐闭环

### 6.1 产品检索 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/knowledge/entries` | 分页列表 |
| GET | `/api/knowledge/entries/{entry_id}` | 详情（含 fields） |

**列表 query**：

- `product_line_code`：可选；缺省用 scope 允许的 PL 集合过滤
- `source_type`：可选，默认不限（本轮数据仅 capa）
- `q`：可选，对 `document_no` / `title` / `embedding_text` ILIKE
- `page`, `page_size`：统一分页

**权限**：`canView('capa')`（或与知识库模块一致的只读门；无独立 knowledge 模块时用 capa view）+ `check_factory_access` + PL scope。

**列表项**：entry_id, source_type, source_id, document_no, title, severity, product_line_code, status, lesson_summary（从 fields 抽）, tags, created_at。  
**详情**：+ 完整 `fields`。

路由挂载：新建 `backend/app/api/knowledge.py`，`main` include；不塞进已膨胀的 `capa.py` 列表逻辑（重沉淀除外，挂 capa 路由以贴资源）。

### 6.2 推荐源 `KnowledgeEntrySource`

- `name = "knowledge_entry"`
- 注册：`recommendation_orchestrator._build_sources` + `NEW_SOURCE_KINDS`
- **Stage**：与 `lessons_learned` 同属 stage 5 组合执行（对齐 historical_capa / lessons 既有 combination 模式；实现时读 STAGE_PLAN，在 stage 5 增加并列 source，**不改变 stage 总数 12** 的对外契约——若 stage 5 已是单 source，则改为 multi-source combination 或在 retrieve 内不扩 stage 数）。
  - **硬约束**：响应仍 12 个 stage 槽位；若不能改 STAGE_PLAN 结构，则在 `LessonsLearnedSource.retrieve` 末尾 UNION entry 命中并在 candidate.metadata 标 `entry_id` + `match_source` 细分——**优先独立 source kind**；仅当 STAGE_PLAN 改动风险过高时退回 UNION。
- `should_skip`：该 factory+PL 无 `status=active` 的 knowledge_entry → skip reason
- `retrieve`：embedding 近邻 on `entity_type=knowledge_entry`，join entries，limit Top-K，candidate.content 用 lesson_summary 或 embedding_text 截断；metadata 含 `entry_id`, `document_no`, `capa_id=source_id`

### 6.3 闭环验收（E2E）

1. 关闭 8D-A（有 LLM）→ entry 落库  
2. 新建/推进 8D-B 同 PL，触发 D4 或 D5 推荐  
3. 响应 items 中存在 metadata.entry_id == 8D-A 的 entry（或 content 含 8D-A document_no）  
4. `GET /api/knowledge/entries?product_line_code=` 可见 8D-A  

无 LLM：`test.skip` 或专用用例 assert 关闭 422 blocked（与 ai-credentials guard 一致）。

**日期**: 2026-07-16  
**状态**: 设计定稿（审查修订版 v3）  
**子故事**: `docs/user-stories/US-E2E-01-capa-8d-closed-loop/US-E2E-01.8-knowledge-sink.md`（定稿 v1，2026-07-08）  
**AI_REQUIRED**: true（无 LLM 凭证 → BLOCKED 阻断 D8 关闭；LLM 调用失败 → FAILED 阻断关闭）  
**Gap**: `docs/superpowers/specs/2026-07-08-us-e2e-01-gap-analysis.md` §01.8  

> v2 修订：D7 `action` 过滤；BLOCKED/FAILED 分契约；`KNOWLEDGE_RETRIEVED`；content_hash；stage 5 extra；embedding_status/id；linked_capa_id。

## 1. 目标

D8 审批关闭时，系统自动将完整 8D 报告沉淀为**结构化知识条目**，进入可扩展的知识库骨架；条目可被：

1. **产品/产品线检索**（后续产品设计查历史 8D 经验）
2. **01.2 推荐编排**（新 8D 触发 D4/D5 推荐时语义命中本条）

形成「当前 8D → 知识库 → 未来 8D」闭环。本轮只接入 **8D 关闭** 作为首个写入源；表与 API 按多源实时 RAG 总线设计，后续 FMEA/SCAR/客诉等只加 writer。

**非目标**（本轮不做）：

- 知识条目人工编辑/审核工作流
- 多源 writer 全量接入（仅预留 `source_type`）
- 检索质量/召回率评测
- 改动或废弃既有 `capa_lessons_learned` 句级路径
- 01.9 横向扩散

## 3. 决策摘要

| 决策 | 选择 | 理由 |
|---|---|---|
| 实体形态 | **新表 `knowledge_entries`（通用骨架）** | 多源可扩展；与句级 `capa_lessons_learned` 解耦 |
| 与 lessons 关系 | **共存，不替换** | 01.2 句级召回不破坏；entry=整单快照 |
| 范围 | **KB 骨架 + 8D 首源** | 用户确认；非本轮全模块入库 |
| 无 LLM / LLM 失败 | **均阻断 D8 关闭**；契约分 `outcome=blocked` vs `outcome=failed` | 故事 AI_REQUIRED + FAILED 字面 |
| 触发时机 | **`D8_APPROVAL_PENDING→D8_CLOSURE` 同事务** | fail-closed；与 D7 lessons 闸口同模式 |
| 幂等 | **`uuid5(knowledge:capa:{report_id})` + UNIQUE(source_type, source_id)** | 手动重触发 = upsert |
| LLM 职责 | **仅 `lesson_summary` + `tags`** | 确定性 7 字段服务层拼装，可测 |
| 推荐接入 | **`knowledge_entry` 注册为 stage 5 的 `extra_sources_d4` + `extra_sources_d5`**（独立 source，12 stage 不变） | 编排器已有 extra_sources 模式；独立 provenance；**禁止** UNION 进 `LessonsLearnedSource` |
| `KNOWLEDGE_RETRIEVED` | **推荐源命中时写 1 条审计/次请求**（含 entry_ids） | 故事字段级契约必验收；非「每次候选一行」 |
| 空业务字段 | **允许空串，8 个 key 必须齐全** | 不因缺 D 步文本卡关闭；缺 key=实现 bug |
| linkage 供应商风险 | **直读 `SupplierRiskAlert.linked_capa_id == capa.report_id`** | 模型 FK 已存在；不写「未合入则空」永久分支 |
| 向量就绪 | **`embedding_status`∈{pending,ready,failed} + `embedding_id` + `content_hash`** | `status=active`≠可语义检索；E2E 轮询 ready |
| 重沉淀并发 | **outbox/worker 按 `content_hash` 丢弃陈旧写入** | 仅 cancel pending 挡不住 processing 竞态 |

## 4. 数据模型

### 4.1 新表 `knowledge_entries`

```python
class KnowledgeEntry(Base):
    __tablename__ = "knowledge_entries"

    entry_id: Mapped[uuid.UUID] = mapped_column(UUID(as_uuid=True), primary_key=True)
    # 确定性: uuid5(NAMESPACE_URL, f"knowledge:{source_type}:{source_id}")

    source_type: Mapped[str] = mapped_column(String(32), nullable=False)  # 本轮仅 "capa"
    source_id: Mapped[uuid.UUID] = mapped_column(UUID(as_uuid=True), nullable=False)

    factory_id: Mapped[uuid.UUID] = mapped_column(
        UUID(as_uuid=True), ForeignKey("factories.id", ondelete="RESTRICT"), nullable=False
    )
    product_line_code: Mapped[str] = mapped_column(String(20), nullable=False)

    document_no: Mapped[str] = mapped_column(String(50), nullable=False)  # 对齐 CAPAEightD.document_no
    title: Mapped[str] = mapped_column(String(200), nullable=False)
    severity: Mapped[str | None] = mapped_column(String(20), nullable=True)

    fields: Mapped[dict] = mapped_column(JSONB, nullable=False)
    status: Mapped[str] = mapped_column(String(16), nullable=False, default="active")
    # active = 条目有效可列表/详情；预留 superseded
    # 注意：active ≠ 语义可检索（见 embedding_status）

    llm_status: Mapped[str] = mapped_column(String(16), nullable=False, default="done")
    # 关闭成功路径恒为 done（无凭证/失败时不会落库）

    embedding_text: Mapped[str] = mapped_column(Text, nullable=False)
    # worker 只读此列，不解析 fields

    content_hash: Mapped[str] = mapped_column(String(64), nullable=False)
    # sha256(embedding_text)；写入 outbox metadata / worker 防陈旧覆盖

    embedding_status: Mapped[str] = mapped_column(String(16), nullable=False, default="pending")
    # pending | ready | failed — 语义检索仅 ready

    embedding_id: Mapped[uuid.UUID | None] = mapped_column(UUID(as_uuid=True), nullable=True)
    # 指向当前有效 document_embeddings.id（worker 成功后回写）；故事契约 entry.embedding_id

    created_at / updated_at: timestamptz
```

**约束与索引**：

- `UNIQUE (source_type, source_id)` — 一源一条 entry
- `INDEX (factory_id, product_line_code, status)` — 产品列表
- `INDEX (factory_id, product_line_code, embedding_status)` — 推荐 should_skip / 语义源
- `CHECK (status IN ('active', 'superseded'))`
- `CHECK (embedding_status IN ('pending', 'ready', 'failed'))`
- `source_type`：**服务层白名单**，无 DB CHECK（避免后续加源改约束）

**外键**：不对 `source_id` 建多态 FK（多源）；CAPA 删除策略：

- 选项：**ON 应用层** — CAPA CASCADE 不自动删 entry（保留历史知识）；或 entry `source_id` 无 FK，CAPA 删后 entry 仍在且 `document_no` 可追溯。
- **本设计选定**：`source_id` **无 FK**；CAPA 行删除（若发生）不级联删知识。E2E/生产 CAPA 极少物理删。手动清理不在范围。

### 4.2 `fields` JSONB 契约（8 逻辑块）

键必须齐全：

```json
{
  "d2": "string",
  "d3": "string",
  "d4_root_cause": "string",
  "d5": "string",
  "d7_node_action": "string",
  "linkage": {
    "fmea_ids": ["uuid-str", "..."],
    "scar_id": "uuid-str | null",
    "supplier_risk_alert_ids": ["uuid-str", "..."]
  },
  "closure": "string",
  "lesson_summary": "string",
  "tags": ["string", "..."]
}
```

说明：故事称「8 字段」——业务块为 d2/d3/d4/d5/d7/linkage/closure/lesson_summary；`tags` 为 LLM 附属，与 summary 同生命周期，存在 `fields` 内便于单次读写。

### 4.3 `embedding_text` 稳定拼装

```
[{document_no}] {title}
严重度: {severity or ""}
D2: {fields.d2}
D3: {fields.d3}
D4: {fields.d4_root_cause}
D5: {fields.d5}
D7: {fields.d7_node_action}
关闭: {fields.closure}
摘要: {fields.lesson_summary}
标签: {", ".join(fields.tags)}
```

顺序固定，便于单测快照。

### 4.4 与 `capa_lessons_learned` / embeddings

```
capa_eightd ──1:1──► knowledge_entries (source_type='capa')
       │
       └──1:N──► capa_lessons_learned     # 不变
                        │
document_embeddings ◄───┴── entity_type ∈ {…, capa_lesson, knowledge_entry}
```

- Worker / backfill：`ENTITY_TYPES` 与 `ENTITY_TABLE_MAP` 增加  
  `knowledge_entry` → `(knowledge_entries, entry_id, product_line_code, factory_id)`  
  chunk 文本列：`embedding_text`（entity_field 可用 `"embedding_text"`）。
- Upsert 前存在性检查（对齐 capa_lesson R9）。
- `document_embeddings.entity_type` 现 `String(20)`：`knowledge_entry` 长度 15，无需扩列。
- **内容版本**：outbox 行须携带 `content_hash`（见 §5.1 / §5.6）；worker 写入前与 entry 当前 hash 比对。

### 4.5 Outbox 内容哈希（防 processing 竞态）

既有 `embedding_sync_outbox` **无** payload/hash 列。本轮二选一，**选定 A**：

| 选项 | 做法 | 选定 |
|---|---|---|
| **A** | 扩 `embedding_sync_outbox` 可空列 `content_hash VARCHAR(64)`；`enqueue_embedding` 增加可选参数；仅 `knowledge_entry` 必填；其他 entity 保持 NULL 兼容 | **是** |
| B | 不改 outbox，worker 读 entry 时比较 hash 且串行 `FOR UPDATE` entry 行 | 作 A 的补充锁，不单独替代 |

Worker 规则（`entity_type=knowledge_entry`）：

1. claim 事件后读 `knowledge_entries`：`SELECT … WHERE entry_id=:id FOR UPDATE`（同 factory）。
2. 若 row 不存在 → 丢弃事件（completed/cancelled）。
3. 若 `event.content_hash != entry.content_hash` → **丢弃不写向量**（陈旧 processing），mark completed + reason stale。
4. 若一致 → 用当前 `embedding_text` 生成向量 → upsert `document_embeddings` → 回写 `entry.embedding_id`、`entry.embedding_status='ready'`。
5. embed **瞬时**失败（未达 max_attempts）→ outbox 回 `pending` 退避重试；**`entry.embedding_status` 保持 `pending`**（非终态失败）。  
6. outbox 进入 **`dead_letter`**（retry 耗尽）→ 同事务/同批回写 `entry.embedding_status='failed'`；**不**改 `status=active`。  
7. UI：`pending`=仍在向量化/重试；`failed`=终态需人工重沉淀或查 worker；`ready`=可语义检索。

重沉淀路径：cancel **pending** + 仍无法 cancel 的 **processing** 靠步骤 3 哈希丢弃；新事件带新 hash。

## 5. 服务与状态机

### 5.1 `knowledge_sink_service.sink_capa_on_close(db, capa, user_id, *, manual=False)`

同事务、fail-closed，**不** `commit`、**不**改 `capa.status`。

步骤：

1. **LLM 可用性（BLOCKED）**  
   `pc = build_client(...)`（与 capa draft/recommend 同源配置）。  
   `pc is None` → raise **`KnowledgeSinkBlockedError`**（reason=`llm_unavailable`）。

2. **拼装确定性字段**（§5.2）→ 得到 partial fields（无 summary/tags）。

3. **LLM（FAILED）**  
   `complete_json(prompt, schema)` → `{lesson_summary, tags}`。  
   校验：summary 非空 strip；tags 为 list[str]，长度 3–8（不足/超限 → **拒绝并失败**，不静默 pad）。  
   超时/异常/schema 失败 → raise **`KnowledgeSinkFailedError`**（reason=`llm_failed`）。

4. **组装**  
   `fields` 合并；`embedding_text` 拼装；  
   `content_hash = sha256(embedding_text utf-8).hexdigest()`；  
   `entry_id = uuid5(..., f"knowledge:capa:{capa.report_id}")`。

5. **Upsert**  
   `INSERT ... ON CONFLICT (source_type, source_id) DO UPDATE` 更新  
   fields / embedding_text / content_hash / title / severity / llm_status /  
   **`embedding_status='pending'`** / **`embedding_id=NULL`** / updated_at。  
   重触发清理：  
   - `UPDATE embedding_sync_outbox SET status='cancelled' WHERE entity_type='knowledge_entry' AND entity_id=:id AND status='pending'`  
   - **不**强杀 `processing`（靠 content_hash 丢弃）  
   - `DELETE FROM document_embeddings WHERE entity_type='knowledge_entry' AND entity_id=:id`  
   - 再 enqueue（带新 hash）

6. **Enqueue**  
   `await enqueue_embedding(db, "knowledge_entry", entry_id, pl, factory_id, content_hash=content_hash)`  
   **必须在 commit 前**。

7. **审计 `KNOWLEDGE_SUNK`**  
   **选定**：`table_name="capa_eightd"`, `record_id=capa.report_id`，`changed_fields={entry_id: str(entry_id), product_line_code, document_no, content_hash, manual, embedding_status:"pending"}` （**UUID 一律 str** 写入 JSONB）。

### 5.2 确定性字段拼装细则

| key | 来源 |
|---|---|
| `d2` | `capa.d2_description or ""` |
| `d3` | `capa.d3_interim or ""`；若存在当前 done 的 D3 impact/report 摘要，追加「受影响范围：…」（实现时读既有 d3 服务/表；无则仅 interim） |
| `d4_root_cause` | `current = (capa.d4_root_cause or "").strip()`；摘要仅取 **与当前根因绑定** 的验证：`CapaRootCauseVerification` 满足 `capa_id` + `factory_id` + `conclusion='passed'` + `root_cause_text == current`（与 D4→D5 门禁同口径），按 `verified_at DESC NULLS LAST, created_at DESC` 取 1 行拼 method/verified_at。无匹配行 → 仅根因文本（**禁止**用陈旧 passed 记录） |
| `d5` | `capa.d5_correction or ""` |
| `d7_node_action` | 聚合 `capa_d7_node_action` 中 **`action IN ('confirmed', 'auto_filled')`**（**不是** `status`；`status` 为 pending/executed/verified 生命周期，本切片可不限制 status）。拼装：`failure_mode_node_id` + `action` + `fmea_id` + prevention 字段摘要。无匹配行则回退 `capa.d7_prevention or ""` |
| `linkage.fmea_ids` | 复用 01.4 反查（header / D4 source_ref / D7 节点）去重列表；失败/无 → `[]` |
| `linkage.scar_id` | `str(capa.scar_ref_id) if capa.scar_ref_id else null` |
| `linkage.supplier_risk_alert_ids` | **`SELECT alert_id FROM supplier_risk_alerts WHERE linked_capa_id = capa.report_id AND factory_id = capa.factory_id`**（模型字段已存在）；无行 → `[]` |
| `closure` | `capa.d8_closure or ""` |

### 5.3 LLM prompt 契约

- **输入**：document_no, title, severity, product_line_code, 确定性 7 块文本（截断单块过长时每块 max ~2k 字符，防爆 context）。
- **输出 JSON schema**：
  ```json
  {
    "type": "object",
    "required": ["lesson_summary", "tags"],
    "properties": {
      "lesson_summary": {"type": "string", "minLength": 1},
      "tags": {"type": "array", "items": {"type": "string"}, "minItems": 3, "maxItems": 8}
    }
  }
  ```
- **超时**：默认 30s（或项目 CAPA LLM 统一配置，实现时与 `capa` draft 对齐并写死常量名）。
- **审计模型名**：可写入 `changed_fields.llm_model`（可选）。

### 5.4 `advance_capa` 接入

现有：

```python
elif current == D8_APPROVAL_PENDING and target == D8_CLOSURE:
    pass
```

改为：

```python
elif current == D8_APPROVAL_PENDING and target == D8_CLOSURE:
    await sink_capa_on_close(db, capa, user_id, manual=False)
```

顺序保持：**闸口成功 → `capa.status = D8_CLOSURE` → TRANSITION + D8_APPROVED 审计**。  
sink 失败 → 不改 status，异常上抛。

#### API 错误契约（BLOCKED ≠ FAILED）

故事：无 LLM 凭证 → `BLOCKED`；LLM 阶段 skipped/error → `FAILED`。两者都**阻断关闭**，但响应**形状必须可区分**（不能只靠 reason 塞进同一个 `blocked:true`）。

| 条件 | 异常类型 | HTTP | body |
|---|---|---|---|
| `build_client()` → None | `KnowledgeSinkBlockedError` | **422** | `{"detail": {"outcome": "blocked", "reason": "llm_unavailable", "message": "知识库沉淀需要 LLM，当前未配置"}}` |
| LLM 超时/异常/schema/校验失败 | `KnowledgeSinkFailedError` | **422** | `{"detail": {"outcome": "failed", "reason": "llm_failed", "message": "..."}}` |
| 其他业务 ValueError | 既有 | **400** | 既有映射 |

- 前端：`outcome==="blocked"` → 配置/凭证引导；`outcome==="failed"` → 可重试关闭/重沉淀。
- 实现：两异常类，API 层 `isinstance` 分支；**禁止**把 `llm_failed` 放进 `blocked: true`。

### 5.5 手动重触发

`POST /api/capa/{report_id}/sink-knowledge`

- 权限：`canEdit('capa')` + factory/PL scope
- 状态：`capa.status ∈ {D8_CLOSURE, ARCHIVED}`
- 体：空或 `{}`
- 调用同一 `sink_capa_on_close(..., manual=True)`
- 成功 200 + entry 摘要（含 `embedding_status`）；失败同 §5.4 契约（blocked / failed / 400）

## 6. 检索与推荐闭环

### 6.1 产品检索 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/knowledge/entries` | 分页列表 |
| GET | `/api/knowledge/entries/{entry_id}` | 详情（含 fields） |

**列表 query**：

- `product_line_code`：可选；缺省用 scope 允许的 PL 集合过滤
- `source_type`：可选，默认不限（本轮数据仅 capa）
- `q`：可选，对 `document_no` / `title` / `embedding_text` ILIKE
- `page`, `page_size`：统一分页

**权限与隔离**：

- 模块：`canView('capa')`（无独立 knowledge 模块时）。
- **列表（collection）**：请求**没有**单行 `factory_id` 可供 `check_factory_access(entity)`。必须在 **SQL WHERE** 显式加工厂谓词，再叠 PL：
  1. 若 `scope.effective_factory_id` 非空 → `knowledge_entries.factory_id = effective_factory_id`
  2. 否则若 `scope.factory_scope.accessible_factory_ids is not None` → `factory_id = ANY(accessible_factory_ids)`（空列表 → 空结果）
  3. 否则（group admin 全厂）→ 不按厂滤，仍可按 query 可选 `factory_id`
  4. PL：`product_line_code` query 或 `allowed_product_lines` 交集
- **详情（item）**：先按 `entry_id` 加载，再 `check_factory_access(entry, scope)` + PL 校验；越权 **404**（不 403 泄露存在性，与 CAPA 详情一致，若项目 CAPA 用 403 则对齐 CAPA）。
- **禁止**只滤 PL 不滤 factory（同 PL 跨厂串读）。

**列表项**：entry_id, source_type, source_id, document_no, title, severity, product_line_code, status, **embedding_status**, **embedding_id**, lesson_summary（从 fields 抽）, tags, created_at。  
**详情**：+ 完整 `fields` + content_hash（可选对客户端隐藏）。

路由挂载：新建 `backend/app/api/knowledge.py`，`main` include；不塞进已膨胀的 `capa.py` 列表逻辑（重沉淀除外，挂 capa 路由以贴资源）。

### 6.2 推荐源 `KnowledgeEntrySource`（定稿，无备选）

- `name = "knowledge_entry"`
- 注册：
  1. `_build_sources["knowledge_entry"] = KnowledgeEntrySource(...)`
  2. `NEW_SOURCE_KINDS` 加入 `"knowledge_entry"`
  3. **STAGE_PLAN stage 5** 改为：
     ```python
     StageSpec(
       5, "经验教训库检索", "lessons_learned", "both",
       extra_sources_d4=["knowledge_entry"],
       extra_sources_d5=["historical_capa_measure", "knowledge_entry"],
     )
     ```
     （在现有 `extra_sources_d5=["historical_capa_measure"]` 上追加；D4 侧新增 extra。）
  4. 若 orchestrator 对 extra source 有 embedding 前置检查列表，将 `knowledge_entry` 列入（与 lessons_learned 同级）。
- **禁止**在 `LessonsLearnedSource.retrieve` 内 UNION entry（避免 provenance 混淆）。
- 保持 **12** 个 stage 槽位不变。
- `should_skip`：该 factory+PL 无 `status=active` **且** `embedding_status='ready'` 的 knowledge_entry → skip reason（仅 active 但 pending 也 skip，reason 可区分「无条目」/「向量未就绪」）。
- `retrieve`：embedding 近邻 on `entity_type=knowledge_entry`，join `knowledge_entries` 且 `embedding_status='ready'`，limit Top-K；candidate.content 用 `lesson_summary` 或 `embedding_text` 截断；metadata 含 `entry_id`, `document_no`, `capa_id=source_id`, `embedding_id`。
- **`KNOWLEDGE_RETRIEVED` 审计（必做）**：在 `KnowledgeEntrySource.retrieve` 返回非空候选后，写 **1 条** `AuditLog`（每推荐请求每 source 至多一条，不按候选逐条）：
  - `action="KNOWLEDGE_RETRIEVED"`
  - `table_name="capa_eightd"`
  - **`record_id`**：`uuid.UUID(str(context.capa_data["report_id"]))`  
    （`RecommendationContext` **无** `capa_id` 属性，见 `recommendation_types.py`；**禁止** `context.capa_id`，否则 AttributeError 被 orchestrator 吞掉 → 整源候选丢失）
  - `factory_id=context.factory_id`
  - `changed_fields` 全部 JSON 安全：  
    `{ "entry_ids": [str(id), ...], "product_line_code": ..., "hit_count": int, "stage": 5 }`  
    **所有 UUID 必须 `str(...)`** 再写入 JSONB（含 SUNK 的 entry_id/capa 相关字段同规则）
  - `operated_by`：若 context 无 user_id，允许 `None`（与部分系统审计一致）；实现时若 orchestrator 可传 user_id 则写入
  - 空结果 **不**写审计；写审计本身失败不得静默吞掉候选——优先 try/except 记日志仍返回 candidates，或与项目 orchestrator 错误策略对齐并在测试锁死

### 6.3 闭环验收（E2E）

1. 关闭 8D-A（有 LLM）→ entry 落库，`embedding_status=pending`  
2. **轮询** entry 至 `embedding_status=ready`（或测试内直接跑一轮 worker）  
3. 新建/推进 8D-B 同 PL，触发 D4 或 D5 推荐  
4. 响应 items 中存在 `metadata.entry_id` == 8D-A 的 entry  
5. 审计存在 `KNOWLEDGE_SUNK`（关 8D-A）+ `KNOWLEDGE_RETRIEVED`（推 8D-B，changed_fields.entry_ids 含 A）  
6. `GET /api/knowledge/entries?product_line_code=` 可见 8D-A  

无 LLM 凭证：专用用例 assert 关闭 **422 + outcome=blocked**（与 ai-credentials guard 一致；或 skip 全文件）。  
LLM 失败路径：单测 mock 失败 → **422 + outcome=failed**，status 不变。

# OpenQMS 通用侧栏助手

日期：2026-11-22。页面范围和员工确认策略已确定。本文定义首个跨模块验收范围。已有 R5 专用任务继续从任务面板打开。当前工作树已在隔离试用环境实现 8D 页发问、同线 PFMEA 查询和确认创建草稿。

## 员工流程

员工从 OpenQMS 的右侧打开一个聊天窗口，直接输入问题或请求，无需先挑任务、插件或技能。聊天顶部可看到当前参考页及对象，例如「8D · 8D-001」。切换页面后，新问题使用新页面上下文。已经生成的操作预览仍指向原目标，并明确显示目标。

Pi 根据问题和当前可用的工具决定怎么查、是否需要另一个模块、是否要追问。结果带打开原对象的入口。当前页未经登记时，聊天仍可打开，助手可询问目标或使用已有权限的查询工具。原任务目录、运行状态和检查点仍用于查看已经发起的业务任务，放在辅助入口。

员工要求修改数据时，助手先展示可核对的操作。用户确认这一笔操作后才执行。比如创建草稿时显示目标工厂、产品线、类型、标题和单号，再提供确认与取消。若该操作还需要模块审批，确认只提交这一笔待审批操作，审批流程按模块规则继续。

## 首个可验收流程

必要工具是 CAPA 当前报告摘要、FMEA 当前产品线查询和 FMEA 草稿创建。首片在隔离数据中接入已有业务服务，通过不同自然语言输入证明模型会选择工具。

| 员工动作 | 应看到的结果 |
|---|---|
| 在 8D 页问「这是哪个产品线？同一条线有哪些 PFMEA？」 | 助手先识别当前报告，再查询 FMEA。答复列出实际查到的单据和入口。 |
| 切到一个 PFMEA 页问「这个版本是什么状态？」 | 同一聊天读取当前 PFMEA。当前页面与上一轮 8D 的对象都可区分。 |
| 要求按指定标题和单号创建 PFMEA 草稿 | 字段不足时先追问。字段齐全后显示待确认的操作，数据库里还没有草稿。 |
| 点击确认，重复点击或重试同一次确认 | 仅创建一条真实草稿。返回草稿入口及执行状态。业务审计记录当前员工和本次 Agent 操作。 |
| 预览后切换工厂、撤权或关键依据变化 | 再确认时由服务端拒绝原操作或要求重做预览。返回的旧工具结果同时按当前可见性处理。 |

## 接线边界

- **页面上下文**。浏览器按页面类型登记当前对象和可识别的显示信息。工具用模块和对象 ID 向服务端查询当前用户可看的正文或摘要。页面内容是业务数据，模型不能把其中的文字当成工具指令。第一版只覆盖 OpenQMS 已登记的页面类型，未保存输入由员工决定是否直接发进聊天。
- **聊天与业务任务**。聊天保留问题、回答、工具结果和待确认操作，业务执行仍走现有任务认证和审计边界。通用入口可按需发起已授权任务。任务完成不结束聊天。现有任务表要求固定 CAPA 外键，跨模块操作需要在现有任务权限内核上扩展类型化目标契约，并保留已绑定 CAPA 的记录和语义。旧 `/api/agent/sessions` 的通用消息接口没有这套工具级授权和来源复核。
- **技能与工具**。技能提供用途说明、适用提示和可用工具。模块为每个工具声明输入输出、读写类型、权限和审批门槛，并复用业务页面背后的服务。Pi 从按当前用户、策略和任务范围过滤过的目录选择工具。服务端在执行时再次校验权限和目标。页面 ID、模型返回的工具名或技能文本均不能授予权限。
- **读与模型交付**。模块明确哪些字段可供 Agent 读取。读取数据和发送给模型分别授权。已批准的模型部署及受控出口负责最终交付。当前页面能看到一项内容，并不自动允许把它完整发给模型。答复引用经授权的对象和来源。
- **写与确认**。服务端保存本次操作的类型、规范参数、原目标、相关来源版本和申请人，并签发操作引用。浏览器只按该引用确认。确认在当前权限与业务规则下复核后执行。草稿写入、确认幂等记录与业务审计共用事务。结果不确定时重试原确认，返回原操作的收据。
- **失败**。取消或改写请求使旧预览失效。连接失败时清除不可再验证的旧内容，提供可执行的恢复入口。拒绝读取、读取成功为空、等待确认、执行成功和执行结果未确认分别展示。

## 代码起点

- [模块化 Agent 架构](2026-09-22-modular-qms-agent-architecture-design.md) 定义能力目录、业务权限与审批责任。
- [当前 Agent 能力盘点](../../development/agent-module-capability-inventory.md) 显示主线已有 CAPA 的受控能力。FMEA 查询和创建需要登记各自的工具及衍生数据范围。IQC 检验单读取可作为后续模块接入验证。
- CAPA 摘要复用 [白名单投影](../../../backend/app/services/capa_agent_projection.py)。PFMEA 查询、草稿创建复用 [FMEA 服务](../../../backend/app/services/fmea_service.py) 和 [页面接口](../../../backend/app/api/fmea.py) 的业务约束。当前草稿创建服务内部提交，写入接入时要让它能在调用方的确认事务里完成。
- [已有 Pi 工作进程](../../../backend/examples/pi_d5_agent/worker.mjs) 演示真实模型轮次和顺序工具。它当前为 R5 注册固定工具。通用入口需要接入经过平台授权的工具目录，并把可发布的模型答复送回聊天。

实施顺序是当前页面上下文与聊天入口、真实跨模块查询、精确预览及确认写入。以同一条浏览器流程贯通这些行为为首片完成条件。

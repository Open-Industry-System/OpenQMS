**日期**: 2026-07-08

## 目标

D8 关闭后一键生成 8D 报告 PPT（标准模板，11 页），生成后由 sub-agent 依据 admin 可配置的审查 skill 自动审查内容，不通过则校正重生成，3 轮上限。LLM 未配置时跳过审查 + 提示，PPT 仍可生成。

## 非目标（本切片不做）

- 阶段性草稿 PPT（D8 关闭前生成；故事明确排除）
- PPT 模板自定义/编辑（本切片用代码定义标准模板，模板可配置为后续迭代）
- PDF/Excel 输出（本切片只做 PPT）
- 多审查 skill + 选择规则（本切片固定单 skill `capa_ppt_review`）
- sub-agent 审查的 LLM 重写内容（校正只重新查数据/修结构，不编造数据）
- 8D↔FMEA 双向收尾（01.4）、知识库沉淀（01.8）、横向扩散（01.9）

## 关键决策（来自澄清）

| 决策 | 结论 |
|---|---|
| 文件存储 | 后端流式返回 PPT bytes，前端浏览器原生下载弹窗（不落盘） |
| file_url | `capa_ppt_export` 表保留，file_url nullable 恒 None，表记元数据 |
| 生成权限 | engineer+（L2 quality_engineer 及以上） |
| 状态门控 | D8_CLOSURE + ARCHIVED 可生成 |
| 联动附录 | 列关联单号+状态 + 展开 CAPA 关联的 FMEA 节点（`fmea_ref_id` + `fmea_node_id`）详情，非全部节点 |
| version 语义 | 时间戳（= generated_at ISO 字符串） |
| 审查 skill 存储 | DB 表 `agent_review_skill`，按 `tenant_schema` 隔离 |
| 审查 skill 作用域 | 固定单 skill（`name="capa_ppt_review"` + tenant 查），admin 可改 content 不能改名/增删 |
| skill 管理权限 | 仅 admin（L5）可 CRUD |
| 审查时机 | 同步阻塞 + 自动校正循环（生成→审查→不通过则校正重生成→再审查） |
| 循环上限 | 3 轮（生成 + 2 次校正）；达上限仍不合格 → 返回最后 PPT + 审查报告（`needs_review`），不报错 |
| LLM 缺失 | 跳过 sub-agent 审查（`review_status=skipped`），PPT 仍生成（只跑内置规则校验），前端提示「大模型未配置，已跳过自动审核」 |

### 数据流

```
用户点「生成 PPT」
  → 前端 generatePpt(reportId) [blob 下载, timeout 120s]
  → 后端 POST /api/capa/{id}/ppt-export
    → 权限校验 (engineer+) + 状态门控 (D8_CLOSURE/ARCHIVED)
    → capa_ppt_service.generate_ppt() → bytes + content
    → _validate_ppt_content(content, capa)  # 内置规则校验
       → 不通过 → _correct_by_issues 重生成（不耗 LLM 轮次）；重生成后仍不通过 → 计入 LLM 审查轮次
    → 若 LLM 已配置:
        → capa_ppt_review_service.review_and_correct()  # 3 轮闭环
          → 读 AgentReviewSkill(name="capa_ppt_review", tenant=ctx.tenant_schema)
          → 构造审查 prompt = skill.content + PptContent 序列化
          → sub-agent (LLM) 审查 → {passed, issues, suggestions}
          → 不通过 → _correct_by_suggestions 重生成 → 再审查
          → 合格或达 3 轮上限 → 返回
    → 若 LLM 未配置:
        → 跳过审查，review_status=skipped
    → 写 capa_ppt_export 记录 + PPT_GENERATED 审计
    → StreamingResponse(pptx bytes, headers={X-PPT-Review-Status, X-PPT-Review-Rounds})
  → 前端浏览器下载弹窗
  → 若 review_status=skipped → message.warning("大模型未配置，已跳过自动审核")
  → 若 review_status=needs_review → message.warning("经 N 轮审核仍需人工复核")
  → 若 review_status=passed → message.success("PPT 已生成（审核通过，N 轮）")
```

    review_rounds: Mapped[int] = mapped_column(Integer, default=0, nullable=False)  # 0=未审查/跳过，1-3=审查轮数

- `version` = `generated_at` 的 ISO 字符串（时间戳作版本）
- `file_url` 恒 None（不落盘）
- `review_status`：`passed`（审查通过）/ `skipped`（LLM 未配置跳过）/ `needs_review`（3 轮上限仍不合格）
- `review_rounds`：实际审查轮数（0=未审查/跳过，1=首轮通过，2-3=校正后通过或达上限）
- `review_report`：sub-agent 审查返回的 issues + suggestions（JSONB，供审计追溯）

## PPT 生成器 + 审查闭环逻辑

### `capa_ppt_service.generate_ppt`

```python
async def generate_ppt(db: AsyncSession, capa_id: uuid.UUID) -> tuple[bytes, PptContent]:
    """从落库数据生成 8D 报告 PPT。返回 (pptx_bytes, content_struct)。
    content_struct 供内置规则校验 + sub-agent 审查（避免 sub-agent 解析二进制 pptx）。"""
```

**数据查询**（一次组装）：
- `capa` 本体（document_no/title/severity/product_line_code/status/d1_team..d8_closure/due_date/created_by/created_at）
- `CapaRootCauseVerification` 列表（D4 验证记录摘要：root_cause_text/method/result/is_verified）
- `CapaD7NodeAction` 列表（D7 node-action 摘要：failure_mode/cause/action/prevention_control_name_after）
- 关联 FMEA 节点详情（`fmea_ref_id` + `fmea_node_id` → 从 `graph_data` 提取该失效模式节点的 cause/control）
- `SupplierSCAR`（`capa_ref_id == capa_id` 反查：scar_no/status/description 摘要）
- `SupplierRiskAlert`（`linked_capa_id == capa_id` 反查：risk_level/status/snapshot_date）

**PPT 结构**（python-pptx 构建，11 页）：

| 页 | 标题 | 内容 |
|---|---|---|
| 1 | 封面 | 8D 单号、标题、严重度、产品线、发起人、状态、日期 |
| 2 | D1 团队 | d1_team JSONB → 成员姓名/角色表 |
| 3 | D2 问题描述 | d2_description 文本 |
| 4 | D3 遏制措施 | d3_interim 文本 + 受影响范围摘要（如有 d3 数据） |
| 5 | D4 根因分析 | d4_root_cause + 验证记录列表（method/result/is_verified） |
| 6 | D5 永久措施 | d5_correction 文本 |
| 7 | D6 实施验证 | d6_verification 文本 |
| 8 | D7 预防复发 | d7_prevention 文本 + node-action 列表（失效模式/处置/预防控制） |
| 9 | D8 关闭结论 | d8_closure 文本 |
| 10 | 联动附录 | 关联 FMEA 节点详情 + SCAR 单号/状态 + 供应商风险预警单号/状态 |
| 11 | 生成信息 | export_id/version/generated_at/generated_by/review_status |

### `capa_ppt_review_service.review_and_correct`（3 轮闭环）

```python
async def review_and_correct(
    db: AsyncSession, capa_id: uuid.UUID, ctx: AgentContext
) -> tuple[bytes, PptContent, ReviewResult]:
    """生成 → 审查 → 校正闭环，3 轮上限。"""
    bytes_ppt, content = await generate_ppt(db, capa_id)
    review_result = ReviewResult(status="skipped", rounds=0, report=None)

    # 1. 内置规则校验（不耗 LLM 轮次）
    rule_issues = _validate_ppt_content(content, capa)
    if rule_issues:
        bytes_ppt, content = await _correct_by_issues(db, capa_id, rule_issues)

    # 2. LLM 审查闭环（3 轮上限）
    if not ctx.llm_available:
        return bytes_ppt, content, ReviewResult("skipped", 0, None)  # 前端提示「大模型未配置」

    skill = await agent_review_skill_service.get_by_name(ctx.tenant_schema, "capa_ppt_review")
    for round_idx in range(1, 4):  # 1,2,3
        review = await _subagent_review(db, ctx, skill, content)
        if review.passed:
            return bytes_ppt, content, ReviewResult("passed", round_idx, review.report)
        if round_idx < 3:
            bytes_ppt, content = await _correct_by_suggestions(db, capa_id, review.suggestions)
        else:
            return bytes_ppt, content, ReviewResult("needs_review", 3, review.report)
```

**`_subagent_review`**（sub-agent 审查，调 LLM）：

```python
async def _subagent_review(db, ctx, skill, content) -> ReviewOutcome:
    """构造审查 prompt = skill.content + PptContent 序列化 → LLM → 解析 {passed, issues, suggestions}。"""
    prompt = f"{skill.content}\n\n--- 待审查 PPT 内容 ---\n{serialize_content(content)}"
    result = await provider_adapter.complete_json(ctx.pc, prompt, schema=REVIEW_SCHEMA)
    return ReviewOutcome(passed=result["passed"], issues=result["issues"], suggestions=result["suggestions"])
```

**`_correct_by_suggestions`**（按审查反馈校正）：

校正语义：PPT 内容来自落库数据，**不是 LLM 重写内容**。sub-agent 的 suggestions 指向「哪页缺什么字段/哪个值与落库数据不符」→ 校正 = 重新查数据 + 补到 PptContent + 重生成 pptx。若 suggestion 指向「落库数据本身缺失」（如 d2_description 为空），则**无法校正**（数据源问题，非 PPT 生成问题）→ 计入 issues，继续轮次。

```python
async def _correct_by_suggestions(db, capa_id, suggestions) -> tuple[bytes, PptContent]:
    """按 suggestions 重新查数据/修结构 → 重生成。suggestion 指向数据源缺失则跳过（记 issue）。"""
    return await generate_ppt(db, capa_id)
```

### API 端点

```python
@router.post("/{report_id}/ppt-export")
async def export_ppt(
    report_id: uuid.UUID,
    db: AsyncSession = Depends(get_db),
    scope: RequestScope = Depends(get_request_scope),
):
    capa = await capa_service.get_capa(db, report_id)
    if capa is None: raise HTTPException(404)
    check_factory_access(capa.factory_id, scope)
    # 权限：engineer+
    level = await get_user_permission(scope.user, Module.CAPA, db)
    if level < PermissionLevel.EDIT: raise HTTPException(403)
    # 状态门控：D8_CLOSURE / ARCHIVED
    if capa.status not in (EightDState.D8_CLOSURE.value, EightDState.ARCHIVED.value):
        raise HTTPException(400, "8D 未关闭，不可生成 PPT")

    ctx = build_agent_context(db, scope)  # 含 llm_available + pc + tenant_schema
    bytes_ppt, content, review = await capa_ppt_review_service.review_and_correct(db, report_id, ctx)

    # 写 capa_ppt_export + PPT_GENERATED 审计
    export = await _record_export(db, capa, scope, review)

    # 响应头带审查状态（前端据此提示）
    headers = {"X-PPT-Review-Status": review.status, "X-PPT-Review-Rounds": str(review.rounds)}
    return pptx_response(bytes_ppt, f"8D_{capa.document_no}_{export.version}.pptx", headers)
```

**`pptx_response`**（仿 `excel_response`）：

```python
def pptx_response(pptx_bytes: bytes, filename: str, headers: dict = None) -> StreamingResponse:
    encoded = urllib.parse.quote(filename)
    return StreamingResponse(
        BytesIO(pptx_bytes),
        media_type="application/vnd.openxmlformats-officedocument.presentationml.presentation",
        headers={"Content-Disposition": f"attachment; filename*=UTF-8''{encoded}", **(headers or {})},
    )
```

**`frontend/src/api/capa.ts`**（加下载函数）：

```ts
export async function generatePpt(reportId: string): Promise<{ reviewStatus: string; reviewRounds: number }> {
  const resp = await client.post(`/capa/${reportId}/ppt-export`, {}, {
    responseType: "blob",
    timeout: 120000,  // 生成 + 最多 3 轮 LLM 审查
  });
  const reviewStatus = resp.headers["x-ppt-review-status"] || "skipped";
  const reviewRounds = parseInt(resp.headers["x-ppt-review-rounds"] || "0", 10);
  // 浏览器原生下载弹窗
  const blob = new Blob([resp.data]);
  const url = window.URL.createObjectURL(blob);
  const link = document.createElement("a");
  link.href = url;
  link.setAttribute("download", resp.headers["content-disposition"]?.match(/filename\*=UTF-8''(.+)/)?.[1]
    ? decodeURIComponent(RegExp.$1) : `8D_report_${reportId}.pptx`);
  document.body.appendChild(link);
  link.click();
  link.remove();
  window.URL.revokeObjectURL(url);
  return { reviewStatus, reviewRounds };
}
```

## 错误处理

| 场景 | 处理 |
|---|---|
| CAPA 不存在 | 404 |
| 跨工厂访问 | 403（`check_factory_access`） |
| 权限不足（< engineer） | 403 |
| 状态未关闭（非 D8_CLOSURE/ARCHIVED） | 400「8D 未关闭，不可生成 PPT」 |
| 关联 FMEA 节点查不到（`fmea_ref_id` 指向已删 FMEA） | 附录页标「关联 FMEA 已删除」，不阻断生成（数据降级，非错误） |
| 关联 SCAR/风险预警查不到 | 附录页跳过该项（无关联是正常态，非错误） |
| 内置规则校验不通过（如 d2_description 空） | 校正轮次内补；若数据源本身缺失（字段空）→ 计 issue，不阻断，PPT 该页标「待补充」 |
| LLM 未配置 | 跳过审查，`review_status=skipped`，响应头 `X-PPT-Review-Status: skipped`，前端提示 |
| LLM 审查 3 轮仍不合格 | `review_status=needs_review`，返回最后 PPT + 审查报告，前端提示「需人工复核」 |
| LLM 调用异常（超时/解析失败） | 该轮计失败，继续下一轮；3 轮全失败 → `needs_review`，不报错（PPT 仍返回） |
| python-pptx 生成异常 | 500（生成失败，非数据问题） |
| admin 改 skill content 为空 | 400「审查标准不可为空」 |

## 风险与取舍

- **sub-agent 审查依赖 LLM**：故事 01.10 标 `AI_REQUIRED=false`（PPT 生成本身非 AI），但 sub-agent 审查需 LLM。无 LLM 时跳过审查 + 提示，PPT 仍可生成——符合故事契约（生成不卡 LLM）。
- **3 轮上限的「needs_review」**：达上限返回最后 PPT + 审查报告，不报错。用户拿到 PPT 但知需人工复核——可接受，避免死循环。
- **校正语义**：PPT 内容来自落库数据，校正 = 重新查数据 + 修结构，**非 LLM 重写内容**。若 suggestion 指向数据源缺失（如 d2_description 空），无法校正——计 issue 继续。这是正确语义：PPT 生成器不编造数据。
- **`PptContent` dataclass**：单使用方（审查），但避免 sub-agent 解析二进制 pptx（成本高且不稳定）。是合理的中间层，非过度抽象。
- **审查 skill 固定单 skill**：本切片只支持 `capa_ppt_review`。admin 可改 content 不能增删——YAGNI，多 skill 选择规则留后续。
- **`python-pptx` 依赖**：纯 Python + wheel，无系统库。`Pillow` 是其依赖，与项目无冲突。
- **响应时间**：生成 + 最多 3 轮 LLM 审查，前端 timeout 120s。可接受——PPT 生成是低频操作。
- **审查 skill 按 tenant 隔离**：与 SaaS 多租户一致。单租户场景 `tenant_schema=NULL`，seed 全局默认 skill。
- **与状态机切片并行**：01.10 不碰 `eightd_state.py` / `advance_capa` / `capa_service` 状态机相关文件，只读 `capa.status` 做门控（D8_CLOSURE/ARCHIVED）。与 01.3 状态机切片无冲突，可并行开发。

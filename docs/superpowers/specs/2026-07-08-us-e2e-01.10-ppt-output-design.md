## 目标

D8 关闭后一键生成 8D 报告 PPT（标准模板，11 页），生成后由 sub-agent 依据 admin 可配置的审查 skill 自动审查内容，不通过则校正重生成，3 轮上限。LLM 未配置时跳过审查 + 提示，PPT 仍可生成。

## 非目标（本切片不做）

- 阶段性草稿 PPT（D8 关闭前生成；故事明确排除）
- PPT 模板自定义/编辑（本切片用代码定义标准模板，模板可配置为后续迭代）
- PDF/Excel 输出（本切片只做 PPT）
- 多审查 skill + 选择规则（本切片固定单 skill `capa_ppt_review`）
- sub-agent 审查的 LLM 重写内容（校正只重新查数据/修结构，不编造数据）
- 8D↔FMEA 双向收尾（01.4）、知识库沉淀（01.8）、横向扩散（01.9）

## 关键决策（来自澄清）

| 决策 | 结论 |
|---|---|
| 文件存储 | 后端流式返回 PPT bytes，前端浏览器原生下载弹窗（不落盘） |
| file_url | `capa_ppt_export` 表保留，file_url nullable 恒 None，表记元数据 |
| 生成权限 | engineer+（L2 quality_engineer 及以上） |
| 状态门控 | D8_CLOSURE + ARCHIVED 可生成 |
| 联动附录 | 列关联单号+状态 + 展开 CAPA 关联的 FMEA 节点（`fmea_ref_id` + `fmea_node_id`）详情，非全部节点 |
| version 语义 | 时间戳（`YYYYMMDDTHHMMSSZ` 格式，如 `20260708T143022Z`；安全文件名，无冒号，Windows 友好） |
| 审查 skill 存储 | DB 表 `agent_review_skill`，按 `tenant_schema` 隔离 |
| 审查 skill 作用域 | 固定单 skill（`name="capa_ppt_review"` + tenant 查），admin 可改 content 不能改名/增删 |
| skill 管理权限 | 仅 admin（L5）可 CRUD |
| 审查时机 | 同步阻塞 + 自动校正循环（生成→审查→不通过则校正重生成→再审查） |
| 循环上限 | 3 轮（生成 + 2 次校正）；达上限仍不合格 → 返回最后 PPT + 审查报告（`needs_review`），不报错 |
| LLM 缺失 | 跳过 sub-agent 审查（`review_status=skipped`），PPT 仍生成（只跑内置规则校验），前端提示「大模型未配置，已跳过自动审核」 |

### 数据流

```
用户点「生成 PPT」
  → 前端 generatePpt(reportId) [blob 下载, timeout 120s]
  → 后端 POST /api/capa/{id}/ppt-export
    → 权限校验 (engineer+) + 状态门控 (D8_CLOSURE/ARCHIVED)
    → 预生成 export 元数据：export_id(uuid4) / generated_at(now) / version(generated_at 的 YYYYMMDDTHHMMSSZ) / generated_by
    → 解析 LLM provider client（沿用 management_review 模式）：
        try: pc = await provider_adapter.build_client(db)
        except ProviderNotConfiguredError: pc = None  # LLM 未配置
    → capa_ppt_review_service.review_and_correct(db, capa_id, pc, tenant_schema)
        → 内部：generate_content() 组装 PptContent（**不渲染 pptx**）
        → _validate_ppt_content() 内置规则校验
           → 不通过 → _correct_by_issues 重组 content（不耗 LLM 轮次）；重生成后仍不通过 → 计入 LLM 审查轮次
        → 若 pc is None (LLM 未配置):
            → review = ReviewResult("skipped", 0, None)
        → 否则 3 轮 LLM 审查闭环：
            → 读 AgentReviewSkill(name="capa_ppt_review", tenant=tenant_schema)（未命中回退 'public'）
            → 构造审查 prompt = skill.content + PptContent 序列化
            → sub-agent (LLM) 审查 → {passed, issues, suggestions}
            → 不通过 → _correct_by_suggestions 重组 content → 再审查
            → 合格或达 3 轮上限 → 返回 (content, ReviewResult)
        → **返回 (content, review)，不渲染 pptx**
    → 最终渲染一次：capa_ppt_service.render_pptx(content, meta, review.status, review.rounds) → bytes
       （第 11 页「生成信息」此时 review_status 已知，直接渲染，无需回填/替换单页）
    → 写 capa_ppt_export 记录（含 review_status/review_rounds/review_report）+ PPT_GENERATED 审计
    → StreamingResponse(pptx bytes, headers={X-PPT-Review-Status, X-PPT-Review-Rounds, X-PPT-Export-Id})
  → 前端浏览器下载弹窗
  → 若 review_status=skipped → message.warning("大模型未配置，已跳过自动审核")
  → 若 review_status=needs_review → message.warning("经 N 轮审核仍需人工复核") + 提供「查看审查报告」入口（调 GET /api/capa/{id}/ppt-exports/{export_id}）
  → 若 review_status=passed → message.success("PPT 已生成（审核通过，N 轮）")
```

> **第 11 页「生成信息」时序**：export_id/version/generated_at/generated_by 在审查前预生成（uuid4 + now，不依赖 DB insert）；review_status/review_rounds 审查完成后才知。因为最终 pptx 在审查结束后**只渲染一次**（`render_pptx`），第 11 页用已知 review_status 直接渲染——**无需「单页替换」复杂能力**。审查过程只操作 `PptContent`（数据结构），不触碰 pptx。

## 数据模型与迁移

### `capa_ppt_export`（PPT 生成记录）

```python
class CapaPptExport(Base):
    __tablename__ = "capa_ppt_export"
    export_id: Mapped[uuid.UUID] = mapped_column(UUID(as_uuid=True), primary_key=True, default=uuid.uuid4)
    capa_id: Mapped[uuid.UUID] = mapped_column(UUID(as_uuid=True), ForeignKey("capa_eightd.report_id", ondelete="CASCADE"), nullable=False)
    factory_id: Mapped[uuid.UUID] = mapped_column(UUID(as_uuid=True), ForeignKey("factories.id", ondelete="RESTRICT"), nullable=False)
    tenant_schema: Mapped[str | None] = mapped_column(String(63))
    generated_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now())
    generated_by: Mapped[uuid.UUID] = mapped_column(UUID(as_uuid=True), ForeignKey("users.user_id"), nullable=False)
    version: Mapped[str] = mapped_column(String(40), nullable=False)        # = generated_at 的 YYYYMMDDTHHMMSSZ 格式（安全文件名）
    file_url: Mapped[str | None] = mapped_column(String(500), nullable=True)  # 恒 None（不落盘）
    review_status: Mapped[str] = mapped_column(String(20), default="skipped", nullable=False)  # passed/skipped/needs_review
    review_rounds: Mapped[int] = mapped_column(Integer, default=0, nullable=False)  # 0=未审查/跳过，1-3=审查轮数
    review_report: Mapped[dict | None] = mapped_column(JSONB, nullable=True)  # {issues, suggestions} 或 None
    created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now())
```

- `version` = `generated_at` 的 `YYYYMMDDTHHMMSSZ` 格式（时间戳作版本；安全文件名，无冒号，Windows 友好）
- `file_url` 恒 None（不落盘）
- `review_status`：`passed`（审查通过）/ `skipped`（LLM 未配置跳过）/ `needs_review`（3 轮上限仍不合格）
- `review_rounds`：实际审查轮数（0=未审查/跳过，1=首轮通过，2-3=校正后通过或达上限）
- `review_report`：sub-agent 审查返回的 issues + suggestions（JSONB，供审计追溯）

### `agent_review_skill`（审查 skill，admin 管理）

```python
class AgentReviewSkill(Base):
    __tablename__ = "agent_review_skill"
    skill_id: Mapped[uuid.UUID] = mapped_column(UUID(as_uuid=True), primary_key=True, default=uuid.uuid4)
    tenant_schema: Mapped[str | None] = mapped_column(String(63))  # 按租户隔离；'public' = 全局默认（seed）
    name: Mapped[str] = mapped_column(String(64), nullable=False)  # 固定 "capa_ppt_review"
    content: Mapped[str] = mapped_column(Text, nullable=False)      # 审查标准/剧本（admin 可改）
    version: Mapped[int] = mapped_column(Integer, default=1, nullable=False)  # 每次更新 +1
    is_active: Mapped[bool] = mapped_column(Boolean, default=True, nullable=False)
    updated_by: Mapped[uuid.UUID | None] = mapped_column(UUID(as_uuid=True), ForeignKey("users.user_id"))
    updated_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now(), onupdate=func.now())
    created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now())

    # 唯一性由迁移中的 COALESCE 表达式唯一索引保证（防多个 NULL 全局默认），
    # 不在 ORM __table_args__ 重复声明 UniqueConstraint（NULL != NULL 会漏防）。
```

- `name + COALESCE(tenant_schema, '')` 唯一（固定单 skill）。PostgreSQL 中 `NULL != NULL`，多个 `tenant_schema=NULL` 行不违反 `UniqueConstraint(tenant_schema, name)`，故用 `COALESCE` 列上的唯一索引或 partial index 实现防重（见迁移）。
- `version` 每次 admin 更新 +1（供审计追溯用了哪版 skill 审查）
- `is_active` 软删（固定单 skill 场景下一般恒 True）

#### skill 查找的 tenant 回退

审查时按当前请求 `tenant_schema` 查；无命中（该租户未自定义）→ 回退到 `tenant_schema='public'` 的全局默认 skill（seed）。即 `get_by_name` 先按 `tenant AND name` 查，未命中再按 `name AND tenant_schema='public'` 查。seed 的全局默认 skill `tenant_schema='public'`（非 NULL），保证可被回退查到且被唯一索引保护。

## PPT 生成器 + 审查闭环逻辑

### `capa_ppt_service.generate_content` + `render_pptx`（职责分离）

审查只操作 `PptContent` 数据结构，最终 pptx 在审查后**只渲染一次**——避免审查中反复渲染 pptx + 避免「单页替换」复杂能力。

```python
async def generate_content(db: AsyncSession, capa_id: uuid.UUID) -> PptContent:
    """从落库数据组装 PptContent（不渲染 pptx）。供内置规则校验 + sub-agent 审查。"""

def render_pptx(
    content: PptContent,
    meta: ExportMeta,          # export_id/version/generated_at/generated_by
    review_status: str,        # passed/skipped/needs_review
    review_rounds: int,
) -> bytes:
    """从 PptContent + meta + review 一次性渲染最终 pptx（python-pptx）。
    第 11 页「生成信息」用已知 review_status 直接渲染，无需回填。"""
```

`ExportMeta` dataclass：`export_id: uuid.UUID, version: str, generated_at: datetime, generated_by: uuid.UUID`。

**数据查询**（一次组装）：
- `capa` 本体（document_no/title/severity/product_line_code/status/d1_team..d8_closure/due_date/created_by/created_at）
- `CapaRootCauseVerification` 列表（D4 验证记录摘要：root_cause_text/method/result/is_verified/evidence_attachments）。evidence_attachments 是 JSONB 数组（`[{filename, content_type, ...}]`），PPT 列每条验证记录的附件引用（文件名 + 类型 + 所属 D4；不内嵌文件二进制，仅引用清单）。
- `CapaD7NodeAction` 列表（D7 node-action 摘要：failure_mode/cause/action/prevention_control_name_after）
- 关联 FMEA 节点详情（`fmea_ref_id` + `fmea_node_id` → 从 `graph_data` 提取该失效模式节点的 cause/control）
- `SupplierSCAR`（`capa_ref_id == capa_id` 反查：scar_no/status/description 摘要）
- `SupplierRiskAlert`（`linked_capa_id == capa_id` 反查：risk_level/status/snapshot_date）

### `capa_ppt_review_service.review_and_correct`（3 轮闭环）

只返回 `(PptContent, ReviewResult)`，**不渲染 pptx**——最终渲染统一在 API 层做一次（避免审查中反复渲染 + 避免「单页替换」复杂能力）。`pc=None` 表示 LLM 未配置（沿用 `try: build_client / except ProviderNotConfiguredError: pc=None` 模式）。`tenant_schema` 来自 `tenant_schema(request)`（`app/core/tenant.py:12`，非 `RequestScope` 字段——`RequestScope` 无此字段）。

```python
@dataclass
class ReviewOutcome:
    passed: bool
    issues: list[str]
    suggestions: list[str]
    @property
    def report(self) -> dict:
        return {"issues": self.issues, "suggestions": self.suggestions}

@dataclass
class ReviewResult:
    status: str           # passed/skipped/needs_review
    rounds: int           # 0=未审查/跳过，1-3=审查轮数
    report: dict | None   # {"issues": [...], "suggestions": [...]} 或 None（skipped 时）

async def review_and_correct(
    db: AsyncSession, capa_id: uuid.UUID, pc, tenant_schema: str
) -> tuple[PptContent, ReviewResult]:
    """生成 → 审查 → 校正闭环，3 轮上限。pc=None 表示 LLM 未配置。返回 (content, review)，不渲染 pptx。"""
    content = await capa_ppt_service.generate_content(db, capa_id)

    # 1. 内置规则校验（不耗 LLM 轮次）
    rule_issues = capa_ppt_service._validate_ppt_content(content, capa)
    if rule_issues:
        content = await _correct_by_issues(db, capa_id, rule_issues)

    # 2. LLM 未配置 → 跳过审查
    if pc is None:
        return content, ReviewResult("skipped", 0, None)

    # 3. LLM 审查闭环（3 轮上限）
    skill = await agent_review_skill_service.get_by_name(db, tenant_schema, "capa_ppt_review")
    last_report: dict = {"issues": [], "suggestions": []}
    for round_idx in range(1, 4):  # 1,2,3
        try:
            review = await _subagent_review(db, pc, skill, content)
        except Exception:
            # LLM 调用异常（超时/解析失败）→ 该轮计失败，继续下一轮
            review = ReviewOutcome(passed=False, issues=["LLM 调用异常"], suggestions=[])
        last_report = review.report  # 每轮更新，最终需人工复核时用最后一轮报告
        if review.passed:
            return content, ReviewResult("passed", round_idx, last_report)
        if round_idx < 3:
            content = await _correct_by_suggestions(db, capa_id, review.suggestions)
        else:
            return content, ReviewResult("needs_review", 3, last_report)
```

> **`ReviewOutcome.report` / `ReviewResult.report` 统一为 `{"issues": [...], "suggestions": [...]}`**：`ReviewOutcome.report` 是 property 组装该结构；`ReviewResult.report` 存同结构 dict（skipped 时 None）。API 层 `review.report` 写入 `capa_ppt_export.review_report` + 前端经 `GET /ppt-exports/{id}` 回读展示。

**`_subagent_review`**（sub-agent 审查，调 LLM）——`complete_json` 实际签名为 `complete_json(pc, prompt, response_schema)`（位置参数，第三参数名 `response_schema` 非 `schema`，见 `provider_adapter.py:155`）：

```python
REVIEW_SCHEMA = {
    "type": "object",
    "properties": {
        "passed": {"type": "boolean"},
        "issues": {"type": "array", "items": {"type": "string"}},
        "suggestions": {"type": "array", "items": {"type": "string"}},
    },
    "required": ["passed", "issues", "suggestions"],
}

async def _subagent_review(db, pc, skill, content) -> ReviewOutcome:
    """构造审查 prompt = skill.content + PptContent 序列化 → LLM → 解析。"""
    prompt = f"{skill.content}\n\n--- 待审查 PPT 内容 ---\n{serialize_content(content)}"
    result = await provider_adapter.complete_json(pc, prompt, REVIEW_SCHEMA)  # 注意：response_schema，非 schema=
    return ReviewOutcome(passed=result["passed"], issues=result["issues"], suggestions=result["suggestions"])
```

**`_correct_by_suggestions`**（按审查反馈校正）：

校正语义：PPT 内容来自落库数据，**不是 LLM 重写内容**。sub-agent 的 suggestions 指向「哪页缺什么字段/哪个值与落库数据不符」→ 校正 = 重新查数据 + 修 PptContent 结构（**重组 content，不渲染 pptx**——pptx 只在 API 层最终渲染一次）。若 suggestion 指向「落库数据本身缺失」（如 d2_description 为空），则**无法校正**（数据源问题，非 PPT 生成问题）→ 计入 issues，继续轮次。

```python
async def _correct_by_suggestions(db, capa_id, suggestions) -> PptContent:
    """按 suggestions 重新查数据/修结构 → 重组 PptContent（不渲染 pptx）。
    suggestion 指向数据源缺失则跳过（记 issue）。返回更新后的 content。"""
    return await capa_ppt_service.generate_content(db, capa_id)
```

`_correct_by_issues` 同理——重组 `PptContent`，返回 `PptContent`（不渲染 pptx）。

```python
@router.post("/{report_id}/ppt-export")
async def export_ppt(
    report_id: uuid.UUID,
    request: Request,                          # 用于解析 tenant_schema
    db: AsyncSession = Depends(get_db),
    scope: RequestScope = Depends(get_request_scope),
):
    capa = await capa_service.get_capa(db, report_id)
    if capa is None: raise HTTPException(404)
    check_factory_access(capa.factory_id, scope)
    # 权限：engineer+
    level = await get_user_permission(scope.user, Module.CAPA, db)
    if level < PermissionLevel.EDIT: raise HTTPException(403)
    # 状态门控：D8_CLOSURE / ARCHIVED
    if capa.status not in (EightDState.D8_CLOSURE.value, EightDState.ARCHIVED.value):
        raise HTTPException(400, "8D 未关闭，不可生成 PPT")

    # 预生成 export 元数据（不依赖 DB insert，第 11 页可直接渲染）
    export_id = uuid.uuid4()
    generated_at = datetime.now(UTC)
    version = generated_at.strftime("%Y%m%dT%H%M%SZ")  # 安全文件名（无冒号，Windows 友好）
    tenant = tenant_schema(request)

    # 解析 LLM provider client（None = 未配置）
    try:
        pc = await provider_adapter.build_client(db)
    except provider_adapter.ProviderNotConfiguredError:
        pc = None

    content, review = await capa_ppt_review_service.review_and_correct(
        db, report_id, pc, tenant
    )

    # 最终渲染一次（审查后，review.status 已知，第 11 页直接渲染）
    meta = ExportMeta(export_id=export_id, version=version, generated_at=generated_at, generated_by=scope.user.user_id)
    bytes_ppt = capa_ppt_service.render_pptx(content, meta, review.status, review.rounds)

    # 写 capa_ppt_export 记录 + PPT_GENERATED 审计
    await _record_export(db, capa, scope, export_id, generated_at, version, tenant, review)

    # 响应头带审查状态 + export_id（前端据此查审查报告，见 #5）
    headers = {
        "X-PPT-Review-Status": review.status,
        "X-PPT-Review-Rounds": str(review.rounds),
        "X-PPT-Export-Id": str(export_id),
    }
    return pptx_response(bytes_ppt, f"8D_{capa.document_no}_{version}.pptx", headers)
```

```ts
export async function generatePpt(reportId: string): Promise<{ reviewStatus: string; reviewRounds: number; exportId: string | null }> {
  const resp = await client.post(`/capa/${reportId}/ppt-export`, {}, {
    responseType: "blob",
    timeout: 120000,  // 生成 + 最多 3 轮 LLM 审查
  });
  const reviewStatus = resp.headers["x-ppt-review-status"] || "skipped";
  const reviewRounds = parseInt(resp.headers["x-ppt-review-rounds"] || "0", 10);
  const exportId = resp.headers["x-ppt-export-id"] || null;  // 查审查报告用
  // 浏览器原生下载弹窗（version=YYYYMMDDTHHMMSSZ，文件名安全无冒号）
  const blob = new Blob([resp.data]);
  const url = window.URL.createObjectURL(blob);
  const link = document.createElement("a");
  link.href = url;
  link.setAttribute("download", resp.headers["content-disposition"]?.match(/filename\*=UTF-8''(.+)/)?.[1]
    ? decodeURIComponent(RegExp.$1) : `8D_report_${reportId}.pptx`);
  document.body.appendChild(link);
  link.click();
  link.remove();
  window.URL.revokeObjectURL(url);
  return { reviewStatus, reviewRounds, exportId };
}

// 查审查报告（needs_review 时前端展示 issues + suggestions）
export async function getPptExportReviewReport(reportId: string, exportId: string): Promise<{ reviewReport: any }> {
  const resp = await client.get(`/capa/${reportId}/ppt-exports/${exportId}`);
  return { reviewReport: resp.data.review_report };
}
```

## 错误处理

| 场景 | 处理 |
|---|---|
| CAPA 不存在 | 404 |
| 跨工厂访问 | 403（`check_factory_access`） |
| 权限不足（< engineer） | 403 |
| 状态未关闭（非 D8_CLOSURE/ARCHIVED） | 400「8D 未关闭，不可生成 PPT」 |
| 关联 FMEA 节点查不到（`fmea_ref_id` 指向已删 FMEA） | 附录页标「关联 FMEA 已删除」，不阻断生成（数据降级，非错误） |
| 关联 SCAR/风险预警查不到 | 附录页跳过该项（无关联是正常态，非错误） |
| 内置规则校验不通过（如 d2_description 空） | 校正轮次内补；若数据源本身缺失（字段空）→ 计 issue，不阻断，PPT 该页标「待补充」 |
| LLM 未配置 | 跳过审查，`review_status=skipped`，响应头 `X-PPT-Review-Status: skipped`，前端提示 |
| LLM 审查 3 轮仍不合格 | `review_status=needs_review`，返回最后 PPT + 审查报告，前端提示「需人工复核」 |
| LLM 调用异常（超时/解析失败） | 该轮计失败，继续下一轮；3 轮全失败 → `needs_review`，不报错（PPT 仍返回） |
| python-pptx 生成异常 | 500（生成失败，非数据问题） |
| admin 改 skill content 为空 | 400「审查标准不可为空」 |

## 风险与取舍

- **sub-agent 审查依赖 LLM**：故事 01.10 标 `AI_REQUIRED=false`（PPT 生成本身非 AI），但 sub-agent 审查需 LLM。无 LLM 时跳过审查 + 提示，PPT 仍可生成——符合故事契约（生成不卡 LLM）。
- **3 轮上限的「needs_review」**：达上限返回最后 PPT + 审查报告，不报错。用户拿到 PPT 但知需人工复核——可接受，避免死循环。
- **校正语义**：PPT 内容来自落库数据，校正 = 重新查数据 + 修结构，**非 LLM 重写内容**。若 suggestion 指向数据源缺失（如 d2_description 空），无法校正——计 issue 继续。这是正确语义：PPT 生成器不编造数据。
- **`PptContent` dataclass**：单使用方（审查），但避免 sub-agent 解析二进制 pptx（成本高且不稳定）。是合理的中间层，非过度抽象。
- **审查 skill 固定单 skill**：本切片只支持 `capa_ppt_review`。admin 可改 content 不能增删——YAGNI，多 skill 选择规则留后续。
- **`python-pptx` 依赖**：纯 Python + wheel，无系统库。`Pillow` 是其依赖，与项目无冲突。
- **响应时间**：生成 + 最多 3 轮 LLM 审查，前端 timeout 120s。可接受——PPT 生成是低频操作。
- **审查 skill 按 tenant 隔离**：与 SaaS 多租户一致。单租户场景 `tenant_schema='public'`（seed 全局默认），多租户各自可自定义覆盖。
- **与状态机切片并行**：01.10 不碰 `eightd_state.py` / `advance_capa` / `capa_service` 状态机相关文件，只读 `capa.status` 做门控（D8_CLOSURE/ARCHIVED）。与 01.3 状态机切片无冲突，可并行开发。

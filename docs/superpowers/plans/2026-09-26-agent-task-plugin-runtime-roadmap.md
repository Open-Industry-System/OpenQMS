## 顺序与交付门槛

| 切片 | 独立交付物 | 进入下一片的必要证据 |
|---|---|---|
| R0 设计与基线 | 审核任务/插件设计、确认 PR #24 权限内核作为依赖；冻结 HTTP v1、首版 Python SDK、任务/运行/消息 ID 与租户凭据契约 | 接口规格经过评审；与现有 `AgentSession`/`gateway` 并行而无第二条无门禁写路径 |
| R1 持久任务骨架 | 租户内任务、运行、排队消息、插件安装与授权；任务创建/列表/详情/追加消息；每轮固定插件版本。**不建事件、检查点或结果表** | 创建、列表、详情、追加均重查 CAPA VIEW、身份与对象范围；撤权后无任务内容；目标能力授权不覆盖报告时保持阻塞；幂等消息顺序与新会话持久化 |
| R2 独立插件只读接入 | 受控插件容器＋Python SDK；运行租约与短期凭据；能力发现、8D D4/D5 脱敏上下文与按需查询；**事件与结构化分析结果在保存时附服务端验证的来源/敏感等级**，并提供受来源约束的读取服务；外发门禁 | 真正独立进程多轮只读分析；跨工厂在执行身份×插件授权内可读，跨模块分别授权；缺来源或跨模块无权读结果时拒绝；禁用插件/撤权后下一调用拒绝；无业务写入 |
| R3 侧栏与运行控制 | 统一侧栏、排队/已采纳消息、进度/来源/分析结果、只读检查点；后台运行、暂停/恢复、可选恢复引用 | 页面切换不改变目标 8D；仅发起者追加指令；员工首次查看结果前同时校验当前任务与每个来源模块的权限和敏感等级，不满足则隐藏结果而非仅凭任务可见；消息排序/重连去重，暂停后无新工具调用 |
| R4a 元数据本地受控试用 | 精确部署策略、正常 grant/任务配置、到期/凭据绑定、永久撤销与固定启动器 | 不替换规范目录或交付策略的真实配置验收；独立进程/浏览器、当前权限和撤销竞态通过；可信本地主机、回环、无模型 |
| R4b 任务资料与只读发布门禁 | 正文脱敏、受控附件存储/扫描/分类、通用 SDK 与生产可信部署 | 文件入模前独立外发判断；复验 R2/R3 来源限制、无全局搜索；部署隔离/网络与模型外发经实测；不满足则继续禁用上传/原文投递和生产开放 |
| R5 写入与补偿 | 8D 结构化候选、措施、修订；业务操作账本；一次性跨业务授权；审批、幂等、预写检查点、撤销预览、冲突/部分回滚和新运行 | 每个操作都通过所属模块服务；不能自批/复用批准/覆盖人工修改；旧运行不可复活；回滚状态与实际业务一致 |
| R6 正式替换 | 完整分析—建议—采纳—回滚验收后替换旧 D4/D5 推荐用户入口；旧实现仅作为部署回退 | 无双入口权限旁路；未完成任务有明确处理；业务模型与回退版本兼容；审批和审计一致 |
| R7 逐模块推广 | 对 FMEA、IQC、供应商等逐项定义所属模块的上下文/命令、脱敏和最低审批，按样板契约接入 | 第二个插件能接续业务产物；跨模块/租户/工厂与派生敏感等级回归通过 |

R0 同时冻结逻辑检查点 `(task_id, run_id, accepted_message_seq, source_versions, operation_refs, plugin_resume_ref)`，及分析结果的候选根因/支持与反对证据/缺失信息/条件措施/来源版本结构。R1 只定义逻辑关系，不建事件/结果/检查点表，也不建立可误导用户的“回滚”按钮；R2 建事件和结果表并保存来源限制，R3 落地只读检查点，R5 才填充业务操作账本与补偿。

推荐依赖：R0 → R1 → R2 → R3 → R4a → R4b → R5 → R6 → R7。R1 的后端队列与 R3 的侧栏静态交互可并行开发，但运行接线和验收仍按依赖顺序。R5、R6、R7 各自另写独立实施计划，不能从本路线直接开始改代码。

## 首片实施计划与明确取舍

[R1 任务/插件基础运行时实施计划](2026-09-26-agent-task-plugin-runtime-foundation.md)详细列出第一独立切片的文件、接口、RED/GREEN 步骤与验收。R2 工具/只读证据、R3 侧栏/控制分别成计划，在 R1 契约和凭据通过评审后编写。本轮评审已认可 **HTTP JSON v1＋后续 Python SDK＋R1 持久消息队列/R2 事件队列＋独立短期运行令牌**；前端按游标轮询是 R3 的建议实现，MCP/SSE 仍只作为后续适配层，不另造业务规则。五分钟令牌有效期仅为可配置初值，每次请求仍检查当前权限、插件状态和运行有效性。示例插件在受控网络内运行，首版不向外部模型传数据，也不依赖模型凭据即可验收。

R2 保存结构化分析结果时，由平台把已返回证据的 `(来源模块, 对象 ID, 版本, 敏感等级)` 绑定到结果；缺来源或无法判定的自由文本保守限制，不接受插件自报“已降敏”。R2 的结果读取服务须同时校验当前任务/目标 8D 权限与各来源模块对应敏感等级的权限（沿用 `can_view_derived` 语义），无权时不返回内容、摘要或命中数量；结果默认不入统一搜索。R3 侧栏只调用该受控读取服务，首次展示及撤权后的再次读取均做检查，不能以任务可见代替来源可见。验收用“CAPA 可见、供应商受限来源不可见”及中途撤权两种场景；R4a 补齐元数据本地试用配置与撤销，R4b 负责资料及生产发布复验。

只读切片只写平台任务/运行/分析结果，不修改 8D 业务对象。任务普通读取可由执行身份与插件长期授权自动形成**任务级读 grant**，用以满足已实现策略内核的三重交集；不要求逐步骤人工批准。目标 8D 写范围单独锁定，直到 R5 前始终不开放业务写能力。当前页面工厂选择不收窄已授权的跨工厂只读查询；租户和来源权限始终不可越过。

## 后续计划的前置决定

- **R4a 试用**：元数据本地切片已通过正常配置、永久撤销、真实进程/浏览器及完整冻结门禁；只保留在独立工作树，不授权生产开放。
- **R4b 文件/生产**：选择受控对象存储或租户隔离文件存储、扫描与保留期；定义正文脱敏、模型独立外发及生产可信部署。无法证明分类和模型/插件投递策略时只允许文本消息，不把文件传给插件。
- **R5 操作**：逐项 8D 命令与最低审批矩阵、根因/措施状态与版本、模块拥有的撤销命令、不可逆业务动作、部分回滚优先级及跨业务一次性授权。审批绑定具体参数/版本，原批准不授权补偿。
- **R6 切换**：历史正文迁移和旧采纳记录如何保留、未完成任务如何处理、部署回退时数据兼容、单一用户入口与旧接口停用策略。
- **R7 推广**：每个模块数据归属、搜索派生源版本、脱敏/外发等级及审批责任人；不得用 CAPA 的一张通用权限表替代模块声明。

**持续约束**：页面和工具共用业务服务；旧 `AgentSession` 与同步 `run_message` 在新链路验收前保持原状；插件 SDK 和内部模型不可改业务事实或授权；每项切片须用独立测试库、跨租户/工厂、撤权、重试和失败恢复证据签收。`backend/app/database.py:get_db` 在请求结束时会回滚未提交事务，所以持久消息、检查点及事件应显式事务提交，不依赖响应成功隐含落库。

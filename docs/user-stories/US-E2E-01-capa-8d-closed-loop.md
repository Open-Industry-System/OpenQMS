# 用户故事 US-E2E-01：8D 全程闭环（AI 多源推荐 + 流程可视化 + 根因现场验证）

**状态**: 定稿 v6（2026-07-02），后续可能迭代
**关联**: E2E 测试套件（`docs/superpowers/specs/2026-07-01-system-e2e-test-suite-design.md`）、特性缺口检测待办

## 故事

**作为** 现场质量工程师，**我想** 在发现现场来料不良时提交 8D，借助 AI 多源推荐（本产品 FMEA + 知识库 + 同类型产品 + SPC/MES/IQC/供货历史 + 经验教训 + 规则 + LLM 融合）辅助根因与纠正措施，**按推荐根因到现场验证**，并能**看到 AI 推荐流程的编排与执行过程**，推进到预防复发后由 8D 团队负责人审批关闭，**以便** 不良问题被完整记录、根因经现场验证、AI 推荐可追溯可解释、闭环可审计。

> **角色说明**：来料不良 8D 由**现场质量工程师**（field_qe）在本系统发起；**供应商质量工程师**（supplier_qe）不在本系统提交 8D（他在供应商的质量系统上提客户投诉）。D7 预防复发 / D8 关闭由 **8D 团队负责人 / 问题拥有者** 签署（当前系统由持 `canApprove('capa')` 权限的 `manager` 账号代表；若需将「8D 团队负责人/问题拥有者」拆为独立 RBAC 角色，另立改造）。

## 背景 / 前置条件

- 系统已部署，「默认工厂」+ 产品线 `DC-DC-100-E2E`；该产品已有 FMEA、知识库、SPC 控制图、IQC 检验记录、MES 连接。
- 账号：engineer（现场质量工程师 / field_qe）、manager（8D 团队负责人）、viewer（只读）、admin。
- AI 步骤需 `.env.e2e` 配 LLM 凭证；无凭证时 AI 步骤跳过+告警，核心闭环照常运行。
- 现场发现一批来料螺栓尺寸超差。

## 主流程

1. 现场质量工程师登录，进入 CAPA，新建 8D：单号 `E2E-STORY-CAPA-001`、标题「来料螺栓尺寸超差」、严重度「致命」。
2. **D1 团队组建**：填写团队成员，指定 8D 团队负责人。
3. **D2 问题描述**：描述现象；【AI 草拟】辅助生成问题描述，确认后保存。
4. **D3 临时措施**：填写临时围堵。
5. **D4 根因分析（含现场验证）**：
   - a. 【AI 多源推荐】给出根因建议（带来源 + 流程可视化面板）；
   - b. 工程师选定一条候选根因；
   - c. **现场验证**：工程师到现场按候选根因验证——记录验证方法、测量/观察结果、证据附件；
   - d. 验证通过 → 确认根因；验证不通过 → 回到 a 选另一条或新增根因，再次验证；
   - e. 保存确认的根因（含验证记录）。
6. **D5 永久措施**：【AI 多源推荐】给出纠正措施建议（带来源 + 流程面板），工程师参考选定并保存。
7. **D6 实施验证**：填写验证结果，推进至 D7。
8. **D7 预防复发**：【AI 预防提示】给出预防复发/经验教训建议；工程师在 D7 无法继续——D7→D8 需 8D 团队负责人审批。
9. 8D 团队负责人登录，在列表看到待审批 8D，进入详情，审批并推进 D7→D8 关闭。
10. 只读用户登录，在列表看到已关闭 8D，打开详情可看内容，但无任何编辑/推进按钮。

## AI 推荐流程编排（D4/D5，可视化 DAG）

触发 D4/D5 推荐后，UI 展示**流程编排可视化面板**，按以下阶段执行；每阶段显示：名称 / 来源 / 状态（pending·running·done·skipped·error）/ 命中数·摘要。

1. 上下文采集（关联产品/产品线/失效现象）
2. 本产品 FMEA 检索（图相似：相似 FailureMode 的 Cause/控制措施）
3. 全局知识库 RAG 检索（pgvector 语义 + 全文 + RRF 融合，6 实体）
4. 同类型产品知识库检索（按 `product_types` 主数据聚合，跨工厂共享）
5. 经验教训库检索（历史 8D lessons）
6. **SPC 异常关联检索**（SPC 判异 → 关联失效模式）
7. **MES 设备/过程数据检索**（设备异常/参数漂移）
8. **IQC 来料检验数据检索**（本批及历史来料不良）
9. **供货历史检索**（供应商评级/历史 PPM）
10. 规则启发（高 RPN 优先/重复根因加权/安全特性提级）
11. LLM 融合排序（去重/排序/自然语言解释）
12. 输出推荐列表（每条带**来源 provenance** 标签）

## 业务规则 / 验收标准

- **状态机**：8D 必须按 D1→D2→…→D7→D8_CLOSURE 顺序流转，不可跳步。
- **权限**：D1-D6 推进需「编辑」权限（现场质量工程师可）；D7→D8 推进需「审批」权限（8D 团队负责人可，现场质量工程师不可）。
- **可见性**：只读用户可查看 8D 列表与详情，但不能创建/编辑/推进/删除。
- **D4 根因验证**：根因必须经现场验证才可确认；验证记录（方法/结果/证据）落库且可追溯；未验证的根因不能推进 D4→D5。
- **AI 流程可视化与执行验证**（LLM 凭证齐时）：
  - 触发 D4/D5 推荐后，流程编排面板出现，展示上述 12 阶段；
  - 关键阶段（本产品 FMEA / 全局知识库 / SPC / MES / 规则 / LLM）达 `done`（或合理 `skipped` 并注明原因，如无 SPC 数据）；
  - 最终推荐列表非空、每条带来源标签；`AP∈{H,M,L}`、`S/O/D∈1..10`；
  - E2E 断言**编排被执行**（面板各阶段状态符合预期，非黑盒），只验结构/状态/来源，不验精确文字；
  - 无 LLM 凭证时 AI 步骤跳过+告警，不阻断核心闭环。
- **审计轨迹**：每次创建与状态流转写审计日志（操作人、旧状态→新状态）；最终含 1 条 CREATE + 7 条 TRANSITION（D1→D2…D7→D8），D1-D7 由现场质量工程师、D7-D8 由 8D 团队负责人；AI 推荐采纳 + 根因验证记录留痕（含来源）。
- **数据落库**：单号、标题、严重度、当前状态、各 D 步字段、AI 推荐采纳记录（含来源/命中阶段）、根因验证记录正确持久化。

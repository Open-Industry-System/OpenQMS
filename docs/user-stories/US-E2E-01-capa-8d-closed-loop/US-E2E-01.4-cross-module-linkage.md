# 子故事 US-E2E-01.4：8D 跨模块联动闭环（FMEA / SCAR / 供应商风险）

**状态**: 定稿 v1（2026-07-08）
**所属 epic**: US-E2E-01（README.md v8）
**关联 skill**: `verify-capa-8d-cross-module`
**前置**: 01.1、01.2、01.3（8D 各步数据落库稳定）

## 故事

**作为** 现场质量工程师 / 8D 团队负责人，**我想** 在 8D 闭环过程中，
8D 与 FMEA / SCAR / 供应商风险之间建立**双向联动闭环**——
8D 的根因/预防措施能回写或关联到 FMEA 图、来料不良 8D 能触发 SCAR、
供应商相关的 8D 能更新供应商风险评级，
**以便** 跨模块数据一致、问题不孤立、联动可追溯可审计。

## 背景 / 前置条件

- 系统已部署，8D 各步数据落库稳定（01.1-01.3 已交付）。
- 现场发现一批来料螺栓尺寸超差（来料不良场景，涉及供应商）。
- AI 步骤必须配置 `.env.e2e` 的 LLM 凭证。

## 联动关系

### 8D ↔ FMEA（双向）
- **8D → FMEA**：D4 根因 + D7 预防节点可回写/关联到 FMEA 图的 Cause 节点 / Prevention 控制节点（01.3 的 node-action 已提供关联，本子故事补全反向追溯与 FMEA 侧的更新闭环）。
- **FMEA → 8D**：从 FMEA 节点可反查关联的 8D 记录（01.3 已要求，本子故事确保 FMEA 模块侧的入口与展示）。

### 8D → SCAR（来料不良触发）
- 来料不良的 8D（涉及供应商），在 D3 遏制或 D4 根因阶段可触发**SCAR（Supplier Corrective Action Request）**：
  - 从 8D 一键发起 SCAR，携带 8D 单号、不良描述、受影响批次等上下文；
  - SCAR 单号回写到 8D，建立关联；
  - SCAR 的状态变更同步回 8D（如 SCAR 关闭 → 8D 可见）。

### 8D → 供应商风险评级
- 涉及供应商的 8D（来料不良），其根因/处置结果影响供应商风险评级：
  - 8D 的严重度 + 处置结果 + 是否重复发生，作为供应商风险评级的输入；
  - 供应商风险评级变化时，关联的 8D 可见该影响。

## 主流程

1. field_qe 发起来料不良 8D，推进至 D4 根因（01.2 推荐 + 01.3 验证）。
2. D4 确认根因后，根因关联到 FMEA 图的 Cause 节点（8D → FMEA 联动）。
3. D7 预防节点落库为 node-action（01.3），关联 FMEA Prevention 节点（8D → FMEA）。
4. 来料不良场景下，field_qe 在 D3 或 D4 触发 SCAR 发起（8D → SCAR），SCAR 单号回写 8D。
5. 供应商风险评级系统读取本 8D 的严重度+处置结果，更新供应商风险（8D → 供应商风险）。
6. 从 FMEA 节点可反查本 8D（FMEA → 8D）。
7. 8D 团队负责人审批 D7→D8 关闭前，可查看所有联动关联（FMEA/SCAR/供应商风险）是否已处理。

## 业务规则 / 验收标准

- **8D ↔ FMEA 双向**：
  - D4 根因可关联 FMEA Cause 节点；D7 node-action 关联 FMEA Prevention 节点（01.3 已要求落库，本子故事验收 FMEA 侧反查入口与展示）；
  - 从 FMEA 节点可反查关联的 8D 记录列表；
  - 关联关系落库且可审计。
- **8D → SCAR**：
  - 来料不良 8D 可一键发起 SCAR，携带上下文（8D 单号、不良描述、受影响批次）；
  - SCAR 单号回写 8D；
  - SCAR 状态变更同步回 8D 可见。
- **8D → 供应商风险评级**：
  - 涉及供应商的 8D，其严重度+处置结果作为供应商风险评级输入；
  - 供应商风险评级变化关联到 8D 可见。
- **联动审计**：8D ↔ FMEA / SCAR / 供应商风险的关联与变更均写审计日志。
- **数据落库**：联动关系（8D-FMEA 节点、8D-SCAR、8D-供应商风险）正确持久化，可追溯。
- **执行验证**：E2E 断言三类联动的建立与反向追溯链路完整，只验结构/状态/关联，不验精确文字。
- **关闭前置**：D7→D8 审批前，联动关联的可处理性对 8D 团队负责人可见（不强制全部处理完，但需可见状态）。

## 不在本子故事范围

- 供应商风险评级算法的完整定义（本子故事只管 8D 作为输入的传递，评级算法由供应商模块负责）。
- FMEA 图的自动更新逻辑（FMEA 图更新由 FMEA 模块负责，本子故事只管关联与反查）。
- 客户投诉侧的联动（supplier_qe 在供应商系统的客户投诉流程，不在本系统，epic 范围外）。

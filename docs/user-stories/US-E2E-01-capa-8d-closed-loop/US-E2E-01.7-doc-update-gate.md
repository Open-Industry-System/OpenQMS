# 子故事 US-E2E-01.7：D8 关闭前文档更新审核（影响分析 + 自动化审核门禁）

**状态**: 评审稿 v1（2026-07-08）
**所属 epic**: US-E2E-01（README.md v8.1）
**关联 skill**: `verify-capa-8d-doc-update-gate`
**前置**: 01.2、01.3（8D 根因+预防 node-action 数据就绪，方可知哪些文档受影响）
**AI_REQUIRED**: true（文档影响分析用 LLM；无 LLM 凭证 → `BLOCKED`）

> **责任边界（评审修订）**：本子故事负责**门禁逻辑**——文档影响分析 + 自动审核 + 阻断/放行。审批壳归 01.3，本子故事不验审批，只通过状态机衔接（D7_COMPLETED→D8_GATE_PENDING→审核通过→D8_APPROVAL_PENDING）。

## 故事

**作为** 8D 团队负责人 / 现场质量工程师，**我想** 在 8D 报告完成、D8 关闭审批前，
系统自动分析 8D 报告识别需更新的相关受控文档（控制计划、FMEA、作业指导书/SOP 等），
并自动化审核这些文档的更新情况（是否已更新、更新是否到位），
D8 关闭审批前必须通过此审核门禁，
**以便** 8D 发现的改进真正落到受控文档、文档与实际不脱节、关闭审批有据可依。

## 背景 / 前置条件

- 系统已部署，8D 已推进至 D7（根因 + D7 node-action 已落库，01.2/01.3 就绪）。
- 对应产品已有控制计划、FMEA、作业指导书（SOP）等受控文档。
- AI 步骤必须配置 `.env.e2e` 的 LLM 凭证（文档影响分析用 LLM）。

## 能力 A：文档影响分析

8D 报告完成后（D7 填写后），系统自动分析 8D 报告，识别需更新的相关受控文档：

- **受影响文档类型**（识别清单）：控制计划（Control Plan）、FMEA（PFMEA/DFMEA）、作业指导书（SOP/Work Instruction）、检验作业指导书、其他受控文档（如适用）。
- **影响分析依据**：8D 的根因、D5 永久措施、D7 预防 node-action、严重度。
- **输出**：受影响文档清单 + 每项更新建议（哪些章节/节点需更新、更新方向）。
- **AI 辅助**：AI 基于 8D 报告内容分析受影响文档范围 + 更新建议（辅助，工程师确认）。

## 能力 B：文档更新自动化审核（D8 关闭门禁）

D8 关闭审批前，系统自动化审核相关文档的更新情况：

- **审核内容**（每项受影响文档）：
  - 是否已更新（版本号 bump、更新时间在 8D 发起之后）；
  - 更新是否到位（关键更新点是否覆盖——控制计划是否新增/修改对应控制特性、FMEA 节点是否更新、SOP 是否修订）；
  - 审核状态（通过 / 待更新 / 更新不完整）。
- **门禁规则**：
  - D8 关闭审批前，文档更新审核必须通过（所有受影响文档状态 = 通过）；
  - 未通过时，D8_GATE_PENDING 不可推进到 D8_APPROVAL_PENDING（门禁阻断）；
  - **延期处理规则（评审修订，明确）**：延期 = 记录待办（理由+责任人+期限）但**仍阻断关闭**，8D 不可关闭直至文档更新审核通过；不设"受控例外审批允许关闭"的旁路。延期记录归档供到期跟踪（跟踪闭环为后续迭代）。
- **审核报告**：生成文档更新审核报告，含每项受影响文档的审核状态 + 证据（版本号、更新点）。

## 主流程

1. field_qe 完成 D7（含 node-action），8D 报告数据就绪 → D7_COMPLETED。
2. 系统自动进入 D8_GATE_PENDING，触发文档影响分析：识别受影响文档清单 + 更新建议。
3. 工程师按建议更新相关文档（在 FMEA/控制计划/SOP 各模块操作）。
4. 系统自动触发文档更新审核。
5. 审核通过 → D8_GATE_PENDING→D8_APPROVAL_PENDING（可审批）；未通过 → 门禁阻断，显示未通过文档清单 + 原因；延期处理 → 记录待办但仍阻断。
6. 审核报告 + 门禁决策写审计日志。

## 业务规则 / 验收标准

- **文档影响分析**：8D 报告完成后自动触发，识别受影响文档清单（至少覆盖控制计划/FMEA/SOP）；每项带更新建议（AI 辅助 + 工程师确认）；清单落库可追溯。
- **文档更新审核门禁**：
  - D8_GATE_PENDING 自动审核，每项受影响文档有审核状态；
  - 未全部通过时 D8_GATE_PENDING 不可推进到 D8_APPROVAL_PENDING（门禁阻断，E2E 验证阻断生效）；
  - 延期处理 = 记录待办（理由+责任人+期限）但**仍阻断关闭**，不可关闭；
  - 审核依据 = 文档版本号 bump + 更新时间 + 关键更新点覆盖。
- **审核报告**：生成文档更新审核报告，含每项文档状态 + 证据。
- **审计**：影响分析结果、审核状态、门禁决策（通过/延期）、延期记录均写审计日志。
- **数据落库**：受影响文档清单、审核状态、审核报告、门禁决策记录正确持久化。
- **执行验证**：E2E 断言影响分析 → 审核 → 门禁阻断/放行 → D8_APPROVAL_PENDING 的完整链路。
- **与 01.3 的衔接**：01.3 的审批壳在 D8_APPROVAL_PENDING 进行；本子故事只管 D8_GATE_PENDING→D8_APPROVAL_PENDING 的门禁，不验审批。

## 验收契约（字段级）

| 项 | 定义 |
|---|---|
| 落库实体 | `capa_doc_impact_analysis`（受影响文档清单）、`capa_doc_update_audit`（审核状态+证据）、`capa_doc_gate_decision`（门禁决策） |
| 关键字段 | impact.doc_type∈{control_plan,fmea,sop,inspection_sop,other}、impact.update_suggestion；audit.status∈{passed,pending_update,incomplete}、audit.version_bump、audit.updated_at、audit.coverage；gate.decision∈{passed,blocked,deferred}、gate.defer_reason+defer_owner+defer_deadline |
| 状态枚举 | D7_COMPLETED→D8_GATE_PENDING→（门禁通过）→D8_APPROVAL_PENDING；延期仍停留 D8_GATE_PENDING |
| 审计事件 | `DOC_IMPACT_ANALYZED`、`DOC_UPDATE_AUDITED`（含 status）、`DOC_GATE_BLOCKED`、`DOC_GATE_PASSED`、`DOC_GATE_DEFERRED`（含 reason/owner/deadline） |
| E2E seed 前置 | 8D 推进到 D7_COMPLETED；产品有控制计划+FMEA+SOP 受控文档（含版本） |
| 通过条件 | 影响分析识别 ≥3 类文档 + 审核每项有状态 + 门禁阻断生效（未通过不可推进）+ 延期仍阻断 + 审计 |
| 失败条件（FAILED） | 影响分析缺类；审核状态缺失；门禁未阻断（未通过可推进）；延期允许关闭（旁路）；未审计 |
| 阻塞条件（BLOCKED） | 无 LLM 凭证 |

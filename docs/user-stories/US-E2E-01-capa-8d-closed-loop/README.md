## 故事

**作为** 现场质量工程师，**我想** 在发现现场来料不良时提交 8D，借助 AI 全程辅助——
D3 遏制缺陷品流入客户（数据导入 + 受影响范围分析 + AI 遏制建议）、
D4 根因分析（12 源多源推荐 + 流程可视化 + 现场验证）、
D5 永久措施（多源推荐）、
D7 预防复发（FMEA 预防节点采纳 + node-action 审计）、
D8 关闭前文档更新审核门禁 + 审批、
D8 关闭后知识沉淀 + 横向扩散预警 + 报告输出——
并能**看到 AI 推荐流程的编排与执行过程**，推进到预防复发后由 8D 团队负责人审批关闭，
**以便** 不良问题被完整记录、缺陷品被有效遏制、根因经现场验证、AI 推荐可追溯可解释、跨模块联动可追溯、8D 经验可复用、闭环可审计。

> **角色说明**：来料不良 8D 由**现场质量工程师**（field_qe）在本系统发起；**供应商质量工程师**（supplier_qe）不在本系统提交 8D（他在供应商的质量系统上提客户投诉）。D7 预防复发 / D8 关闭由 **8D 团队负责人 / 问题拥有者** 签署（当前系统由持 `canApprove('capa')` 权限的 `manager` 账号代表；若需将「8D 团队负责人/问题拥有者」拆为独立 RBAC 角色，另立改造）。

## 状态机（D8 阶段语义明确化）

8D 状态机在 D7 之后细分为多个状态，避免"D8 既是阶段又是关闭状态"的歧义：

| 状态 | 含义 | 推进动作 | 责任子故事 |
|---|---|---|---|
| D1_TEAM … D6_VERIFICATION | D1-D6 各阶段 | 按序流转 | 各 D 步对应子故事 |
| D7_PREVENTION | D7 预防复发填写中 | field_qe 填写 + 采纳 node-action | 01.3 |
| D7_COMPLETED | D7 填写完成，待文档门禁 | 自动进入 | 01.3 → 01.7 |
| D8_GATE_PENDING | 文档更新门禁待审核 | 01.7 自动审核 | 01.7 |
| D8_APPROVAL_PENDING | 门禁通过，待 8D 团队负责人审批 | manager 审批 | 01.3（审批壳）|
| D8_CLOSURE（CLOSED） | 已关闭 | 审批通过 → 关闭 | 01.3 |

- **状态流转**：D7_PREVENTION →（field_qe 完成 D7）→ D7_COMPLETED →（系统自动审核文档）→ D8_GATE_PENDING →（门禁通过）→ D8_APPROVAL_PENDING →（manager 审批）→ D8_CLOSURE。
- **门禁未通过**：D8_GATE_PENDING 不可推进到 D8_APPROVAL_PENDING（01.7 阻断）。
- **审批未通过**：D8_APPROVAL_PENDING 可驳回回 D7_PREVENTION（field_qe 修改后重走）。
- **责任边界**：01.3 只负责"审批壳"（权限校验 + 待审批状态 + 审批审计 + 驳回回退）；01.7 只负责"门禁逻辑"（文档影响分析 + 自动审核 + 阻断/放行）。两者通过状态机衔接，不在验收标准里互相耦合。

## D 步业务执行顺序（与 8D 状态机一致）

智能体编排与业务执行严格按 8D 状态机顺序，D3 必须先于 D4/D5/D6——遏制（止损）先于根因分析，顺序不可颠倒，否则无法推进到后续步骤：

```
D1 团队 → D2 问题描述 → D3 遏制措施（01.1）→ D4 根因分析+现场验证（01.2/01.3）→ D5 永久措施（01.2）→ D6 实施验证 → D7 预防复发+node-action（01.3）→ D7_COMPLETED → D8 文档门禁（01.7）→ D8_APPROVAL_PENDING 审批关闭（01.3）→ D8_CLOSURE → 知识沉淀（01.8）+横向扩散（01.9）+PPT（01.10）
```

## 验收骨架（epic 级）

epic 级验收 = 各子故事验收的**合取**（全部子故事通过，epic 方为通过）。详见各子故事文件。

- **状态机**：8D 按 D1→D2→…→D7→D7_COMPLETED→D8_GATE_PENDING→D8_APPROVAL_PENDING→D8_CLOSURE 顺序流转，不可跳步。
- **权限**：D1-D6 推进需「编辑」权限（field_qe 可）；D8_APPROVAL_PENDING→D8_CLOSURE 审批需「审批」权限（8D 团队负责人可，field_qe 不可）。
- **可见性**：只读用户可查看 8D 列表与详情，但不能创建/编辑/推进/删除。
- **AI 流程可视化与执行验证**（强制 LLM 凭证，AI_REQUIRED=true 的子故事）：触发 D4/D5 推荐后，流程编排面板出现，展示 12 阶段；关键阶段必须 `done`，外部数据阶段可在无对应数据时 `skipped` 但必须注明原因；无 LLM 凭证 → `BLOCKED`；LLM 阶段 `skipped`/`error` → `FAILED`。
- **审计轨迹**：每次创建与状态流转写审计日志；AI 推荐采纳 + 根因验证记录 + D7 node-action + D3 遏制决策 + 文档更新门禁决策 + 横向扩散通知 + 知识沉淀均留痕（含来源）。
- **数据落库**：单号、标题、严重度、当前状态、各 D 步字段、AI 推荐采纳记录（含来源/命中阶段）、根因验证记录、D3 遏制分析报告与采纳记录、D7 node-action 记录、文档更新审核记录、跨模块联动记录、知识库沉淀条目、横向扩散通知记录均正确持久化。

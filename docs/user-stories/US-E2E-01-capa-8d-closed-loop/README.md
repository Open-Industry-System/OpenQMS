## 故事

**作为** 现场质量工程师，**我想** 在发现现场来料不良时提交 8D，借助 AI 全程辅助——
D3 遏制缺陷品流入客户（数据导入 + 受影响范围分析 + AI 遏制建议）、
D4 根因分析（12 源多源推荐 + 流程可视化 + 现场验证）、
D5 永久措施（多源推荐）、
D7 预防复发（FMEA 预防节点采纳 + node-action 审计）、
D8 关闭前文档更新审核门禁 + 审批、
D8 关闭后知识沉淀 + 横向扩散预警 + 报告输出——
并能**看到 AI 推荐流程的编排与执行过程**，推进到预防复发后由 8D 团队负责人审批关闭，
**以便** 不良问题被完整记录、缺陷品被有效遏制、根因经现场验证、AI 推荐可追溯可解释、跨模块联动可追溯、8D 经验可复用、闭环可审计。

> **角色说明**：来料不良 8D 由**现场质量工程师**（field_qe）在本系统发起；**供应商质量工程师**（supplier_qe）不在本系统提交 8D（他在供应商的质量系统上提客户投诉）。D7 预防复发 / D8 关闭由 **8D 团队负责人 / 问题拥有者** 签署（当前系统由持 `canApprove('capa')` 权限的 `manager` 账号代表；若需将「8D 团队负责人/问题拥有者」拆为独立 RBAC 角色，另立改造）。

## 交付顺序与依赖

**交付顺序**（建议的实施顺序，遵循 D 步业务流程）：

```
01.1（D3 遏制）→ 01.2（D4/D5 推荐 12 源）→ 01.3（D4 验证深化 + D7 node-action + 审批机制）→ 01.6（D8 文档更新门禁）→ 01.4（跨模块联动）→ 01.5（知识沉淀 + 横向扩散 + PPT）
```

**前置依赖**（硬依赖，见各子故事"前置"行）：

```
01.1 → (无)
01.2 → (无)
01.3 → 01.2
01.6 → 01.2、01.3
01.4 → 01.1、01.2、01.3
01.5 → 01.1、01.2、01.3、01.4、01.6
```

> 交付顺序 ≠ 前置依赖。交付顺序按 D 步业务流程编排（便于走查与增量交付）；前置依赖是硬约束（被依赖项须先就绪）。01.4 与 01.6 互不前置，可并行实施。

- **01.1 先行**：D3 遏制是业务流程最靠前的 AI 步骤（止损优先），独立交付，自带数据导入+分析逻辑，不依赖推荐源抽象。
- **01.2 次之**：D4/D5 根因与永久措施的 12 源推荐；纯后端推荐管道。
- **01.3 第三**：D4 验证深化依赖 01.2 的根因推荐就绪；D7 node-action 依赖 D4 根因确认；含 D7→D8 审批机制。
- **01.6 第四**：D8 关闭前文档更新审核门禁，接入 01.3 的审批机制（01.3 审批引用 01.6 门禁状态）。
- **01.4 第五**：跨模块联动依赖前述 8D 各步数据落库稳定；与 01.6 互不前置，可并行。
- **01.5 最后**：知识沉淀 + 横向扩散 + PPT 输出，依赖完整 8D 报告 + 联动就绪。

## D 步业务执行顺序（与 8D 状态机一致）

智能体编排与业务执行严格按 8D 状态机顺序，D3 必须先于 D4/D5/D6——遏制（止损）先于根因分析，顺序不可颠倒，否则无法推进到后续步骤：

```
D1 团队 → D2 问题描述 → D3 遏制措施（01.1）→ D4 根因分析+现场验证（01.2/01.3）→ D5 永久措施（01.2）→ D6 实施验证 → D7 预防复发+node-action（01.3）→ D8 文档门禁（01.6）→ 审批关闭（01.3）→ 知识沉淀+横向扩散+PPT（01.5）
```

## 验收骨架（epic 级）

epic 级验收 = 各子故事验收的**合取**（全部子故事通过，epic 方为通过）。详见各子故事文件。

- **状态机**：8D 按 D1→D2→…→D7→D8_CLOSURE 顺序流转，不可跳步。
- **权限**：D1-D6 推进需「编辑」权限（field_qe 可）；D7→D8 推进需「审批」权限（8D 团队负责人可，field_qe 不可）。
- **可见性**：只读用户可查看 8D 列表与详情，但不能创建/编辑/推进/删除。
- **AI 流程可视化与执行验证**（强制 LLM 凭证）：触发 D4/D5 推荐后，流程编排面板出现，展示 12 阶段；关键阶段必须 `done`，外部数据阶段可在无对应数据时 `skipped` 但必须注明原因；无 LLM 凭证、LLM 阶段 `skipped`、LLM 阶段 `error` 都视为验收阻塞或失败。
- **审计轨迹**：每次创建与状态流转写审计日志；AI 推荐采纳 + 根因验证记录 + D7 node-action + D3 遏制决策 + 文档更新门禁决策 + 横向扩散通知 + 知识沉淀均留痕（含来源）。
- **数据落库**：单号、标题、严重度、当前状态、各 D 步字段、AI 推荐采纳记录（含来源/命中阶段）、根因验证记录、D3 遏制分析报告与采纳记录、D7 node-action 记录、文档更新审核记录、跨模块联动记录、知识库沉淀条目、横向扩散通知记录均正确持久化。

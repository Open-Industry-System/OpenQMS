## 故事

**作为** 现场质量工程师，**我想** 在 D4 选定候选根因后到现场验证——记录验证方法分类、
测量/观察/复现结果、证据附件，验证不通过时回到推荐选另一条，验证通过才确认根因；
并在 D7 预防复发时，把我采纳的 FMEA 预防节点作为**可追溯的 node-action 记录**落库
（而非只填一段文本）；
并在 D7→D8 审批关闭时走通 8D 团队负责人审批流程，
**以便** 根因经现场验证而非主观认定、预防措施落到 FMEA 图节点且可审计可回溯、关闭审批有据可依。

## 背景 / 前置条件

- 系统已部署，8D 已推进到 D4（根因推荐已由 01.2 交付）。
- 现场发现一批来料螺栓尺寸超差。
- AI 步骤必须配置 `.env.e2e` 的 LLM 凭证；无凭证时本子故事验收视为 `BLOCKED`，不得降级跳过 AI 步骤。

## D4 根因现场验证子流程

工程师选定一条候选根因后，进入**现场验证**子流程：

1. **验证方法分类**（必选其一）：
   - 测量验证（量具/仪器复测尺寸）
   - 观察验证（现场观察现象/工况）
   - 复现实验（在受控条件下复现失效）
2. **验证记录**：
   - 验证方法（上述分类）
   - 测量/观察/复现结果（数值或描述）
   - 证据附件（照片/测量报告/视频等）
   - 验证人 + 验证时间
3. **验证结论**：通过 / 不通过。
4. **回退循环**：
   - 验证通过 → 确认根因，保存（含验证记录），可推进 D4→D5；
   - 验证不通过 → 回到推荐选另一条候选根因，或新增根因，再次验证；
   - 回退循环计数器记录尝试次数（供审计，不设硬性上限，但超过阈值时提示"建议升级处理"）。

## D7 node-action 审计

D7 预防复发阶段，工程师采纳的 FMEA 预防节点（来自 AI 预防提示或工程师手动选择），
落库为**结构化 node-action 记录**（而非 D7 文本字段）：

- **node-action 记录字段**：
  - 关联 FMEA 文档 + 节点 ID（指向 FMEA 图的 Prevention/控制节点）
  - action 类型（新增预防控制 / 优化现有控制 / 经验教训登记）
  - 措施描述
  - 采纳来源（AI 预防提示 / 工程师手动）
  - 状态（待执行 / 已执行 / 已验证）
  - 关联 8D 单号
- **追溯**：从 8D D7 可跳转到关联的 FMEA 节点；从 FMEA 节点可反查关联的 8D 记录。

## 主流程

1. field_qe 在 D4 触发【AI 多源推荐】（01.2 已交付），选定一条候选根因。
2. 进入现场验证子流程：选验证方法 → 记录结果 → 上传证据 → 给结论。
3. 验证通过 → 确认根因（含验证记录落库），推进 D4→D5。
4. （D5/D6 略，见 epic）推进至 D7。
5. D7 触发【AI 预防提示】，工程师采纳预防节点 → 落库为 node-action 记录（结构化，非文本）。
6. D7 填写完成，但 D7→D8 需 8D 团队负责人审批（field_qe 不可推进）。
7. 8D 团队负责人（当前由 manager 账号代表）登录，在 8D 列表看到该 8D 处于"待审批"状态。
8. 进入详情，审批并推进 D7→D8_CLOSURE 关闭（审批前 01.6 文档更新门禁须通过）。

## 业务规则 / 验收标准

- **D4 现场验证**：
  - 根因必须经现场验证才可确认；验证记录（方法分类/结果/证据/验证人/时间）落库且可追溯；
  - 未验证的根因不能推进 D4→D5；
  - 验证不通过可回退选另一条根因再次验证；回退循环计数器记录尝试次数；
  - 尝试次数超过阈值（如 3 次）时提示"建议升级处理"，但不硬性阻断。
- **D7 node-action 审计**：
  - 采纳的 FMEA 预防节点落库为结构化 node-action 记录（含关联 FMEA 文档/节点 ID、action 类型、来源、状态、关联 8D 单号），非 D7 文本字段；
  - 8D D7 ↔ FMEA 节点双向可跳转追溯；
  - 未采纳的预防提示也留存。
- **D7→D8 审批流走查**（纳入验收）：
  - field_qe 完成 D7 填写后，D7→D8 不可自助推进（无「审批」权限）；
  - 8D 团队负责人（当前由 manager 账号代表）登录，在 8D 列表看到该 8D 处于"待审批"状态；
  - 进入详情，审批并推进 D7→D8_CLOSURE 关闭；
  - 审批记录写审计日志（审批人、旧状态 D7→新状态 D8_CLOSURE、时间）；
  - RBAC 角色拆分（8D 团队负责人作为独立角色）仍另立，不在本子故事范围。
- **D8 关闭门禁依赖**：D7→D8 审批前，01.6 的文档更新审核门禁须通过；门禁未通过时 8D 团队负责人不可批准 D8 关闭。
- **权限**：D4 推进需「编辑」权限（field_qe 可）；D7→D8 推进需「审批」权限（8D 团队负责人可，field_qe 不可）。
- **审计轨迹**：根因验证记录（含方法/结果/证据/回退次数）、D7 node-action 采纳记录（含 FMEA 节点引用/来源）、审批记录写审计日志。
- **数据落库**：根因验证记录、D7 node-action 记录（结构化）、审批记录正确持久化。
- **执行验证**：E2E 断言 D4 验证子流程（方法分类/证据/回退）+ D7 node-action 落库（结构化字段，非文本）+ D7→D8 审批流走查。

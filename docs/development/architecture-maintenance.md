# 架构与决策维护约定

日期：2026-09-22。用途：给人工开发者与编码 Agent 提供相同的定位、修改和交接方式。

## 文档职责

| 内容 | 位置 | 写什么 |
|---|---|---|
| 开工规则 | 根及相关目录的 AGENTS.md | 少量必须遵守的约束，以及详情入口 |
| 当前系统 | docs/architecture.md、模块文档、局部 README | 已实现的职责、公开接口、运行语义和代码锚点 |
| 目标设计 | docs/superpowers/specs/ | 决策状态、目标边界、差距、待定项；不能冒充现状 |
| 实施计划 | docs/superpowers/plans/ | 有范围的改动、依赖、迁移和验证步骤 |
| 决策原因 | 建议后续使用 docs/decisions/领域/日期-主题.md | 背景、选择、放弃的方案、代价和重新评估条件 |
| 操作与事故 | 建议后续使用 docs/cookbook/、docs/postmortem/ | 可复现操作流程，或事故证据与防复发措施 |

现有文档沿用原位置，按修改逐步整理；不批量搬迁。决策记录使用普通 docs 路径便于人工和多种工具共同维护，不要求依赖特定 Agent 的私有目录。当前架构目标入口为 [模块化业务与 AI 插件设计](../superpowers/specs/2026-09-22-modular-qms-agent-architecture-design.md)。

## 每次改动的最小工作方式

1. 读取相关 AGENTS.md；从当前模块文档和目标设计定位工作，区分已实现、目标与待定。
2. 用 CodeGraph 查询结构关系；工具不可用时说明并使用定向搜索。按主题检索相关设计与决策，不把全部历史灌入上下文。
3. 明确本次修改的所属模块、公开契约及影响面。页面和 AI 工具共用业务服务；避免直接新增跨模块内部依赖。
4. 对实际行为改动执行对应验证；涉及授权、状态、版本和幂等时验证失败分支。实现契约测试，避免只测试内部函数的拼装方式。
5. 同步更新当前事实文档；有重要取舍时记录决策原因。尚未实现的部分继续放在设计中。
6. 交接注明改动、验证证据、剩余限制和入口。不得将通过局部测试表述为整套目标架构已完成。

## 何时记录决策

接口破坏性变化、数据归属、权限或审批语义、状态机变更、重要依赖选择、非直观限制和事故防复发需要记录。小样式和简单文字修正不要求新文档。

每条记录围绕一个决定，使用以下字段：日期与状态、背景、决定、替代方案及放弃原因、后果、代码或测试锚点、重新评估条件。决定改变时新增记录并链接被替代的记录，不把旧原因改写成新结论。

每份文档提供局部相关链接；不维护每次新增都必须修改的全量历史索引。当前设计已在主文档内保存本轮取舍，不为形式要求重复抄写多份。

## 文档防腐

- 当前事实文档解释系统如何工作；演进过程进入决策或迁移记录。
- API 精确字段以 Schema 或生成文档为准；架构文档描述语义并链接代码，避免手抄完整接口清单。
- 使用稳定文件和符号锚点；路径变化时同步修复引用。
- 根 AGENTS.md 保持短入口；局部复杂规则在模块内部说明，避免所有规则集中追加。
- 文档过长时按职责拆分；建议未来增加链接、Schema 兼容和模块依赖检查。长度阈值与 CI 工具尚未实施，不作为已有门禁。

## 范围纪律

目标设计不能授权自动重构。每次实现只选一个可验证切片；待定项在涉及它的实施前解决。旧的 spec 是当时的设计记录，不能仅因它写着“定稿”就假定对应功能已完成。

参考：[用户提供的 DSH 维护分析文章](https://linux.do/t/topic/2904342)。本约定是针对 OpenQMS 的轻量适配，不是对 DSH 团队流程的复刻或事实认证。

## 开发指引归档位置

2026-09-22 起，根目录开发指引统一使用 [AGENTS.md](../../AGENTS.md)，停用原 Claude 专用入口。内容按职责归入：

- 通用行为、开工交接、简要命令与关键约束：`AGENTS.md`。
- 开发流程、测试、文档 CI 与故事/走查同步：[开发指南](../development.md)。
- 运行架构和权限：[架构概览](../architecture.md)、[权限参考](../permissions.md)。
- 安装、服务启动、数据库迁移和演示账号：[部署指南](../deployment.md)。
- 图模型与表格转换：[图查询说明](../../backend/app/graph/README.md)、[前端工具说明](../../frontend/src/utils/README.md)；共享节点删除和多后果规则也保留在开发入口。
- 历史问题留在 [PROGRESS.md](../../PROGRESS.md) 并标明需复核；既有决策保留在 [DECISIONS.md](../DECISIONS.md)。

迁移不把陈旧版本号、模块数量、性能数字或权限概括重新认定为当前事实；精确行为以代码及验证为准。

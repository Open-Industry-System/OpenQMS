# 员工 Agent 侧栏聊天

## 工作区助手（本机试用）

使用试用环境的员工账号打开 8D 报告 `8D-OWNED-TRIAL`，点击右侧 **工作区助手**。标题区显示 Pi 和当前参考的 8D 单号。打开后可直接输入，无需创建业务任务。试用中可用以下两条消息：

1. `帮我查一下当前 8D 同产品线有哪些 PFMEA？`
2. `为这条线创建 PFMEA 草稿，标题「首件复核 PFMEA」，单号 PFMEA-PI-TRIAL-01`

第一条返回当前工厂、同产品线的 PFMEA 和单据链接。第二条展示工厂、产品线、类型、标题、单号和来源 8D。点击 **确认创建** 才会调用 FMEA 创建服务。成功后可打开新草稿。确认重试使用同一个操作 ID。点击 **取消** 后，原预览无法再确认。切换页面、工厂或员工时，旧聊天会离开当前视图。

Pi Agent Core 负责模型轮次与工具选择。OpenQMS 根据当前员工的模块权限过滤工具，再逐次校验当前报告、工厂和产品线。模型接收员工文本和已登记的少量业务字段。草稿确认在员工会话中执行，写入、审计和同步 outbox 同一事务提交。试用聊天与待确认预览在服务进程内保留，重新启动后开始新会话。已有业务单据仍可从 FMEA 模块打开。

本机试用只对专门登记的测试租户、员工和报告开放。浏览器使用真实 API 和隔离 PostgreSQL。自动回归使用回环模型端点，2026-11-22 的单独人工试用按授权使用 OpenAI `gpt-4.1-mini`，仅发送这套合成测试数据。其它 OpenQMS 页面读取待接入。可继续查阅[通用侧栏助手设计](../superpowers/specs/2026-11-22-openqms-workspace-assistant-design.md)。

### 真实模型试用

OpenAI 试用批准固定受控 Pi 工作进程、模型部署标识、当前测试员工与 8D 对象。平台沿用 R5 现有的 TLS 和地址固定传输以及专用凭据解析，只对精确获准的 OpenAI HTTPS 源发送本轮数据。Pi 的子进程继续只连接平台回环地址。普通实例默认关闭试用。真实模型接入前，应确保实例使用独占合成数据。

本轮用六次员工消息验证工具调用。单问 8D 的产线时模型选报告摘要，两种自然说法各自选同线 PFMEA 查询。模型先追问缺失的标题和单号，补标题后只追问单号。首次缺字段测试触发了模型代填，服务端已加入检查，预览的字段须来自员工消息。即使模型错误返回写入语气，生成预览后页面展示平台的待确认状态。

试用链接携带会话 ID。员工先在相同本机地址登录，然后打开链接，侧栏会自动加载当前权限下的历史与原待确认预览。预览期间和浏览器验收期间未提交任何确认，数据库查证新增草稿数为零。

## 专用任务面板

员工在应用布局中点击 **Agent 任务**，从目录选择已有任务。新任务从有权限的 8D 报告进入 **以本报告创建任务**。选择当前报告可用的插件，受控 D5 任务还要选择获准的模型版本。侧栏一直显示固定的报告编号和接收方。在别的报告里发起创建时，已有对话仍发给原任务绑定的模型。

受控 D5 任务支持自由文本。创建后使用 **启动模型任务** 开始已有的受控运行。底部可以继续补充。Enter 发送，Shift+Enter 换行，中文输入法选词时 Enter 只确认选词。侧栏停在最新消息时随回复滚动。向上阅读时会保留位置，并可点 **回到最新消息**。固定只读插件按预设任务执行，可以看员工的历史记录、分析结果和证据。

**任务详情** 保留暂停、继续、取消、附件、建议更正和检查点。D5 建议卡会带员工回到原 8D 报告审阅，保留原有的来源检查和采纳流程。自由补充可送给绑定模型。保存共享 D5 建议仍要求满足现有来源和意图限制，例如通过 **继续（无额外资料）** 提交明确意图。

- 员工消息仍用 `POST /api/agent/tasks/{id}/messages`。发送成功表示服务端已接单，活动窗口按实际状态区分排队、领取和插件确认接收。连接中断时，显式重试沿用原正文和幂等键。
- `GET /api/agent/tasks/{id}/activity` 额外返回已授权任务的报告编号、插件和版本。报告和安装由服务端从固定任务取出，界面沿用原目标与来源授权。其余活动指针、两个授权分页和最多 100 条活动窗口沿用原先的规则。
- `GET /api/agent/tasks/{id}/workflow` 增加当前运行的 `run_id`、`lease_epoch` 和带时间、稳定 ID 的实际追问。原 `question` 仍表示当前待答问题。前端需要当前活动的运行 ID 和轮次，才能在正确位置展示追问并辨认待答状态。前端无法从原来的单一问题字符串恢复已回答的问题，也无法判断它属于哪个运行，所以在同一个授权接口中补充这几个字段。
- 追问只保存在现有进程内的活跃 Round，最多 8 条。活跃期间关开侧栏会重新读取。运行结束、过期或进程重启后，仍能读取当前授权下的持久员工消息、只读结果和最近 20 条 D5 建议。普通模型最终文本目前只返回给受控执行器，员工侧显示协议提供的追问、结构化结果和建议。
- 关闭、切换任务、身份或工厂后，浏览器撤回上一次请求的内容及草稿，再取当前授权可见记录。模型撤权或任务终态下，发送被禁用。切换工厂不会把原任务移到另一个报告，仍由服务端重新判断可见性。
- 活动窗口连续三次读取失败后停止自动重试，清除旧内容。员工点 **重新连接** 后，侧栏重新读取任务目录并校验活动权限。访问拒绝会立即停读，界面与服务暂不可用分开显示。

## 本地验证

前端用 Vitest 模拟 API 覆盖输入、请求重试、历史展示、权限和任务切换。Chromium 使用员工登录、真实 FastAPI、隔离 PostgreSQL 和受控 Pi 工作进程。R5 的模型响应来自仓库的回环测试传输。真实模型试用需要单独获准的部署；本轮未启用部署，也未把业务数据发送给外部模型。

可在配置项目要求的独占测试数据库和 Chromium 后复跑：

```sh
npm --prefix frontend test -- --run
make check-frontend
cd frontend && npx tsc -p tsconfig.e2e.json --noEmit
```

测试 R5 前先[构建 Pi 工作进程](r5-model-egress.md#pi-工作进程与员工启动)，并在 PATH 中选择官方独立 Node。后端从 `backend/` 运行标准验收入口。按仓库惯例设置 `PYTHONPATH=.` 和专用测试环境。R5 原生入口需要 macOS。

```sh
repo="$(cd .. && pwd)"
python -m tests.e2e.capa_outcome_runner api \
  --pytest-target "$repo/backend/tests/api/test_agent_activity.py" \
  --pytest-target "$repo/backend/tests/api/test_agent_tasks.py"
python -m tests.e2e.capa_outcome_runner r5-api \
  --pytest-target "$repo/backend/tests/e2e/test_r5_model_agent.py"
python -m tests.e2e.capa_outcome_runner r5-browser \
  --pytest-target "$repo/backend/tests/e2e/test_r5_sidebar_chat.py"
```
